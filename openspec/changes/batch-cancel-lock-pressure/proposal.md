# Why

多批次排队时调度器持有全局准入锁，用户取消批次或任务常在 0.5 秒数据库锁等待内失败。大批次取消还为每个排队任务重新查询执行记录，扩大持锁时间。

# What Changes

取消请求在总请求预算内短暂尝试调度锁，未取得时回滚事务并归还连接；排队和未领取任务复用已加载的最新执行记录，已领取任务仍逐项锁定并刷新。超限明确返回可重试的 `503/scheduler_lock`，不写入部分结果。调度分配、Worker 控制和数据库连接池配置不变。

# Impact

批次/单任务取消接口、专项 PostgreSQL 竞争测试、100 个排队任务回归、批次控制指南与项目 Skill。无数据库迁移或 Worker 升级。
