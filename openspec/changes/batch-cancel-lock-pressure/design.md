# Design

保留全局事务锁的资源一致性边界。用户取消入口使用 `pg_try_advisory_xact_lock`，失败立即回滚释放连接，每 50 毫秒重试，最多 2 秒且预留 100 毫秒给请求预算。超时返回 `scheduler_lock`；成功后沿原事务执行取消，版本和权限在持锁后核对。

`PENDING`/`RESERVED` 的变更都通过调度锁串行化，因而可直接使用批次查询已经加载的最后一次 Run；`STARTING`/`RUNNING` 等状态可能由执行上报并发改变，继续锁最新 Run 并刷新 Job 后决定。保持事件、结果与资源清理语义。

定向测试以 100 个排队任务验证无需逐任务 Run 锁查询；独立 PostgreSQL 用短暂持锁验证重试成功和等待时连接归还，以持续持锁验证有界失败。现场其他部署的网关状态码和实际吞吐仍需单独验收。
