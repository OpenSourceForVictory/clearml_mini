# Proposal

## Why
当前运行结果的产物入口隐藏于排查区，Worker 只在客户端结束时收集小文件并将正文存数据库；缺少可靠回合归属、视频在线播放及用户自定义结果目录的只读浏览。用户希望从批次、任务和回合直接查看结果，同时保留历史执行隔离。

## What Changes
- 在任务结果页提供产物侧栏，区分已保存运行产物与节点目录，支持回合筛选、历史尝试及视频 Range 播放。
- 仅自动收集平台输出目录。SDK 保留 output_dir 并增加 episode_output_dir；逐回合 Runner 标记对应目录归属，直接协议使用显式声明。
- 模板允许配置一个只读结果浏览目录，按提交快照及执行节点定位；不自动上传该目录，不推断回合归属。容器仅允许批准的持久挂载目录。
- 新产物使用持久化文件存储与数据库索引、分块上传及独立采集状态；历史数据库正文保留兼容。失败采集不改变业务结果。
- 独立节点文件通道提供有界分页和范围读取，不占用心跳线程或长时间持有数据库连接；访问使用业务账号权限与批准目录边界。

## Capabilities
### New Capabilities
- `execution-artifacts`: 任务及回合产物采集、持久存储、浏览、预览、权限与兼容。
### Modified Capabilities
无。现有平台总规格的任务执行结果规则保持不变，产物失败与业务结果分离。

## Impact
Runner SDK/回合包装器、Worker 上传及历史文件服务、API 产物模型/接口/鉴权、模板契约/快照、结果侧栏与模板编辑器、持久化部署卷、数据库迁移和升级指南。覆盖宿主机/容器、四种运行接入方式、失败与恢复、实际视频播放。需要 API 先升级并迁移，再升级 Worker/Runner；旧 Worker 仍使用旧上传接口。
