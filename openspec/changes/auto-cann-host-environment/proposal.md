## Why
NPU 宿主机任务使用显式构造的环境启动，不能继承交互 shell。新纳管 Worker 的 CANN 环境为空；已安装 CANN 的节点仍可能在 `torch_npu` 导入时因缺少 `libhccl.so` 搜索路径失败。逐卡改私有 JSON 与宿主机模式降低配置量的目标不符。

## What Changes
- NPU 宿主机任务以批准的普通业务账号加载本机 CANN `set_env.sh`，只提取运行所需的环境变量，并与模板及节点已有配置合并。
- 宿主机环境探测同步检查 CANN 环境初始化；脚本存在却不可用时明确报告失败，不把业务启动失败误认为环境就绪。
- 没有标准 CANN 脚本的旧节点继续使用显式批准配置；GPU、Docker 与设备可见性策略不变。
- 修正调度后端能力检查中未定义的执行方式变量，使 NPU 宿主机和共享 GPU 按模板的实际执行方式匹配节点能力。

## Impact
Worker NPU 宿主机启动和环境探测、调度后端能力检查、宿主机操作文档、界面指南及定向回归；不改数据库或公开 API 契约。
