# Proposal

## Why
现有资源池绑定单一 GPU 型号，每卡只能执行一个任务，无法把 RTX 8000 与 RTX 4090 放入统一队列或利用轻量评测的空闲显存。需要在保持任务恢复和多用户公平性的前提下支持异构池与显式 GPU 共享。

## What Changes
- 物理资源池允许不同 GPU 型号；型号、总显存与遥测保存到每个槽位。任务可选限定型号。
- 默认 GPU 独占；管理员可开启共享，配置每卡并发上限、显存安全余量和利用率准入阈值。共享任务必须声明显存额度。
- PostgreSQL 原子预留每卡任务份额与显存，继续执行全局、用户、节点 CPU/RAM 限额；未确认清理的执行继续占用资源。
- Worker 上报实际空闲显存与 GPU 利用率，支持独立执行日志、租约和恢复；旧 Worker 只能接独占任务。
- 界面提供共享配置、任务资源需求与设备实时状态。利用率仅辅助准入/排序，不代表可保证的算力比例。

## Capabilities

### New Capabilities
- `gpu-admission`: GPU 共享资源预留、遥测辅助调度和多执行恢复。

### Modified Capabilities
- `platform`: 同一资源池包含不同型号 GPU，并按任务要求选择槽位。

## Impact
涉及 API、数据库迁移、调度器、Worker、React 界面及部署文档。旧请求默认独占；物理池原型号字段迁移为 `*`，真实型号由 Worker 重新登记。升级应暂停调度并更新 Worker。没有引入 ClearML、MPS 或第三方显存拦截镜像；共享显存额度是调度预留，不是 CUDA 硬隔离。本次不实现 TFLOPS 配额或未经校准的跨型号性能预测。
