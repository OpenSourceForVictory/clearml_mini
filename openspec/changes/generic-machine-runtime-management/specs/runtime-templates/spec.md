## Purpose
将可复用运行定义与机器目录、具体任务输入和运行实例分离，为不同评测客户端及推理服务提供统一版本管理，支持容器和宿主机两种环境而不硬编码仿真业务。

## ADDED Requirements

### Requirement: 类型与执行方式正交
模板 SHALL 区分客户端与服务端，并各自支持 docker 与 host 执行方式；配置包含命令参数、环境、逻辑目录和所需能力，host 模板不强制填写镜像。

#### Scenario: 模式切换
- **WHEN** 用户注册 host 模板
- **THEN** 校验宿主机环境配置及命令，不要求镜像，Docker 专属字段不能伪装成宿主机配置

### Requirement: 版本与快照
模板 SHALL 支持注册、查看、复制新版本、启停和归档，实例保存完整配置快照；旧客户端模板保持 Docker 行为。

#### Scenario: 修改已使用模板
- **WHEN** 管理员改变启动参数
- **THEN** 通过新版本发布，既有任务和服务实例使用原快照，禁用模板不能用于新提交

### Requirement: SDK 命令与直接协议
客户端 SHALL 支持 SDK 包装业务命令和程序直接实现评测协议；两种方式均传入任务清单项、参数、回合数、种子、推理地址及目录，支持逐回合结果、去重、重试和汇总。

#### Scenario: SDK 包装逐回合命令
- **WHEN** SDK 按回合启动业务命令并取得约定结果
- **THEN** 自动生成开始/完成事件和最终汇总；非零退出或结果缺失必须失败，不把退出码零推断为评测成功

#### Scenario: 直接协议与普通日志
- **WHEN** 业务程序输出回合事件或仅输出普通日志
- **THEN** 仅已验证回合事件增加进度，重复事件不重复计数，日志不会被猜测为完成回合

### Requirement: 三类参数与类型化业务契约
模板 SHALL 区分平台参数、业务参数和运行参数，声明业务字段类型、默认值、必填、约束、覆盖权限及输入文件/argv/env 绑定；运行实例保存有效配置快照，业务字段不得覆盖平台分配的身份、资源及保留变量。

#### Scenario: 集合任务参数传给客户端
- **WHEN** 用户用同一模板提交含不同任务名和业务取值的集合
- **THEN** 平台逐项校验并生成独立任务快照，客户端收到该项任务与回合参数，argv 保留参数边界，不通过 shell 拼接

#### Scenario: 业务取值影响运行需求
- **WHEN** 模板声明某业务选项对应特定运行资源或能力需求
- **THEN** 平台按显式确定映射生成并校验规范化需求，预检和调度使用相同规则，不能绕过资源账本

#### Scenario: 参数非法或越权覆盖
- **WHEN** 参数类型不符、缺少必填值或覆盖未开放字段
- **THEN** 提交阶段指出具体任务和字段，不创建部分可运行批次，也不等到 Worker 启动后才发现

### Requirement: 通用容器目录和设备挂载
Docker 模板 SHALL 支持逻辑目录和逻辑设备挂载声明，由已批准节点映射解析；目录包含目标路径和读写属性，设备包含目标和权限需求，独占设备与端口由统一账本预留。GPU 挂载不得绕过调度分配。

#### Scenario: 异构节点解析相同模板
- **WHEN** 两台节点的同名逻辑目录或设备对应不同物理路径
- **THEN** 各自解析到已批准路径并校验就绪，用户无需复制机器专属模板；缺失映射仅使对应节点不满足准入

#### Scenario: 独占设备或端口竞争
- **WHEN** 两个执行请求同一独占设备或同一主机协议端口
- **THEN** 只允许一个持有有效预留，另一个排队或返回可解释冲突，停止但未清理时不提前释放

#### Scenario: 旧模板与旧 Worker
- **WHEN** 升级参数契约版本并保留历史任务
- **THEN** 旧快照按旧规则执行，旧 Worker 不领取需要新参数绑定或挂载能力的任务
