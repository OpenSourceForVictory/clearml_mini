## Purpose
为已纳管计算资源提供可理解的资源池管理入口，统一展示异构 GPU、队列、占用和成员变更进度，复用已有排空及版本检查语义，避免机器管理与资源组织混淆。

## ADDED Requirements

### Requirement: 池生命周期与成员管理
平台 SHALL 提供池新增、名称及策略编辑、停用、成员加入/移出和删除；成员以 GPU 为粒度，支持混合型号，已有排空与并发版本检查继续有效。

#### Scenario: 删除被使用的池
- **WHEN** 池有成员、待迁移成员、待处理或运行任务
- **THEN** 拒绝删除并显示原因；仅有历史引用的池可归档隐藏但保留可追溯记录

#### Scenario: 修改资源策略
- **WHEN** 管理员降低并发或停用池
- **THEN** 阻止不符合新策略的新准入，已领取执行继续完成

### Requirement: 模块边界与资源一致性
平台 SHALL 明确机器、成员、模板、编排、服务、调度、执行和结果模块的状态归属；通过明确接口协作，资源准入及释放只由统一资源账本控制。局部操作失败不得绕过租约、排空或清理约束影响无关执行。

#### Scenario: 局部接入或配置失败
- **WHEN** 新机器 SSH 接入失败或某个模板配置校验失败
- **THEN** 错误限定到对应操作，已纳管机器的续租、取消和结果上报继续可用，失败提交不产生有效资源占用

#### Scenario: 跨模块停止与资源释放
- **WHEN** 机器停用、成员迁移或服务停止涉及正在运行的执行
- **THEN** 通过统一执行生命周期协调，保留执行身份和清理前占用，重复或过期回执不能提前释放资源或改变无关执行
