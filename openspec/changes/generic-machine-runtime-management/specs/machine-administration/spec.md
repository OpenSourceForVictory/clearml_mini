## Purpose
统一客户端和服务端机器的接入、环境检查与生命周期，保留既有资源身份和执行历史，让管理员明确区分接入、就绪、停用与解除纳管状态，并避免重复安装破坏已有配置。

## ADDED Requirements

### Requirement: 多角色机器及配置详情
机器 SHALL 支持客户端、服务端或两者兼任，展示 GPU、容量、心跳、目录及运行能力；旧机器默认客户端且身份不变。

#### Scenario: 升级既有机器
- **WHEN** 五台已纳管机器升级
- **THEN** 原 slot、池归属、NFS 配置和历史任务保留，机器显示为客户端

### Requirement: SSH 检查与纳管
管理员 SHALL 能提交 SSH 主机、端口、用户名及凭据完成环境检查和确认安装，看到逐步进度与失败原因；纳管仅在身份确认和 Agent 回连后完成，不将密码私钥写入数据库或日志。

#### Scenario: 缺失依赖或连接失败
- **WHEN** SSH 失败、主机身份变化或所选执行方式缺少依赖
- **THEN** 显示失败阶段和修复建议，不伪造在线机器或自动覆盖既有安装

#### Scenario: 重复注册
- **WHEN** 同一注册操作重试或目标已有平台 Agent
- **THEN** 操作幂等或明确冲突，不产生第二套执行身份；已有配置更新必须明确选择

### Requirement: 停用与解除纳管
平台 SHALL 区分停止新准入与撤销纳管，停用允许现有执行继续上报；解除纳管须先排空已领取任务、服务及清理，撤销凭据并保留历史记录。

#### Scenario: 忙碌机器解除纳管
- **WHEN** 机器有活动执行或未确认清理
- **THEN** 不立即撤销凭据，显示阻塞原因并停止新准入

#### Scenario: 已解除机器重连
- **WHEN** 旧 Agent 使用撤销凭据重连
- **THEN** 请求被拒绝，机器不会自动恢复纳管；磁盘资产不会被删除
