## Purpose
为无法或不适合容器化的业务提供宿主机执行能力，在统一任务协议和资源预留下管理程序及子进程，使取消、租约失效和 Worker 重启时的执行身份与结果保持可追溯。

## ADDED Requirements

### Requirement: 宿主机环境准入
平台 SHALL 只在已批准并探测就绪的宿主机环境运行 host 模板，绑定已分配 GPU 和独立工作目录，保留每次执行的输入、环境引用及日志；明确宿主机并非容器安全隔离。

#### Scenario: 环境未配置
- **WHEN** 模板所需环境或可执行程序在节点不存在
- **THEN** 预检解释不匹配原因且不启动任务，不自动安装业务依赖或回落其他解释器

### Requirement: 进程树与恢复
宿主机执行 SHALL 在取消、超时、租约丢失或服务停止时终止所属进程树，确认清理前不得释放资源；重启恢复依据执行身份，不仅依据可复用 PID。

#### Scenario: Worker 重启
- **WHEN** 本地执行日志仍存在且进程已启动
- **THEN** 只恢复或终止原执行，不重复启动业务命令，也不杀死无关进程

### Requirement: 结果通道一致
宿主机与 Docker SHALL 使用同一任务输入、回合事件和产物协议，用户无需为不同执行方式实现两套业务协议。

#### Scenario: 同一客户端切换执行方式
- **WHEN** 在两个已就绪环境中分别运行相同样本
- **THEN** 两者都能展示逐回合进度、日志和结果，且目录解析指向各自执行工作区
