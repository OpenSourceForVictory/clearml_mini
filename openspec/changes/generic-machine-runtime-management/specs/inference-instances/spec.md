## Purpose
在已纳管服务端机器部署长期运行的推理业务，提供清晰的启动、健康、日志和停止状态，并与评测任务共用物理资源记账，向现有客户端地址列表提供可复制的推理地址。

## ADDED Requirements

### Requirement: 服务部署与资源预留
管理员 SHALL 选择服务端模板版本、目标机器/GPU、参数及端口部署实例，保存快照并先入队；服务与评测共享资源准入和清理约束，不建立推理服务池。

#### Scenario: 兼任机器资源不足
- **WHEN** 评测任务占用服务需要的 GPU 或主机额度
- **THEN** 服务显示等待资源，不绕过资源池独占与主机容量限制

### Requirement: 服务生命周期和地址
服务 SHALL 展示等待、启动、健康/异常、停止及失败状态，支持停止和重新启动，校验端口冲突并提供服务地址；停止是期望状态，进程已退出且清理确认才表示实际停止。

#### Scenario: 健康检查失败
- **WHEN** 进程存在但探测失败或启动超时
- **THEN** 不显示就绪，展示可诊断状态；客户端不会因仅有 PID 就被告知服务可用

#### Scenario: 停止重启
- **WHEN** 用户停止后重新启动实例
- **THEN** 原执行先完成清理，新执行有独立身份，旧日志可追溯且不会遗留端口占用

### Requirement: 实例日志与权限
平台 SHALL 提供有界日志和失败原因，限制实例管理为管理员，并在机器离线时区分最后报告与实时健康。

#### Scenario: 机器断线
- **WHEN** 服务端心跳过期
- **THEN** 实例不继续显示实时健康，未确认清理的资源仍受保护
