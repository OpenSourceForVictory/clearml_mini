# Design

## Context

动机见 proposal.md。当前 ClientRequest.endpoint 为必填字段，BatchClient 继承它，snapshot 将地址和模板写入 Job.client_spec。scheduling.endpoint_conflict 从 Job 快照取单地址，以模板 endpoint_exclusive 与 held_jobs 判断互斥。Worker claim 直接下发 Job 快照。预检复用此判断，reports 直接读取 spec['endpoint']。因此仅把字段改成列表会破坏互斥、恢复和报告，必须引入尝试级分配。

## Goals / Non-Goals

**Goals:** 在现有调度事务内联合选择 slot 与 endpoint；保证旧任务、旧输入协议及各尝试历史稳定。

**Non-Goals:** 不托管推理服务、不注册服务池、不增加端点共享并发配额、健康巡检、模型加载或连接中途故障转移。本次不验证不同服务端的模型版本一致性。

## Decisions

### 1. 候选列表是运行配置，地址选择是尝试状态

新增请求形态 `client.endpoints=[{"url":"ws://host:8000","mode":"exclusive"}, ...]`；与旧 `endpoint` 二选一，列表最多 100 项，模式必填。复用 endpoint_parts 校验，每项协议需被模板允许。按小写主机名（去末尾点，规范 IP 字面量）及有效端口检查重复；相同主机端口的不同路径/协议也不能重复登记为多份容量。URL 路径保留用于实际请求。

旧 endpoint 在读取时适配成单项候选，模式来自快照模板。显式列表的模式由用户控制，覆盖模板旧默认；新界面从模板默认模式初始化行，允许用户修改。不将共享做成需管理员批准的新流程。

保持 Job 快照不可变；不在 Job.endpoint 中不断覆盖选择，也不在注册表中管理地址。建议 Run 增加 nullable assigned_endpoint、assigned_endpoint_mode 字段，配套成对非空/合法模式约束和必要索引。完成旧尝试可从历史单地址快照回填，但未绑定的新列表尝试不能伪造默认地址。

### 2. 调度事务统一绑定与占用

沿用现有 PostgreSQL 全局调度锁。将 held_jobs 端点判断改为基于持有资源的 Run，优先读实际分配，旧行缺省时读取历史单地址；PENDING 新尝试不能从候选列表产生虚假占用。RESERVED/STARTING/RUNNING/CANCEL_REQUESTED 和 cleanup_confirmed=false 的旧执行均计入占用。

对候选过滤互斥：已占用方或新候选任一 exclusive 就拒绝；shared/shared 允许重叠，不引入请求限流或服务额度。按已持有尝试数最少、原列表顺序选择，以便空闲服务优先获得任务。保留既有用户/集合轮转和资源准入。不把“独占优先”实现为抢占或插队。

只有 endpoint 和 slot 都能分配才在同事务写入绑定与资源预留，并更新本轮内存占用，使同一 tick 后续任务和多 API 实例都看见已占用状态。扫描所有清除 RESERVED 的路径：预留超时、批次暂停、取消、机器存储/运行环境/成员配置切换；回到 PENDING 的同尝试清除绑定与资源。已认领尝试不清除历史绑定，是否占用仍由执行状态与 cleanup_confirmed 决定。

### 3. 下发与执行恢复

Worker claim 将 Job 快照复制为执行输入，再填入 Run.assigned_endpoint；保留现有 endpoint 字符串协议，不要求 Worker 认识候选列表。列表只保存在服务端和有权限的运行视图，避免客户端自行选择绕过分配。反复 claim 同执行返回同地址；旧 Worker/SDK 可继续运行。

本地 journal 已保存任务输入，恢复按原任务/执行 ID 处理。无法连接服务时遵守现有请求超时、任务失败和清理流程，不在运行中换端点。手动重试创建新 Run，可重新选择；历史尝试原绑定用于报告和审计。

### 4. 预检、诊断、结果使用同一模型

抽取统一候选规范化、资源键和互斥函数，供调度与预检调用。预检不预留，不做外部网络 I/O；返回逐候选可用/占用原因及整体 endpoint_busy（仅所有候选均不可用时）。其他用户占用只返回汇总原因，不暴露其任务和地址清单。现有客户端启动连通性检查继续针对所分配地址执行。

运行向导以可增删行显示 URL 和模式，试跑、正式运行、预检与幂等提交使用同一冻结请求。旧单地址入口兼容。任务详情/监控展示实际地址及模式；尚未分配明确显示待分配。JSON/CSV 报告与比较展示候选配置和实际选择，旧数据沿用旧地址，不推断远程模型版本。校验地址列表变化会使旧预检失效，轮询不覆盖用户草稿。

## Risks / Trade-offs

- [名称别名绕过互斥] → 与现状一致按规范主机端口识别；文档要求统一使用同一名称，不声称自动解析 DNS/IP 别名为同服务。
- [共享请求超出推理服务能力] → 用户显式选择共享，界面说明服务端需隔离会话；不暗中新增共享容量配置。
- [独占任务等待持续共享流量] → 保持现有公平调度，无抢占或额外优先级承诺；测试混合模式不发生重叠。
- [旧模板独占与列表模式冲突] → 仅旧单地址使用模板默认，显式列表使用用户选择；覆盖 Cosmos 兼容场景。
- [旧报告把第一地址当作实际执行] → 逐次尝试持久绑定，逐接口核对；未分配不填默认。
- [新字段被旧调度器忽略] → 更新控制端前短暂停止调度并备份，避免新旧 API 调度器混跑；回退必须排空多地址任务。

## Migration Plan

迁移增加 nullable 尝试字段，为已分配/历史单地址执行回填 URL/模式，PENDING 保持未分配；校验旧数据升级及 Alembic 无差异。API/前端先构建并完成隔离 PostgreSQL、真实 Docker 多地址验收；生产备份、停止旧 API 调度后迁移和上线。Worker 输入协议不变，无需仅为本特性升级 Worker。

回退前停止接收多地址提交，取消或排空已有多地址运行并确认清理，备份记录。降级必须拒绝仍存在待运行/持有资源的多地址任务，不能让旧调度器把列表当单地址执行。历史多地址记录即使没有活动任务也不应直接交给不认识列表的旧 UI；回退采用升级前快照恢复到独立数据库，明确升级后记录需另存，不静默丢失历史或把多个地址压成第一个。
