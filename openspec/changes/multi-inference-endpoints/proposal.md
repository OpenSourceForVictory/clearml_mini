# Proposal

## Why

当前一次集合运行只能配置一个推理地址，互斥规则来自客户端模板；多个服务实例需要拆成多次提交。用户希望直接填写地址列表和各地址独占/共享模式，由平台为仿真客户端分配地址，无需注册或管理推理服务池。

## What Changes

- 集合运行和单独 CS 任务支持地址列表，每项包含 URL 与 exclusive/shared 模式；保留旧单地址请求及历史模板互斥语义。
- 调度器联合判断客户端资源和服务地址可用性，为每个执行尝试持久绑定一个地址；全部不可用时排队。
- 同主机、端口跨用户/集合执行占用互斥；任一已占用方或候选方为独占时不能重叠，共享之间允许并行。
- 开始执行后保持地址不变，恢复使用原地址；终态且容器清理确认后释放，重试可重新分配。
- 运行向导提供地址增删和模式选择；预检、等待诊断、任务详情、报告/导出区分候选列表与实际执行地址。
- 不新增推理服务池、服务注册、服务进程托管、健康探测系统或共享端点并发额度设置。

## Capabilities

### New Capabilities

- `inference-endpoint-allocation`: 运行级地址列表、尝试级分配、独占/共享互斥、恢复与分配信息展示。

### Modified Capabilities

无。已发布 platform 规格没有端点行为；本变更补充 CS 协议及 Cosmos 样本变更中的单地址逻辑，旧请求保留原语义。

## Impact

涉及 ClientRequest/BatchClient、Run 字段及迁移、调度器和所有预留释放路径、Worker claim 下发、预检/监控/报告、React 运行向导和相关测试。沿用 FastAPI/PostgreSQL/React 与现有 Worker 输入协议；Worker 接收具体 endpoint，不自行从列表选择。无需第三方依赖。
