# Design

## Context

见 proposal.md。用户确认本次只优化界面读取；调度扫描与资源快照风险另行评审。

列表 batch_view 对每个批次分别加载任务、所有尝试和回合；node_view 每台机器查询 slots 和占用 count。详情 monitoring.monitor 无论是否有 PENDING 都建立全平台 DiagnosticContext；orchestrations.view 先调用 batch_view，又读取服务诊断。前端 OrchestrationStatus 首次打开后一直挂载，即使 hidden 也继续 usePoll；回到任务页又挂载 ServiceStartupSummary，两者调用同一完整接口。ArtifactBrowser 和服务日志已按展开挂载，应保留。

## Goals / Non-Goals

**Goals:** 降低界面读取放大；结果、调度顺序、权限与控制语义保持一致；用固定数据规模与 SQL 计数验证收益。

**Non-Goals:** 不改变历史编排退出扫描规则，不缩小全局锁范围，不修改租约、并发额度、Worker 协议。不引入后台摘要表、跨请求缓存或持久化完成标记。大量历史编排的扫描成本仍是明确残留瓶颈。

## Decisions

### 1. 调度优化延期

用户确认先做界面查询。本次不修改 scheduling、Planner、资源预约、调度公平性、快照或锁。原候选分组与共享资源快照设计留待独立变更重新评审。

### 2. 节点批量读取，列表提供可选摘要

节点列表一批读取 worker、slots 和按 worker 聚合的持有执行数，单节点 node_view 保持可用。批次 GET /batches 增加显式 view=summary（默认 full），保持页大小、排序、权限及现有完整响应。摘要批量读取本页任务的最新尝试及统计需要的投影字段，复用统一结果分类语义，不返回 cases、模板快照和回合原始内容。避免用复杂 SQL 重新发明另一套业务成功率定义；以 full/detail 同数据差分测试约束摘要。查询可按数据库参数上限分块，但不得每任务/每批次逐个查询。

前端 Batch 类型分离摘要和详情，BatchHistory 不再依赖 cases 计算摘要；控制/优先级响应仍可更新摘要字段。旧接口调用者无需同步更新。

### 3. 详情诊断按需，服务视图与批次结果解耦

monitor 仅在存在 PENDING 且需要等待诊断时构造 DiagnosticContext；纯运行/完成批次按关联 slot IDs 批量获取位置。不改变当前 waiting、reason_codes 和配置字段，保留 RESERVED/waiting_service 说明。诊断上下文内按 pool 索引节点、复用排序和活动占用；不同资源要求或服务绑定不能共用错误的诊断结果。最新尝试投影替代读取全部历史 attempts，历史尝试接口仍完整保留。

服务接口增加显式轻量视图（原 full 默认不变），不调用 batch_view；批量加载实例的当前 job/run/slot 和清理占用。只有确有待诊断的服务定义才构建诊断资源；保留所有服务定义与多实例关系。任务页概览与服务页复用这一接口。

前端为服务组件提供 active 条件并传递给 usePoll，隐藏组件保留 UI 状态但停止订阅；请求完成后的迟到响应不得覆盖新路由/尝试。顶层 monitor 继续刷新，因为顶部控制条和全局概览在所有页签均可见；其读取通过按需诊断和最新尝试投影降低开销。子页签暂停刷新保留数据，切回立即刷新；控制接口原 expected_revision 冲突保护保留。

### 4. 验证与收益标准

- 正常/边界/失败：无任务、多卡多实例、未清理执行、完成后重试、暂停恢复的展示与控制修订、越权及缺失对象；关联编排与执行回归检查读取修改没有破坏原行为。
- 数据一致性：单进程与逐回合、普通命令/direct/SDK、退出 0 但协议错误、历史尝试、多回合、待清理、已删除和越权，摘要/monitor/full 逐项对照。
- SQL 增长断言：节点列表从 10 到 500 节点不产生每节点 2 条 SQL；本页批次查询不产生每批次固定重复查询组；无 PENDING 的 monitor 不加载全平台资源。
- 浏览器：服务页往返与路由切换、慢响应、请求失败、回合展开和补跑后 attempt 改变；断言隐藏页签不重复订阅且筛选保留。
- 隔离 PostgreSQL 对照：500 节点；20 批次每批 100 任务；单批 100 任务各 10 回合，固定数据比较原读取与新读取。预热后至少 3 次记录耗时、SQL 数、响应字节并核对结果统计。不将耗时作为脆弱 CI 断言。
- 运行相关专项与统一覆盖率工具，保留失败/跳过证据及未达门槛项；不把专项比例或旧全量报告冒充本次全量达标。真实节点业务不是查询优化吞吐的替代证据。

## Risks / Trade-offs

- [只减少响应但仍读取大字段] → 摘要投影模板分类标志和结果分类字段，查询数与响应体分别记录。
- [摘要与详情统计分叉] → 统一分类函数和差分矩阵，不新增持久化缓存。
- [历史尝试误计入摘要] → 按最大 attempt 选择当前尝试；历史接口保留所有尝试。
- [隐藏页状态过期] → 重新可见即刷新，保留版本冲突检查与错误提示。
- [历史编排仍拖慢调度] → 对照时固定历史数量单独报告；本次不宣称解决该瓶颈或最大 Worker 容量。

## Migration Plan

预期无需数据库迁移。先发布兼容 API，再更新前端；Worker/Runner 无须升级。回退前端仍可使用 full 接口，API 可整体回退。发布前完成专项、同步操作文档/界面指南及 Skill 引用，记录测试边界和 Git 提交。

## 审查补充（用户确认仅查询）

暂停轮询保留已有数据，只有路径变化清空；顶层批次监控继续为可见控制条提供状态。隐藏页签的回合、日志和任务排查也停轮询。列表静态选项与动态批次刷新分离，主动保存/提交后刷新。摘要直接投影需要的字段，最新尝试以 attempt 最大值确定，不能以时间或 UUID 代替。
