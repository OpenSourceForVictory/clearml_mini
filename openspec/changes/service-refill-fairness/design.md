## Context
普通准入已按用户轮转和用户内批次优先级排序，补齐独立按 UUID 顺序扫描。保留两个阶段，不把新增服务和客户端强行统一成新调度算法。

## Goals / Non-Goals
修复补齐公平性；不移除锁、不缓存 Planner、不改变容量及就绪条件，不承诺跨用户全局优先级。

## Decisions
持久 SchedulerState(service_rotation) 与普通 rotation 分离。按有效编排所属用户排序，从最后成功补齐用户之后开始；每用户每轮尝试优先级降序、批次创建时间升序、批次 ID 升序，再按模板定义顺序。每次仅补一个，下一轮重建 Planner 核对最新预约。无法满足的候选继续检查同用户后续候选；整轮无进展终止。仅成功补齐时更新游标，和预约同事务回滚。无客户端活动时仍要求联合容量；已失败的显式实例不被静默重建。

## Risks / Trade-offs
仍保留既有重复 Planner 成本，优化另行基准验证。高优先级可长期压低同用户低优先级；这是现有队列语义。跨用户公平不能被批次优先级绕过。

## Validation
复现两个批次仅一个剩余位置；覆盖优先级/同级时间、跨用户跨 tick 轮转、一次多位置每轮一个、不可满足队首、暂停/删除/账号禁用、预算及回滚、已有目标幂等。关联服务/预约/优先级测试及关键功能组覆盖率。无真实模型质量声明。

## Migration Plan
无需迁移，新游标按需创建；回滚会恢复旧排序。发布与代码验证分开记录。
