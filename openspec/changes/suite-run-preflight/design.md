# Design

## Context

现有 CSWorkbench 以 FormData 一次提交所有参数，SuiteManager 已能传入发布集合。batches.py 同时负责权限、集合解析、参数校验及事务写入；image_runtime 的任务就绪 API 要求已有 Job，不能直接供提交前调用。scheduling.py 的准入分散在 eligible、tick 和 storage/memberships/image_runtime 模块，资源占用包含尚未确认清理的尝试。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 在不改变调度语义的前提下复用校验与资源判定；前端只有一份受控运行草稿；现有 API 调用者无需改动。

**Non-Goals:** 不做显存硬隔离，不预留试跑资源，不从 API 服务探测用户 URL，不引入保存服务地址或密钥的数据模型。

## Decisions

1. 新增 POST /api/v1/batches/preflight，沿用 BatchSubmit。提取不修改请求、不写数据库的清单解析及校验，返回规范化清单和客户端快照，供预检与 create 共用。create 保留锁、配额重查及完整事务。相比复制校验逻辑，可防止预检与提交逐渐分歧。
2. 返回 checked_at、任务/回合汇总、全局原因及逐 GPU 槽位原因；每个原因含稳定 code、中文说明、category（environment/resource）、建议操作。非法请求保留现有错误状态码并附可定位错误。容量状态由共享纯判定函数产生，调度继续消费相同函数；不调用 tick 或 reconcile 做预检。测试覆盖原 eligible 行为及用户/全局/节点配额、endpoint_conflict、未清理资源计数。展示“当前可接纳单项任务”，不把槽位数误当作整个批次的可用并发承诺。
3. 仅返回选择资源池的必要节点标识和逻辑资源名。普通用户不获得宿主路径、原始运行环境报告或其他用户任务信息。没有候选节点属于可提交的等待原因；被禁用或不存在资源池沿用提交错误。
4. 拆出运行向导组件和草稿类型，集合选择锁定匹配客户端，切换自定义必须显式操作。隐藏步骤不依赖浏览器对不可见必填字段的校验。向前逐步校验，返回保留草稿，轮询只更新列表和状态。配置变化清除预检；异步响应通过请求序号或指纹拒绝旧响应。确认前重新预检，失败可重试，不展示过期成功状态。
5. 试跑将用户选中任务复制为一个回合的自定义批次，保留 task_name、seed、parameters、客户端及资源，max_concurrent=1，suite_id 留空，名称标注试跑及来源集合版本。避免为局部执行增加正式集合覆盖语义或修改不可变版本。通过现有批次 API 轮询并链接任务详情；保留完整正式草稿，试跑与正式提交独立幂等键。未声明回合上报的模板明确显示无法验证回合报告，不能伪造已完成一回合。

## Risks / Trade-offs

- [预检与调度判定分歧] → 提取共享判定并增加同一状态下的一致性测试，不复制整套调度器。
- [状态随时变化] → 显示检查时间及非预留说明，提交重新校验，调度再次准入。
- [提取事务校验破坏幂等或并发] → 保留原幂等查找顺序与锁，回归并发及批次原子创建。
- [预检成功被误解为模型可评测] → 明确服务连通与客户端协议需要实际试跑，试跑成功也只说明所选任务的一回合结果。
- [页面轮询覆盖草稿] → 将服务器列表与受控草稿分离，浏览器测试验证返回步骤和轮询后的值。

## Migration Plan

无需数据迁移。先完成隔离后端测试、前端类型检查与浏览器回归，再在隔离实例跑三任务向导、试跑及缺资源排队。部署时保留原镜像用于回滚；上线只读检查与专用测试批次验收，不修改已有集合及节点配置。记录证据并 Git 提交。
