## Purpose

让用户通过分步操作完成仿真评测提交，在执行前理解清单、客户端、资源需求和节点准备情况，并通过独立试跑验证客户端链路，保留资源不足时先提交排队的能力。

## ADDED Requirements

### Requirement: 分步运行与参数保留
平台 SHALL 提供集合、客户端与服务、资源、确认四步运行流程，支持已发布集合和自定义清单，保留返回编辑时的参数，确认页展示集合版本、任务与回合总数、客户端版本、服务地址、每项资源及最大并发。

#### Scenario: 从集合管理运行
- **WHEN** 用户点击已发布集合的运行入口
- **THEN** 向导带入集合、客户端和任务清单，已发布清单不可被临时修改，返回上一步不丢失输入

#### Scenario: 自定义任务清单
- **WHEN** 用户选择自定义清单并填写任务参数
- **THEN** 向导校验任务及回合定义，确认后提交相同清单

### Requirement: 无副作用预检
平台 SHALL 提供与批次提交一致的权限和参数校验，并只读返回当前候选节点及原因；预检不得创建批次、任务、尝试或资源预留，不得启动容器或主动连接用户指定服务。

#### Scenario: 非法配置或越权访问
- **WHEN** 用户预检不可访问集合、模板或无效资源参数
- **THEN** 请求被拒绝且不泄露他人配置，输入错误可定位，数据库中不产生评测记录

#### Scenario: 多次检查合法配置
- **WHEN** 用户重复预检合法批次
- **THEN** 返回检查时间、任务与回合总数、各节点的资源和环境判定，资源占用及队列保持不变

### Requirement: 可解释的准备状态
平台 SHALL 区分参数错误、需要准备环境、暂时等待资源和当前可运行，覆盖镜像、逻辑资产、在线状态、配置生效、磁盘、GPU 匹配及容量、资源占用、节点配额、用户与全局并发以及服务互斥，结果仅代表检查时刻而非资源承诺。

#### Scenario: 环境或资源不足
- **WHEN** 合法任务缺少镜像、资产、匹配 GPU 或暂时无空闲资源
- **THEN** 确认页展示原因与建议操作，允许用户提交排队，不承诺固定名次和开始时间

#### Scenario: 预检后条件变化
- **WHEN** 用户改变参数或节点状态在提交前发生变化
- **THEN** 修改参数使旧预检失效，提交重新校验且调度继续按最新资源判定；旧预检不能绕过校验或保证即时执行

#### Scenario: 普通用户查看节点原因
- **WHEN** 返回镜像或逻辑资产缺失原因
- **THEN** 只包含必要节点和逻辑资源信息，不包含宿主机目录、凭据或其他用户任务内容

### Requirement: 独立单回合试跑
平台 SHALL 允许用户从当前清单选择一个任务以一个回合和并发一发起独立试跑，保留该任务其他参数，通过正常排队、执行、回合上报和取消链路展示进度及结果；试跑不修改集合或正式运行草稿，且不自动发起正式运行。

#### Scenario: 试跑后正式提交
- **WHEN** 用户完成一个任务一个回合的试跑后提交正式批次
- **THEN** 正式批次使用原始完整清单和回合数，试跑结果不混入正式结果，试跑成功不被标为整个集合完成

#### Scenario: 试跑排队或失败
- **WHEN** 试跑缺少资源、服务不可达或客户端执行失败
- **THEN** 页面展示真实排队或失败状态及详情入口，用户仍可修改配置或返回正式运行

### Requirement: 提交兼容与防重复
平台 SHALL 保持已有批次 API 的合法请求行为和幂等机制，试跑与正式提交使用各自的幂等键，并在向导中阻止重复点击创建重复批次。

#### Scenario: 网络重试
- **WHEN** 同一试跑或正式提交因响应丢失被重试
- **THEN** 同一请求复用幂等键，返回原批次；正式运行不会误用试跑批次
