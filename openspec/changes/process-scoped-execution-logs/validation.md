# 验收与测试矩阵

这是实施验收要求，尚未执行，不得作为已通过证据。

## 归属矩阵

| 执行方式 | 模式 | 要验证的日志 |
| --- | --- | --- |
| host | direct + per_episode，普通命令/平台协议，stop/continue | 每个已启动回合独立；诊断公共；未启动回合无伪日志 |
| host | sdk-command，显式 per_episode 及既有逐回合适配 | 按实际子进程分回合，参数/seed/退出码原样保持 |
| host | whole_task，普通命令/direct/原生 SDK | business 公共日志，多个协议回合不触发错误拆分 |
| docker | 普通命令/direct/原生 SDK 整进程 | business；挂载写权限、注入适配与输出独立 |
| docker | sdk-command 每回合子进程 | episode；不能因 host episode_launch 不存在而漏分 |
| host/docker | 两个同名服务实例，同节点不同卡 | service 按实例执行隔离，不按名称串写 |
| old worker/runner | 旧执行及能力回退 | v2 公共入口不变，不伪造回合文件 |

每项覆盖正常结果、退出 0 缺 final、业务非零退出；验证结果与日志独立且协议事件恰好一次。原生 SDK 内部线程/并行回合保持公共日志，不推断因果。

## 失败、边界与恢复

- 同时大量 stdout/stderr，纯 stderr、无换行、8 KiB 以上记录、分块 UTF-8、非法编码、ANSI；消费并发且内存有界。
- 空输出、启动前失败、最后一个字节后直接退出、子孙进程持有管道、超时/取消/SIGKILL、磁盘满/只读/慢写、队列溢出；退出码与日志关闭原因正确。
- 分片、scope、执行、整机四处阈值边界；多卡同时写入、崩溃留下预留额度、降额、10000 回合；总体积包含元数据/转义，文件数和清理标记不无限增加。
- Worker/API 重启、重复页响应、claim 过期、游标代次变化、长时间离线、节点目录配置修改；不重启业务、不把历史根换成新目录。
- 单页读与轮转、读与 staging 清理、读与批次删除、下载中删除；无无限锁和持有 DB 连接等待。
- 越权、跨尝试/节点、任意路径、..、符号链接换入、非普通文件、替换 manifest、过大响应、过期 token、读请求重放；不得读取执行范围外文件。
- 终态租约已过期仍可授权读文件；删除任务后迟到响应不能复活索引或泄露缓存。

## 平台负载

使用隔离 API/数据库和可控制的 Worker 慢响应。默认预算下饱和 128 个活跃/缓存请求，验证总响应正文不超过 8 MiB、超额请求 429、TTL 到期可回收。将连接池缩至 2 并使 Worker 延迟 20 秒，验证正常心跳和任务查询仍有可用连接，日志接口没有等待节点的长事务；记录 p50/p95、CPU、峰值内存、DB 连接占用和请求数，不只报告“接口成功”。

无人打开页面时验证没有全文件持续上传；两用户同页复用节点请求但权限独立；关闭面板停止查询；大量小片段不引发按行数据库写入。

## 界面

真实/模拟 API 两类测试分别标明。覆盖两个任务入口、单进程公共提示、逐回合日志抽屉、同名服务实例、选择旧尝试、迟到响应、复制成功/拒绝、暂停跟随、向前翻页、空页过滤、截断/离线/已清理、有限下载及不支持流式浏览器、键盘焦点和窄屏。前端未插桩不计 Python 覆盖率。

## 迁移与真机

- 专用一次性 PostgreSQL 验证迁移保留旧 RunLog/RunLogChunk；批次删除新索引/读取数据的外键顺序及终态并发回包；降级数据损失单独记录，禁止用生产数据库测降级。
- GPU 节点真实宿主机/容器小程序运行；NPU 节点真实宿主机服务；同节点不同卡的同名双实例；先核对活跃任务、节点权限和目录，记录实际执行/日志/页面证据。不能将 Python 回显称为 GPU/NPU 模型评测；不具备对应机器或镜像时保留阻塞/跳过，不能用模拟结果替代。
- 用 scripts.test_coverage 同口径检查覆盖率：逐目录 80%/70%，业务执行结果关键组 90%/80%。定向回归选择不改变分母，门槛未通过如实记录；不合并不同源码版本数据。保留首轮失败和跳过。

## 本次决策与阶段证据

整机配额默认不限制，跨账号配额通道不启用；执行内预算继续有限。现有压测项目仍为完整验收要求，不能以单进程小程序替代。已执行的接线回归与未完成项见 [验证记录](../../../docs/validation/process-log-connected-20261119/README.md)。

原生 SDK 组合要求：真实 EvaluationClient 子类，在 host 整任务（stop/continue 不扩大适用范围）、host per_episode（stop/continue）及 Docker 整任务下覆盖正常、业务结果 False、Exception、非法 EpisodeResult、SystemExit(7)。同时检查回合事件只上报一次、最终汇总、seed 回绕、输入/环境与公共/逐回合日志。独立进程及容器未插桩，不合并为已统计的行覆盖率。

子进程/Worker 故障补测必须同时断言业务退出码和日志状态：缺失日志根、磁盘写入/关闭故障、慢写、超长行和未结束行、回调异常后子进程回收；节点侧验证独立线程存活、停止、目录与代次身份、跨槽位拒绝、清理锁 busy 后恢复、API 暂断重试和删除后清理私有登记。单模块比例不替代目录/关键功能门槛，未插桩子进程不计覆盖率。

补充回归场景：轮转需淘汰旧文件时分别中止于新索引提交前、提交后和旧文件删除后，再由新 Worker 日志服务恢复；四进程在同一执行目录写入独立 scope；分页持锁期间清理拒绝，释放后清理成功；已有一万回合索引限定一次同步 16 项；约 25 MiB 输出遇到阻塞 sink 时队列和 stderr 尾部有界；离线节点 128 项请求、每用户 8 项与 PostgreSQL 两连接池下八路并发，超限 429、TTL 过期释放且心跳/取消可达。API 测试冻结请求时钟精确推进 TTL，耗时仅记录实际请求耗时；这些不是生产长时间容量验收。

最终关联回归：870 通过、40 跳过；业务执行与结果完整 38 文件分母为行 91.21%、分支 83.13%，达到 90%/80%。全仓其他目录未达标及真实节点矩阵跳过均保留，不宣称全项目达标；证据见 docs/validation/execution-group-logs-20261119（从仓库根目录定位）。
