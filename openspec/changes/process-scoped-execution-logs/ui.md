# 日志界面设计

本文件是设计稿，不表示功能已上线。

## 批次 → 任务 → 回合

保留“程序执行”“平台协议结果”两套统计。回合表增加日志入口，不新增混合的成功/失败列：

| 回合 | Seed | 程序执行 | 平台协议结果 | 日志 |
| --- | --- | --- | --- | --- |
| 1 | 100000 | 正常结束，退出码 0 | 业务成功 | 查看回合日志 |
| 2 | 100001 | 正常结束，退出码 0 | 结果校验异常 | 查看回合日志 |
| 3 | 100002 | 运行中 | 等待结果 | 查看回合日志 |

单进程多回合模式按钮改为“查看公共日志”，并在列表顶部说明“本任务的多个回合共用一个业务进程和同一份日志”。未启动回合不提供伪造日志，显示未启动；启动失败的任务提供执行诊断入口。已清理显示“日志已清理”，仍可查看保留的结果和平台缓存说明。

任务详情顶部显示所选执行尝试、执行 ID、节点/卡及实际目录；复制路径不执行节点命令。批次排查和完整任务详情共享组件。服务实例按行显示日志入口，名称相同也必须显示实例身份和当前执行尝试。

## 统一抽屉

```text
+-------------------------------------------------------+
| Round 2 / Seed 100001 / Attempt 1              [Close] |
| Node / Device / Execution ID                   [Copy] |
| Source: node | Status: closed | Updated: ...           |
| [All] [stdout] [stderr] [Follow/Pause] [Download]       |
| [Load earlier retained output]                        |
|                                                       |
| Log text ...                                          |
|                                                       |
| [Gap / rotated / cache-only / offline notice]          |
| Node path: ...                                 [Copy] |
+-------------------------------------------------------+
```

实际中文文案：“全部输出 / stdout / stderr”“自动跟随 / 暂停”“下载保留日志”“加载更早日志”。另提供“执行诊断”切换，不能将它混入业务 stderr。

- 默认尾部一页，按需向前加载。内存默认 256 KiB 上限，超过后释放远端页面并保留可重新加载的游标；不自动加载所有历史。
- 向上滚动暂停自动跟随，用户点击恢复后才回到底部。关闭抽屉停止轮询，回合/实例/尝试切换清空旧内容。
- 显示采集来源（节点保留日志/平台缓存/旧版公共日志）、最后更新时间、完整性。终态后仅在日志关闭且读尽时停止自动请求；节点失联采用退避，不无限高频刷新。
- 请求排队、节点离线、超时、权限失效、版本不支持、未生成、已清理、部分淘汰分别有文案。暂无正文并不等于业务未执行。
- 文件内容仅纯文本，可选择复制；ANSI/控制字符不作为 HTML。来源过滤使用记录的 stream 字段，不根据字符串前缀猜测。
- 下载保留范围：开始提示采集时间区间/已淘汰提示；完成报告完整保留范围或缺口。取消下载仅取消读取，不取消任务。浏览器不支持流式文件保存时提供有限分片下载。
- 路径是节点宿主机路径；需要容器映射时并列标注容器内路径，不能把其用作远程任意文件入口。
- 抽屉有标题、焦点管理、Escape 关闭与回到触发按钮；窄屏全宽展示。

## 机器设置

在现有“数据保留”下增加“日志容量”区域：分片大小、单份日志上限、单次执行上限、整机日志上限。显示期望配置与节点生效版本、容量回收中/失败，保存前验证关系和有限值；当前任务继续采用其执行配置，整机保护策略仍有效。显示作用范围：只管理平台采集日志，业务自建文件由原执行数据清理策略管理。
