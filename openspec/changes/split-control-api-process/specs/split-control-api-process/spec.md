## Purpose

在保留外部 API 地址和端口的前提下，允许执行控制请求使用独立进程的处理线程与数据库预算。

## ADDED Requirements

### Requirement: 可选进程隔离
系统 SHALL 提供显式启用的双 API 进程部署，控制请求与普通请求分别进入专属进程；单进程部署继续可用。

#### Scenario: 混合请求
- **WHEN** Web、日志、领取、Agent 监控与 Worker 心跳同时进入同一外部端口
- **THEN** 控制路径进入控制进程，其余进入普通进程，二者不共用 FastAPI 同步线程池

#### Scenario: 单进程默认
- **WHEN** 只使用基础 Compose 部署
- **THEN** 维持一个 API 进程和原端口，不要求修改 Worker 地址

### Requirement: 控制安全与健康
系统 SHALL 只运行一个调度器，并在控制进程不可用或请求被误路由时明确失败，不把控制请求静默改交普通进程。

#### Scenario: 控制进程不可用
- **WHEN** 控制进程故障而普通进程仍可用
- **THEN** 控制请求返回暂时失败，普通接口可继续服务，网关整体健康不伪称完全正常

#### Scenario: 错误路由
- **WHEN** 请求到达与其分类不符的 API 进程
- **THEN** 请求在鉴权和数据库访问前被拒绝

### Requirement: 统一入口与预算
系统 SHALL 保持外部监听地址和端口、认证及响应语义，并按两个 API 进程实际创建的数据库池验证连接预算。

#### Scenario: 切换到双进程
- **WHEN** 管理员使用双进程部署覆盖配置
- **THEN** 浏览器和 Worker 仍使用原平台地址，且两进程合计预算不超过配置的数据库连接上限

#### Scenario: 按职责分配连接且不增加入口并发闸门
- **WHEN** 普通 API 同时收到 Agent 观察、可靠结果、日志与 Web 请求，控制 API 同时收到续租和完成请求
- **THEN** 普通 API 为观察与结果保留独立数据库连接配额、控制 API 为执行控制保留主要配额，且两进程预算分别校验，不额外按类别限制 HTTP 入口并发；连接耗尽时仍按预算返回可重试错误

#### Scenario: 只创建本角色所需的池
- **WHEN** 双进程使用相同的类别额度启动，控制进程不运行调度器
- **THEN** 普通进程只创建普通、观察、结果、调度池，控制进程只创建控制池；总预算按这些实际池计算，单进程部署保持原池契约

#### Scenario: 每进程的线程和连接预算对齐
- **WHEN** 双进程覆盖配置使用默认额度 23/40/9/7/1
- **THEN** 普通和控制 API 各自最多创建 40 个数据库连接，合计 80 个；进程内同步线程额度不因入口中间件扩展超过 40

### Requirement: 空闲领取不争用调度锁
系统 SHALL 在没有候选执行或待清理执行时完成只读领取轮询；涉及实际状态转换时仍须与调度器串行化并重新核对状态。

#### Scenario: 空闲卡位轮询
- **WHEN** 已认证卡位没有待领取执行和待清理执行
- **THEN** 领取接口返回空结果，不尝试全局调度锁

#### Scenario: 候选执行遇到调度锁忙
- **WHEN** 卡位看见候选执行，但本轮无法获取调度锁
- **THEN** 本轮返回空结果，Worker 在下一次正常轮询重查；数据库或网络过载仍沿用有界随机退避

#### Scenario: 并发状态变化
- **WHEN** 只读检查后执行或清理状态发生变化
- **THEN** 领取接口在取得锁后重新核对，不重复启动或错误清理

#### Scenario: 临时故障后持续领取
- **WHEN** 领取请求遇到可重试 HTTP 或网络故障
- **THEN** Worker 持续尝试领取、不设重试次数上限，单次退避总等待不超过 3 秒；请求本身仍受独立的 HTTP 超时约束
