## Purpose

在保留外部 API 地址和端口的前提下，允许执行控制请求使用独立进程的处理线程与数据库预算。

## ADDED Requirements

### Requirement: 可选进程隔离
系统 SHALL 提供显式启用的双 API 进程部署，控制请求与普通请求分别进入专属进程；单进程部署继续可用。

#### Scenario: 混合请求
- **WHEN** Web、日志、领取、Agent 监控与 Worker 心跳同时进入同一外部端口
- **THEN** 控制路径进入控制进程，其余进入普通进程，二者不共用 FastAPI 同步线程池

#### Scenario: 单进程默认
- **WHEN** 只使用基础 Compose 部署
- **THEN** 维持一个 API 进程和原端口，不要求修改 Worker 地址

### Requirement: 控制安全与健康
系统 SHALL 只运行一个调度器，并在控制进程不可用或请求被误路由时明确失败，不把控制请求静默改交普通进程。

#### Scenario: 控制进程不可用
- **WHEN** 控制进程故障而普通进程仍可用
- **THEN** 控制请求返回暂时失败，普通接口可继续服务，网关整体健康不伪称完全正常

#### Scenario: 错误路由
- **WHEN** 请求到达与其分类不符的 API 进程
- **THEN** 请求在鉴权和数据库访问前被拒绝

### Requirement: 统一入口与预算
系统 SHALL 保持外部监听地址和端口、认证及响应语义，并按两个 API 进程的全部数据库池验证连接预算。

#### Scenario: 切换到双进程
- **WHEN** 管理员使用双进程部署覆盖配置
- **THEN** 浏览器和 Worker 仍使用原平台地址，且两进程合计预算不超过配置的数据库连接上限
