# Design

## Current state

`deploy/compose.yml` 只启动一个暴露 `API_BIND_PORT` 的 API。`backend/app/db_budget.py` 将请求分为 ordinary、control、observation、result，入口准入和数据库池独立，但 FastAPI 同步依赖仍共用进程默认线程池。`backend/app/main.py` 默认启动调度线程。原背压设计明确把独立控制 API 进程留给后续变更。

## Deployment

提供显式 Compose overlay，默认 `compose.yml` 不变。Overlay 移除原 API 的宿主机端口映射，新增同镜像 `control-api` 容器和仅网关暴露原 `API_BIND_HOST:API_BIND_PORT`。两个 API 容器均在内部监听 8000；网关按准确路径转发控制 POST，其余流量转发普通 API。网关保留原 Host、客户端来源和转发协议，不在日志中写凭据或正文。网关 `/healthz` 应同时检查两个 API 的存活，控制 API 不健康时控制请求必须失败，不回退到普通进程。

控制 API 使用 `SCHEDULER_ENABLED=0`；普通 API 保持原调度线程。两者启用数据库背压，`API_DB_PROCESS_COUNT=2`；两进程读取相同的五类额度，只创建本角色实际使用的池。普通 API 创建普通、观察、结果、调度池，控制 API 只创建控制池；按五类额度之和校验总连接预算，并保留 PostgreSQL 管理连接余量。单进程仍创建原五类池以兼容现有调用。两个进程虽各有完整路由表，但请求入口根据自身角色拒绝误路由，防止路由规则漂移或内部直接调用损坏隔离。`/healthz` 为无数据库的例外。

混合负载专项发现统一使用单进程默认池 10/5/2/2/1 时，200 Worker 的 Agent 观察上报会变旧。双进程覆盖配置按职责分配默认池，五类额度共为 23/40/9/7/1；普通进程仅创建普通/观察/结果/调度 23/9/7/1，控制进程仅创建控制池 40，各进程最多 40 个连接、合计 80，对齐各自默认 40 个同步线程额度。之前的 26 和 31 连接配置仅作为历史压测证据。新增的类别入口并发闸门默认在此覆盖配置中关闭（`DB_ADMISSION_ENABLED=0`），类别池仅约束同时持有的数据库连接，连接等待仍有超时和可重试 503；双进程模式不再将 AnyIO 线程额度加到超过连接预算。只拆进程、使用旧数据库会话的 100 Worker 短测失败，保留有界连接池但无入口闸门的 100 Worker 短测通过。普通 API 仍可能因日志/产物拥塞影响 Agent 所共享的 CPU 和数据库；该分配只作为后续容量验收的起点，不宣称生产 100/200 Worker 长期稳定。PostgreSQL 当前最多 100 连接且有其他连接来源，启用前必须检查余量；主要池可用 `DB_SPLIT_*_POOL_SIZE` 覆盖，变更后核对两个进程的展开配置和总预算。

网关路径清单须与 Python `request_category` 的控制分类测试对照，覆盖心跳、服务健康/探测、完成/清理、停止许可、取消和服务控制。Agent 观察、回合结果、日志、产物、领取及 Web 留在普通进程。网关和两个 API 使用独立健康检查；普通 API 的 `readyz` 仍表示数据库可用，不代表控制进程健康。外部地址和 Worker 配置不变。

空闲卡位的领取轮询先在认证后只读检查是否存在待领取或待清理执行；若两者都没有，直接返回空结果。存在候选时才尝试非阻塞调度锁，取得锁后复核执行与清理状态。候选刚出现但锁忙时返回空结果，下一轮轮询再试，避免把可预期的调度窗口当作 Worker 执行异常；数据库连接/网络过载仍保留现有 503 与随机退避。领取循环不设重试次数上限，仅将单次退避总等待（包括 `Retry-After`）限制为 3 秒；HTTP 请求本身仍用既有超时。一次只读检查与新分配并发时最多推迟一个轮询周期。锁仍保护真实领取的 `RESERVED -> STARTING` 转换；不改调度器资源分配语义。

## Failure and rollout

网关不可用时外部服务不可用；控制 API 不健康时只拒绝控制请求且 Worker 按既有暂时故障策略重试，绝不由普通 API 代办。普通 API 不健康时 Web、日志等不可用，控制进程仍可续租。数据库整体故障、同一行锁和主机 CPU/磁盘竞争仍共享，进程隔离不保证数据库无限容量。

先在隔离数据库做路由与并发验证，再检查目标 Worker 的背压兼容能力、现有执行和数据库预算；发布使用新 overlay 重建，回退时移除 overlay 并恢复单 API。启停调度器不能在切换窗口双开；运行中任务切换仍需按现有发布流程排空或确保兼容，不能清除节点 journal。
