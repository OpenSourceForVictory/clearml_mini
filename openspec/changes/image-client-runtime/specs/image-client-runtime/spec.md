## Purpose
允许用户携带已有 Python 仿真客户端镜像，通过明确的启动命令、变量和逻辑目录接入评测平台，并在不同宿主机路径之间复用同一集合，保留调度准入、执行隔离、进度和结果追溯。
## ADDED Requirements
### Requirement: 用户镜像客户端
平台 SHALL 允许普通用户注册自己拥有的镜像模板和版本，声明启动命令、非敏感变量及可覆盖项；节点批准和预置镜像后才可执行。
#### Scenario: 提交已有镜像
- **WHEN** 用户登记包含 Python 的镜像和客户端命令
- **THEN** 模板可用于自己的集合，平台适配层传递任务并保留日志/事件/指标协议，不宣称任意镜像零适配
### Requirement: 启动配置快照
平台 SHALL 保存模板默认变量及运行覆盖值，限制覆盖键和保留变量，参数按独立字符串传递，不隐式执行 shell 展开。
#### Scenario: 不同运行覆盖
- **WHEN** 用户为两次运行提供不同的允许变量
- **THEN** 各运行使用独立快照，后续模板和节点变更不改变已有执行
### Requirement: 逻辑目录映射
平台 SHALL 允许管理员为每台机器定义逻辑资产名称对应的宿主目录，用户只指定容器目标；工作和结果目录按执行独立分配，资产只读。
#### Scenario: 双机不同路径
- **WHEN** 同一客户端在两台资产实际路径不同的机器执行
- **THEN** 容器使用同一资产路径，不能访问其他执行工作目录或任意宿主目录
### Requirement: 就绪报告与安全变更
平台 SHALL 基于 Worker 报告的镜像和资产可用性筛选节点，展示缺失原因；版本化修改节点配置需要等待旧执行清理完成，旧协议不能领取新运行配置任务。
#### Scenario: 缺少镜像或资产
- **WHEN** 节点没有所需镜像或可读资产
- **THEN** 新任务保留排队，可查询原因，资源恢复后自动重新参与调度
#### Scenario: 忙碌时切换
- **WHEN** 修改正在运行任务的节点配置
- **THEN** 未领取预留回队列，旧任务与续租恢复继续，新配置在清理完成后确认生效
