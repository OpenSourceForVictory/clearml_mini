# Design

## Context

见 proposal.md 的问题范围。2026-11-23 将先前分散的连接池、锁及重试方案统一为以下端到端设计。本文的目标行为不等于当前已实现能力。

当前监控已经更新最新状态，不是每次新增历史记录；UPDATE 仍消耗连接、行锁和 WAL。日志已有按流合并、序号和 ACK，Agent 已保留最新采样，应复用这些机制。共享存储产物读取已在文件 I/O 前释放 Session，应保持。

现有原型的控制池覆盖心跳及服务健康，但完成、清理仍处于普通流量；Agent 监控也可能挤占续租。两池不能隔离同步处理线程与数据库 CPU。Worker 部分结果、旧日志及产物上报仍位于完成确认之前，持续繁忙可拖住收尾；V2 日志最终排空超时后没有完整终态补传能力。因此“连接池隔离已做”不能代表核心目标完成。

### 现有证据与保留边界

| 原型/证据 | 处置及尚缺验证 |
|---|---|
| 有界连接池、SQL/锁预算、精确 503 分类 | 保留方向；补全生命周期分类、处理预算及调度预算；现有每条 SQL 前两次 SET LOCAL 的额外往返需要优化验证 |
| 运行中续租及执行内上报移除全局锁、超时扫描锁后复核 | 保留方向；仍需统一锁顺序及撤销、清理、配置竞争验收 |
| 短时 FIFO 控制入口队列 | 作为有界突发整形原型；不能代替持续容量，需按新分类验证饥饿与取消释放 |
| Agent 配置/观察分表及迁移 | 未完成；首次专项 3 失败、17 通过，包含旧测试直接修改旧 JSON 的问题；不能据此宣称迁移可发布 |
| Worker 分类重试、宿主机/Docker 短程序故障注入 | 保留有效证据；尚无可靠终态补传，Retry-After 下早期抖动被固定等待吞掉需修正 |
| 100 Worker 短压测 | 缩锁后 30 秒档最大续租间隔 4.11 秒，通过当时小场景；不是持续生产容量 |
| 200 Worker 短压测 | 缩锁 23.27 秒、FIFO 18.61 秒、同总连接数重分配后 60 秒档 17.62 秒，均未达最大间隔小于 10 秒的目标 |
| 全量测试 | 中断时 2 失败、861 通过、87 跳过；相关修正后专项 110 通过，尚无新全量通过及覆盖率达标结论 |

证据位置：`docs/validation/control-plane-backpressure-20261123/`；后续队列与分表试验原始记录在 `.runtime/backpressure-control-queue-load/`、`.runtime/backpressure-control-priority-load/`、`.runtime/agent-split-first.log`，发布前提取去敏后的可追踪报告。旧压测未启用真实调度、Agent、Web 和业务，并未按真实 Retry-After 重试；只能用于瓶颈定位，不作为最终容量验收。宿主机/Docker 短程序并非真实模型评测。

## Goals / Non-Goals

**Goals:** 在经验证的负载范围和数据库可工作的条件下，日志/产物拥塞不造成续租丢失、服务就绪失真或资源释放被拖住。所有类别有容量、等待、重试及可观测边界；可靠数据能够恢复交付。

**Non-Goals:** 不消除数据库必要行锁，不无限增大连接池，不将所有写入异步化，不更改批次优先级或业务结果判定，不绕过租约看门狗，不在首版引入独立消息服务。数据库完全不可用时必须继续遵守停止执行的安全规则。

## Decisions

### 1. 按语义分类，并保护完整生命周期

| 通道 | 内容 | 交付与预算 |
|---|---|---|
| 执行控制 | 权威续租、启动状态、服务就绪/失效、取消、完成摘要、停止及清理确认 | 独立入口/处理/数据库预留；有界短等待，关键确认提交后 ACK；不得被大正文占用 |
| 调度与最新状态 | 调度周期、领取、Agent 最新监控、配置应用回执 | 调度保留处理与连接预算；领取限频；采样按节点/会话合并；监控不能借用执行控制预留 |
| 可靠业务数据 | 回合协议结果、任务结果等 | 持久化后可重试、幂等 ACK；有界独立并发，不能丢弃或被日志大包阻塞 |
| 批量数据及交互 | 日志、产物注册/上传、历史读取及 Web | 有界普通预算与分页/大小限制；可排队、可恢复，不能借用上述预留 |

完成摘要只含受限的执行身份、退出状态、协议结果清单摘要、停止/清理状态，不携带日志或产物正文。服务健康连续样本可合并，但就绪/失效状态转换按会话及序号确认，失效后不能被旧就绪报告覆盖。取消指令通过控制响应及时送达。

选择语义隔离而非只按 URL 分两池：同为 Worker 请求，日志与续租的时效要求不同；同为监控，设备可用状态与历史采样也不同。路由分类由服务端决定，鉴权使用同类预算，不信任客户端优先级标记。

### 2. 全链路预算，而非仅增加连接

入口在鉴权、同步处理线程和借连接之前取得有界许可；执行控制有专用处理容量，其余通道不能耗尽它。调度后台同样保留预算。队列等待者有上限、截止与取消回收，不占数据库连接；等待时间计入总请求预算。HTTP 同步处理不得依赖一个可被普通请求占满的无隔离线程池。

数据库预算按所有 API 进程、后台调度及其他连接使用者求和，低于 PostgreSQL 可用连接数并保留管理余量。池无无限 overflow；连接、锁和语句均有截止，持锁区间不能进行文件 I/O、网络调用或大对象解码。诊断区分入口拒绝、线程等待、池等待、锁等待、语句慢、数据库不可用。

SQL 超时仅控制数据库部分，不能宣称覆盖 Python CPU 和所有 I/O。减少预算设置的重复往返时必须保留累计截止保护。短队列吸收突发；持续超载明确返回可重试响应，不通过不断加长等待掩盖饥饿。

首版保留现有部署形态；若共享进程 CPU 下专用处理容量仍不能满足混合验收，必须暂停容量声明并以独立控制 API 进程隔离作为后续设计变更，不悄悄扩大本次依赖。

### 3. 权威状态、最新采样与可靠事件分开处理

权威租约提交成功才返回续租 ACK；请求已入队不是续租成功。监控以服务端接收时间判断新鲜度，携带设备采样时间用于诊断，不用不可信节点时钟延长租约。采样可覆盖旧样本，但身份、会话、序号、配置版本和需要确认的事件不能随合并丢失。

Agent 期望配置留在 Worker，最新观察进入每节点一行的独立记录。注册切换会话；观察更新只接受当前会话，旧会话或旧序号不能复活旧数据。统一读取合并时避免 N+1 查询。必须审查 Slot 的遥测、执行心跳、配置写入：Agent 分表不等于所有同机竞争已解除；必要时继续分离高频观察字段，保持原子会话校验。

锁规则以操作列明并测试，不再笼统要求每个请求获取全局锁：

| 操作 | 原子边界 |
|---|---|
| 预约、领取、启动资源转换、完成/清理释放 | 调度资源保护及涉及记录的稳定顺序；禁止先拿执行锁再逆向获取全局锁 |
| 已运行执行续租、结果及日志幂等更新 | 执行局部行锁/CAS，必要设备行按固定顺序；不获取全局调度锁 |
| 超时扫描 | 仅锁疑似到期执行，跳过忙记录；刷新租约、取消与终态后再决定，资源释放沿统一资源路径 |
| 配置与注册 | 配置锁保护期望状态；注册按 Worker→观察记录顺序切换身份，普通采样不反向取配置锁 |

跨路径具体记录顺序须在实现审计中列出，使用真实 PostgreSQL 验证，不凭移除锁后的吞吐宣称一致性。配置撤销与上报竞态必须有明确先后提交结果。

### 4. 执行结束不等待日志，可靠数据继续同步

分离三个维度：程序执行状态、平台协议结果、数据同步状态。程序退出码为 0 可说明程序正常退出，不代表缺失的协议结果成功。协议结果未齐时保持待同步；超出同步期限明确标为结果不完整，不伪造成功。

业务进程停止后，Worker 优先交付控制完成摘要和清理确认。平台核对身份及停止证据后按照原有资源释放条件回收资源，不等待日志和产物。清理尚未确认时仍保留相应资源保护，不能为了降载提前复用卡。完成请求丢失响应时用原执行身份重放，不产生新执行。

采用节点侧持久化、有界 outbox，复用已有日志文件/journal/游标；由 Worker 管理交付，不要求业务账号访问 Worker 私有账本。记录不可变执行 ID、所属节点/会话、流/序号、内容摘要、截止及 ACK 状态。重启恢复同一队列，成功 ACK 后才推进；每执行及整机都有字节、条数、保留期限制。可靠结果预留空间，不与大日志共享最后可用容量；可靠结果无法持久化必须明确报告交付失败，不能当作已接收。日志达限按明确截断策略标记缺口；磁盘满不得无限重试或影响续租线程。

补传接口只允许原执行授权范围内的数据，校验重放摘要及序号；终态补传不续租、不改资源占用、不恢复运行态。删除批次/任务后拒绝补传并清理 outbox，不能复活数据。每执行补传权限有期限，可撤销，重纳管旧身份不能自动获得补传权限。旧 API 不支持此能力时走既有协议；不得向旧 API 发送新的终态语义。

界面执行状态与“数据同步中/同步失败/日志截断”分别显示；可靠协议结果完整性单独展示。未完成本节前，不宣称日志与产物拥塞不会拖住收尾。此 outbox 不替代此前独立日志的业务侧配额通道设计，本变更只管理 Worker 已接管的待交付数据。

### 5. Worker 调度上报与重试

续租/取消处理独立于批量交付，服务状态和完成/清理不会排在日志后。每类有有界并发和单一交付所有者，避免多线程重复发送同一序号；大文件采用受限分片或既有有界路径。

429/502/503/504 及暂时网络故障采用有界随机退避；Retry-After 是最早重试时间，在其后仍保留抖动，不能所有节点固定一秒同时重试。若提示等待超过租约剩余时间，不提前忽略服务端要求重试，也不延长租约；看门狗仍在原截止停止业务。取消可中断等待。永久鉴权、执行失效及协议错误按各接口语义终止，不做无限繁忙重试。终态补传使用自身截止，不借用活动租约。

### 6. 验收采用真实混合链路

先验证正确性，再测容量。基线与候选档记录节点数、每节点卡数、设备 Worker 数、执行数、上报周期、正文大小、Web 并发、API/DB 硬件及进程/连接预算；不把连接数当作并发 Worker 上限。

最终基线目标为 100 个模拟设备 Worker 持续至少 30 分钟；200 为候选档，失败即保留结果并停止继续加压，不改变阈值。启用实际调度、Agent、领取、服务就绪、完成/清理、日志/产物及 Web，加入多卡同节点与重连突发。模拟器使用真实 Retry-After/退避规则。额外用真实宿主机/Docker 短程序确认停止、补传和资源复用，GPU/NPU 验证执行链路而不冒充模型评测。

验收必须包含：

- 仅批量通道饱和时，无续租丢失和误超时；最大续租间隔小于 10 秒且小于测试租约安全余量，调度所需采样在配置新鲜度内。
- 逐类别记录成功请求 P95/P99、拒绝次数、最大等待和队列年龄；不能用大量快速 503 拉低整体 P99。控制成功响应 P99 小于 5 秒；统计服务就绪、调度周期及资源释放延迟相对空载基线的变化。
- 已停止且满足清理条件的执行，在批量通道持续堵塞时仍能控制确认并释放资源；以两个调度周期加控制请求预算为测试上界，具体配置随报告保存。
- 暂时故障后可靠结果不丢失/不重复；日志缺口显式；outbox 有界且恢复排空，批量通道不被永久饿死。
- 行锁/慢 SQL、池耗尽、线程饱和、网络断开、响应丢失、Worker/API 重启、磁盘满、撤销/重纳管、删除与补传并发均有失败路径测试。数据库持续不可用仍按租约停止，不能用宽限无限续命。

容量结论限于已测硬件、配置和负载；完整覆盖率使用统一脚本，目录 80%/70%、关键功能 90%/80%，未插桩前端及未合并子进程不计入覆盖率。

## Risks / Trade-offs

- 预留过多导致空闲容量浪费 → 先用小且明确的预算验收，按指标调整，不允许普通流量无限借用关键预留。
- 同一执行的大量数据仍可能竞争续租行锁 → 限制批次和持锁时间，必要时分离交付游标行；测试同执行竞争，不只测不同执行。
- 终态补传扩大权限与保留范围 → 固定执行身份、限定数据类型/大小/期限、撤销与删除拒绝、不可重开生命周期。
- 结果同步与资源释放分离增加状态复杂度 → 控制摘要、协议结果和同步状态分别测试展示，退出码不能覆盖协议失败。
- 分表迁移及旧 Worker 过载行为不同 → 能力协商、暂停旧 API 写入迁移、灰度开关和回滚演练。

## Migration Plan

按可验收的纵向阶段实施，阶段完成不等于整体功能完成：

1. 先统一通道、预算、锁/事务、重试及观测；证明控制路径与普通流量隔离。此阶段不承诺完成后补传。
2. 完成观察状态迁移及所有读写路径、真实并发验证；停止旧 API 写入，回填后升级，不混跑新旧 API。降级须合并当前会话的最新观察状态，保留期望配置。
3. 实现 outbox、终态补传、结果完整性和界面同步状态，完成新旧能力协商；此阶段结束才具备完整的日志/产物不阻塞收尾能力。交付状态若需新增数据库字段，同阶段提供迁移与回滚测试，不能只迁观察表就宣称整体 schema 完成。
4. 混合容量、故障及统一覆盖率验收，更新操作指南和 Skill，再部署灰度。先验证新 Worker 对旧 API 兼容，再升级目标节点，最后启用服务端背压及新补传能力；不热替换在途任务代码或清除 journal。

回滚先关闭新入口策略，停止新能力任务；保留 outbox/日志与恢复记录，排空或导出未确认数据，再按已验证步骤回滚 API/schema。未排空新补传数据时禁止直接降级到不理解其状态的 API。当前原型尚未完成上述阶段，不部署、不标记可发布。
