# Design

## Context

见 proposal.md 的问题范围。2026-11-23 将先前分散的连接池、锁及重试方案统一为以下端到端设计。本文的目标行为不等于当前已实现能力。2026-11-25 按用户确认补充有限断联容忍与不限制选项；下文原型证据保留其历史范围，四角色 API 隔离的最新部署与测试证据见 ../priority-api-isolation/，不代表断联恢复已实施。

当前监控已经更新最新状态，不是每次新增历史记录；UPDATE 仍消耗连接、行锁和 WAL。日志已有按流合并、序号和 ACK，Agent 已保留最新采样，应复用这些机制。共享存储产物读取已在文件 I/O 前释放 Session，应保持。

现有原型的控制池覆盖心跳及服务健康，但完成、清理仍处于普通流量；Agent 监控也可能挤占续租。两池不能隔离同步处理线程与数据库 CPU。Worker 部分结果、旧日志及产物上报仍位于完成确认之前，持续繁忙可拖住收尾；V2 日志最终排空超时后没有完整终态补传能力。因此“连接池隔离已做”不能代表核心目标完成。

### 现有证据与保留边界

| 原型/证据 | 处置及尚缺验证 |
|---|---|
| 有界连接池、SQL/锁预算、精确 503 分类 | 保留方向；补全生命周期分类、处理预算及调度预算；现有每条 SQL 前两次 SET LOCAL 的额外往返需要优化验证 |
| 运行中续租及执行内上报移除全局锁、超时扫描锁后复核 | 保留方向；仍需统一锁顺序及撤销、清理、配置竞争验收 |
| 短时 FIFO 控制入口队列 | 作为有界突发整形原型；不能代替持续容量，需按新分类验证饥饿与取消释放 |
| Agent 配置/观察分表及迁移 | 未完成；首次专项 3 失败、17 通过，包含旧测试直接修改旧 JSON 的问题；不能据此宣称迁移可发布 |
| Worker 分类重试、宿主机/Docker 短程序故障注入 | 保留有效证据；尚无可靠终态补传，Retry-After 下早期抖动被固定等待吞掉需修正 |
| 100 Worker 短压测 | 缩锁后 30 秒档最大续租间隔 4.11 秒，通过当时小场景；不是持续生产容量 |
| 200 Worker 短压测 | 缩锁 23.27 秒、FIFO 18.61 秒、同总连接数重分配后 60 秒档 17.62 秒，均未达最大间隔小于 10 秒的目标 |
| 全量测试 | 中断时 2 失败、861 通过、87 跳过；相关修正后专项 110 通过，尚无新全量通过及覆盖率达标结论 |

证据位置：`docs/validation/control-plane-backpressure-20261123/`；后续队列与分表试验原始记录在 `.runtime/backpressure-control-queue-load/`、`.runtime/backpressure-control-priority-load/`、`.runtime/agent-split-first.log`，发布前提取去敏后的可追踪报告。旧压测未启用真实调度、Agent、Web 和业务，并未按真实 Retry-After 重试；只能用于瓶颈定位，不作为最终容量验收。宿主机/Docker 短程序并非真实模型评测。

## Goals / Non-Goals

**Goals:** 在经验证的负载范围和数据库可工作的条件下，日志/产物拥塞不造成续租丢失、服务就绪失真或资源释放被拖住。所有类别有容量、等待、重试及可观测边界；可靠数据能够恢复交付。

**Non-Goals:** 不消除数据库必要行锁，不无限增大连接池，不将所有写入异步化，不更改批次优先级或业务结果判定，不取消用户配置的业务执行时限或明确停止指令，不在首版引入独立消息服务。数据库完全不可用时已领取任务仍可执行；平台不能因此释放不确定的资源。

## Decisions

### 1. 按语义分类，并保护完整生命周期

| 通道 | 内容 | 交付与预算 |
|---|---|---|
| 执行控制 | 权威续租、启动状态、服务就绪/失效、取消、完成摘要、停止及清理确认 | 独立入口/处理/数据库预留；有界短等待，关键确认提交后 ACK；不得被大正文占用 |
| 调度与最新状态 | 调度周期、领取、Agent 最新监控、配置应用回执 | 调度保留处理与连接预算；领取限频；采样按节点/会话合并；监控不能借用执行控制预留 |
| 可靠业务数据 | 回合协议结果、任务结果等 | 持久化后可重试、幂等 ACK；有界独立并发，不能丢弃或被日志大包阻塞 |
| 批量数据及交互 | 日志、产物注册/上传、历史读取及 Web | 有界普通预算与分页/大小限制；可排队、可恢复，不能借用上述预留 |

完成摘要只含受限的执行身份、退出状态、协议结果清单摘要、停止/清理状态，不携带日志或产物正文。服务健康连续样本可合并，但就绪/失效状态转换按会话及序号确认，失效后不能被旧就绪报告覆盖。取消指令通过控制响应及时送达。

选择语义隔离而非只按 URL 分两池：同为 Worker 请求，日志与续租的时效要求不同；同为监控，设备可用状态与历史采样也不同。路由分类由服务端决定，鉴权使用同类预算，不信任客户端优先级标记。

### 2. 全链路预算，而非仅增加连接

入口在鉴权、同步处理线程和借连接之前取得有界许可；执行控制有专用处理容量，其余通道不能耗尽它。调度后台同样保留预算。队列等待者有上限、截止与取消回收，不占数据库连接；等待时间计入总请求预算。HTTP 同步处理不得依赖一个可被普通请求占满的无隔离线程池。

数据库预算按所有 API 进程、后台调度及其他连接使用者求和，低于 PostgreSQL 可用连接数并保留管理余量。池无无限 overflow；连接、锁和语句均有截止，持锁区间不能进行文件 I/O、网络调用或大对象解码。诊断区分入口拒绝、线程等待、池等待、锁等待、语句慢、数据库不可用。

SQL 超时仅控制数据库部分，不能宣称覆盖 Python CPU 和所有 I/O。减少预算设置的重复往返时必须保留累计截止保护。短队列吸收突发；持续超载明确返回可重试响应，不通过不断加长等待掩盖饥饿。

请求角色隔离沿用已部署的 priority-api-isolation 四角色设计；恢复对账和停止确认归执行控制，可靠结果归 Worker 数据，日志产物归批量通道。新增接口必须同步路由清单及兼容部署测试，不能绕过已建立的隔离预算。

### 3. 权威状态、最新采样与可靠事件分开处理

权威租约提交成功才返回续租 ACK；请求已入队不是续租成功。监控以服务端接收时间判断新鲜度，携带设备采样时间用于诊断，不用不可信节点时钟延长租约。采样可覆盖旧样本，但身份、会话、序号、配置版本和需要确认的事件不能随合并丢失。

Agent 期望配置留在 Worker，最新观察进入每节点一行的独立记录。注册切换会话；观察更新只接受当前会话，旧会话或旧序号不能复活旧数据。统一读取合并时避免 N+1 查询。必须审查 Slot 的遥测、执行心跳、配置写入：Agent 分表不等于所有同机竞争已解除；必要时继续分离高频观察字段，保持原子会话校验。

锁规则以操作列明并测试，不再笼统要求每个请求获取全局锁：

| 操作 | 原子边界 |
|---|---|
| 预约、领取、启动资源转换、完成/清理释放 | 调度资源保护及涉及记录的稳定顺序；禁止先拿执行锁再逆向获取全局锁 |
| 已运行执行续租、结果及日志幂等更新 | 续租取 Run NO KEY UPDATE 与必要设备行；v2 日志取 Run KEY SHARE、日志状态行锁，并以执行专属事务锁与完成/清理排序；旧日志仍修改 Run.log_bytes，需单独兼容；不获取全局调度锁 |
| 超时扫描 | 仅锁疑似到期执行，跳过忙记录；刷新租约、取消与终态后再决定，资源释放沿统一资源路径 |
| 配置与注册 | 配置锁保护期望状态；注册按 Worker→观察记录顺序切换身份，普通采样不反向取配置锁 |

跨路径具体记录顺序须在实现审计中列出，使用真实 PostgreSQL 验证，不凭移除锁后的吞吐宣称一致性。配置撤销与上报竞态必须有明确先后提交结果。

### 4. 执行结束不等待日志，可靠数据继续同步

分离三个维度：程序执行状态、平台协议结果、数据同步状态。程序退出码为 0 可说明程序正常退出，不代表缺失的协议结果成功。协议结果未齐时保持待同步；超过同步告警阈值标记延迟，不因断联时长删除未确认结果或直接判失败，不伪造成功。

业务进程停止后，Worker 优先交付控制完成摘要和清理确认。平台核对身份及停止证据后按照原有资源释放条件回收资源，不等待日志和产物。清理尚未确认时仍保留相应资源保护，不能为了降载提前复用卡。完成请求丢失响应时用原执行身份重放，不产生新执行。

采用节点侧持久化、有界 outbox，复用已有日志文件/journal/游标；由 Worker 管理交付，不要求业务账号访问 Worker 私有账本。记录不可变执行 ID、所属节点/会话、流/序号、内容摘要、截止及 ACK 状态。重启恢复同一队列，成功 ACK 后才推进；每执行及整机有字节、条数限制；已确认数据按保留期清理，未确认执行状态和可靠结果不因断联时长自动删除。可靠结果预留空间，不与大日志共享最后可用容量；可靠结果无法持久化必须明确报告交付失败，不能当作已接收。日志达限按明确截断策略标记缺口；磁盘满不得无限重试或影响续租线程。

补传接口只允许原执行授权范围内的数据，校验重放摘要及序号；终态补传不续租、不改资源占用、不恢复运行态。删除批次/任务先隐藏业务记录并保留取消意图、执行归属和资源记录；安全停止/清理上报仍接受，业务数据补传按删除标记拒绝。收到明确丢弃确认后才清理对应 outbox，不能复活用户已删除的数据，也不能遗失尚未停止的进程。补传凭据可到期及撤销，但普通凭据到期后允许原授权主体重新认证并核对执行归属后补传，不因离线过久拒绝合法未确认结果；重纳管旧身份不能自动获得补传权限。旧 API 不支持此能力时走既有协议；不得向旧 API 发送新的终态语义。

界面执行状态与“数据同步中/同步失败/日志截断”分别显示；可靠协议结果完整性单独展示。未完成本节前，不宣称日志与产物拥塞不会拖住收尾。此 outbox 不替代此前独立日志的业务侧配额通道设计，本变更只管理 Worker 已接管的待交付数据。

### 5. Worker 调度上报与重试

续租/取消处理独立于批量交付，服务状态和完成/清理不会排在日志后。每类有有界并发和单一交付所有者，避免多线程重复发送同一序号；大文件采用受限分片或既有有界路径。

429/502/503/504 及暂时网络故障采用有界随机退避；Retry-After 是最早重试时间，在其后仍保留抖动，不能所有节点固定一秒同时重试。若提示等待超过心跳新鲜度阈值，不提前忽略服务端要求重试，也不伪造续租；已领取任务进入离线执行流程，不因旧心跳截止被看门狗停止；有限断联容忍截止和业务时限仍由本地监督执行。取消可中断等待。永久鉴权、执行失效及协议错误按各接口语义终止，不做无限繁忙重试。每次网络尝试有超时，重试间隔有上限；未确认状态和结果的重试生命周期不以断联时长为截止。

### 6. 断联继续执行与重连对账（用户确认）

心跳新鲜度、断联容忍时间与业务执行时限分离。已确认领取并持久保存的执行归属不会仅因心跳过期失效。用户可选择有限断联容忍时长或不限制：容忍期内（或不限制时）Worker 继续已领取任务的既定回合，不领取新任务、不自行创建新执行；有限容忍超限后停止业务及后续回合，持久保存停止原因、真实退出状态和已有结果。业务总时限、启动就绪时限、程序失败策略、本地停止和已收到的明确取消仍独立生效；断联不能保证远程取消即时到达。

配置及计时契约：

- 新任务向导默认选择不限制，也可配置有限时长；服务端校验有限值为正整数秒。执行快照中的 `disconnect_tolerance_seconds` 使用正整数表示有限时长、显式 null 表示不限制；字段缺失代表旧协议，不能被当作不限制。原批次重建时回显原配置，不给历史执行追溯启用新策略。
- 领取时下发策略及版本，Worker 在启动前持久保存；客户端与服务实例均带各自执行快照，任务运行中不单边热改。未协商恢复能力时不得静默接受新策略，须提示升级。
- 计时从最近一次有效执行控制确认所对应的请求发出时刻算起，初始领取确认建立起点。只接受匹配执行 ID、分配代次、请求序号的确认；日志/产物成功、Agent 在线或其他执行心跳不能刷新计时。超过本地容忍截止才到达的响应不得撤销已作出的停止决定。
- 同一机器启动期间使用单调时钟，持久保存起点及 boot ID，Worker 重启不能重置容忍时间。机器启动身份变化按原进程中断对账，不能拼接不同启动的单调时间。有效重连对账后可重新建立在线起点，未完成对账前不得凭普通 HTTP 成功刷新。
- 业务时限与有限断联截止先到者触发停止，记录明确原因，不能混写为 lease or execution deadline expired。请求超时、重试及日志排空不能阻塞本地停止监督；监督者故障后的接管仍须核验进程身份。
- 超限后平台显示“断联超限、停止待确认”，这是对停止意图/预期的描述，不证明节点已停止。停止失败保留待确认与资源，重试清理；只有确认停止和清理或完成可信隔离才能释放。已停止执行绝不因恢复连接重新启动。
- 容忍时长只限制离线业务继续执行，不是结果补传有效期。即使超限很久，合法原执行仍可补报退出、回合结果和清理；同序号同摘要幂等，同序号异摘要冲突，旧执行不得覆盖新执行。

平台显示“连接异常、执行待确认”，保持执行 ID、资源预约及服务实例归属，不因心跳过期标记业务超时、不自动重派或释放卡。失联服务不向新客户端分配，已有任务与服务仍按原关联继续；持续服务按原生命周期等待关联任务结束或明确停止，在有限断联容忍超限前不因断联擅自销毁；超限须执行原服务快照中的停止策略。节点长期失联意味着相关资源长期保留；需要人工回收时先验证停止或完成节点隔离，建立旧执行不可继续使用资源的隔离边界后才重派。

重连先对账再领取：Worker 提交原执行 ID、分配代次、进程身份/退出码、回合进度与待上传序号，平台核对未撤销的原归属。仍运行的恢复在线跟踪，已完成的接收结果和清理确认，不重启程序；旧回合重放幂等。Worker 重启先从持久记录恢复并验证进程身份，不能仅凭 PID 或 unit 名盲目重启。显式撤销或隔离后的旧执行进入冲突处理，不覆盖新执行。

已过期的普通心跳接口不能继续作为唯一恢复入口，需要独立恢复对账协议。仅两端协商支持时对新执行启用此策略；旧版本保持旧行为且界面明确提示。在途执行策略不可单边切换。未确认结果持续保留并有界速率重试，日志容量仍可显式截断；这不意味着无限磁盘容量。

### 7. 生命周期与恢复协议细化

首版仅保证容忍期内或不限制模式下平台断联不会主动打断已领取业务，不保证机器故障或业务自身错误后仍能完成；不自动迁移或重跑。连接状态（在线/失联/恢复核对中）、程序状态、资源清理状态、结果同步状态独立记录；取消和删除是控制意图，不直接充当进程已经停止的证据。

| 事件 | Worker 行为 | 平台行为/资源边界 |
|---|---|---|
| 分配提交，领取响应丢失 | 用稳定领取请求标识查询原分配，不另启执行 | 保留原执行和分配代次，重试返回同一分配；不能按未领取预约超时释放已提交领取 |
| 已收到分配、尚未启动 | 先原子持久化任务快照和归属，再启动 | 已领取即持有资源；恢复核对可确认未启动，但不得在原授权仍有效时自行重派 |
| 心跳超期但容忍期未到，或不限制 | 已领取任务继续既定回合，状态写本地 | 标记失联，保持原程序状态与资源，不宣称仍运行或已经失败 |
| 有限断联容忍超限 | 停止程序及后续回合，持久保存退出、停止原因与未确认结果 | 标记超限待确认，不凭计时自动释放资源；恢复后接受原执行补报 |
| 程序退出 | 先持久保存退出及结果摘要，优先报告停止/清理 | 安全清理确认后释放资源，协议结果未齐仍待同步 |
| Worker 进程重启 | 核对 boot ID、进程启动身份、unit/container 身份后接管 | 不创建新执行；身份不明则保持待确认 |
| 机器重启/进程消失 | 有持久退出记录则补报；否则报告中断和现存证据，不自动重跑 | 不猜测退出码或成功，核对该执行不存在及清理后释放资源 |
| 取消/删除 | 收到指令则停止并确认；断联期间可能继续运行 | 取消待确认；删除先隐藏，安全记录保留至确认或人工隔离 |

领取请求提交与响应必须可幂等恢复；本地落盘失败不能启动。启动意图、进程身份、退出记录分别持久化，处理“进程启动了但身份记录尚未落盘”的崩溃窗口，优先查询实际运行实体，不能靠 journal 单个 created 布尔值认定可重启。同执行仅一个本地监督者，使用本地互斥及稳定启动标识；代次用于识别旧授权，不能代替真正停止/隔离旧进程。

恢复协议先认证、核对执行 ID/节点/分配代次及当前控制版本，返回恢复运行、确认已完成、执行停止或需要人工核对之一。每次对账和控制确认都幂等；服务端在事务中序列化取消、删除、隔离与完成的竞争。普通凭据到期走重新认证，不能把暂时认证不可达当作用户撤销；明确撤销不接受旧授权恢复运行。

恢复对账后先处理已经提交的停止意图，再确认实际进程和资源，再补传可靠结果及日志；不以日志排空作为资源复用条件。取消与完成交错时，已提交终态保持不变，较早提交的取消意图优先决定平台生命周期结果，同时保留真实退出码及协议结果；审计保留双方事件，不能用节点不可靠墙钟决定先后。平台已知真实退出且清理完成的任务可释放资源，即使结果尚在补传。

业务时限在节点本地监督执行，起点随原执行持久保存；Worker 重启或重连不重置。运行期间使用单调计时；机器启动身份变化时按中断核对，不拿新机器的单调时钟续算旧进程。服务启动的本地就绪超时仍有效，但平台未收到启动上报不能单凭旧 STARTUP_TIMEOUT 将离线执行终结。

客户端与服务端按已确认关联继续工作。控制平台失联不等于客户端与服务端网络中断；业务连接真的失败仍按原业务失败策略处理。服务停止需所有关联执行已确认结束/解除关联，或收到明确停止指令、服务自身业务时限或有限断联容忍到期；某客户端失联不等于它结束。已完成客户端解除关联的消息可补报，服务端在平台恢复后接收停止决定。失联服务不承接新客户端，重连后重新验证就绪再提供新绑定。

未确认可靠数据的持久保存要求受物理存储可用性约束：领取前检查余量并为最小终态记录预留空间，可靠结果有单条上限；空间不足优先停止日志增长并告警，不阻塞业务 stdout 导致程序挂死。不能写入可靠结果时明确记录交付异常并保留原始文件，不声称已接收；磁盘完全损坏无法保证结果不丢。已确认数据按保留期清理，不因离线过久清除未确认结果。

### 8. 恢复故障测试矩阵

所有场景覆盖宿主机/Docker、单进程/逐回合、普通命令/直接协议/SDK；公共逻辑可参数化，真实进程验证不得只用 mock。多卡同机至少覆盖两个同名服务实例和两个客户端执行，确认身份不串用。

| 场景 | 必须观察的结果 |
|---|---|
| 领取事务提交后断开、重复领取、持久化失败 | 同一分配代次，只启动一次；持久化失败不启动 |
| 启动前、运行中、两回合之间断联，超过旧租约和告警阈值 | 容忍期内或不限制时继续，有限超限后停止；均无自动重派 |
| 有限值、null、字段缺失、非法值、历史导入及混合版本 | 有限与不限制语义明确，旧协议不被误启用；界面回显一致 |
| 截止边界、迟到/乱序 ACK、仅日志成功、Worker 重启和墙钟跳变 | 不误续期，不因重启延长，不恢复已停止程序 |
| 超限停止失败及长期离线后补传 | 资源继续保留，确认后才释放；已有结果仍可幂等接受 |
| 完成请求/清理请求 ACK 丢失、结果乱序和重复 | 终态与清理幂等，资源不重复释放，结果不重复计数 |
| 恢复时进程存活、正常退出、退出记录缺失 | 分别接管、补报完成、记录中断待核对；不盲目重启 |
| Worker 重启、节点重启、PID 复用、两个监督者 | 身份核验，无重复进程；执行时限不被重置 |
| 取消/删除与完成竞态，撤销/隔离后旧执行回来 | 控制版本与终态规则一致，安全上报仍可完成，不复活已删数据 |
| 仅一侧客户端/服务端失联、服务尚在使用 | 不误停服务，不新增失联服务绑定，恢复后重验就绪 |
| 日志爆量、磁盘不足、补传被拒、结果过大 | 日志显式截断，可靠结果异常可见，控制和业务 stdout 不被卡住 |
| 大规模同时重连、旧 API/Worker、升级/降级 | 对账限流且预留控制容量；原执行策略不单边切换，拒绝不安全降级 |

### 9. 验收采用真实混合链路

先验证正确性，再测容量。基线与候选档记录节点数、每节点卡数、设备 Worker 数、执行数、上报周期、正文大小、Web 并发、API/DB 硬件及进程/连接预算；不把连接数当作并发 Worker 上限。

最终基线目标为 100 个模拟设备 Worker 持续至少 30 分钟；200 为候选档，失败即保留结果并停止继续加压，不改变阈值。启用实际调度、Agent、领取、服务就绪、完成/清理、日志/产物及 Web，加入多卡同节点与重连突发。模拟器使用真实 Retry-After/退避规则。额外用真实宿主机/Docker 短程序确认停止、补传和资源复用，GPU/NPU 验证执行链路而不冒充模型评测。

验收必须包含：

- 仅批量通道饱和时，无续租丢失和误超时；最大续租间隔小于 10 秒且小于测试租约安全余量，调度所需采样在配置新鲜度内。
- 逐类别记录成功请求 P95/P99、拒绝次数、最大等待和队列年龄；不能用大量快速 503 拉低整体 P99。控制成功响应 P99 小于 5 秒；统计服务就绪、调度周期及资源释放延迟相对空载基线的变化。
- 已停止且满足清理条件的执行，在批量通道持续堵塞时仍能控制确认并释放资源；以两个调度周期加控制请求预算为测试上界，具体配置随报告保存。
- 暂时故障后可靠结果不丢失/不重复；日志缺口显式；outbox 有界且恢复排空，批量通道不被永久饿死。
- 行锁/慢 SQL、池耗尽、线程饱和、网络断开、响应丢失、Worker/API 重启、磁盘满、撤销/重纳管、删除与补传并发均有失败路径测试。数据库持续不可用超过旧租约和断联告警阈值时，不限制模式下已领取任务仍能执行完，有限模式下超限停止；两种模式资源均不重派，恢复后幂等对账并接受迟到结果。另测真实业务时限、取消和人工隔离仍能生效。

容量结论限于已测硬件、配置和负载；完整覆盖率使用统一脚本，目录 80%/70%、关键功能 90%/80%，未插桩前端及未合并子进程不计入覆盖率。

## Risks / Trade-offs

- 预留过多导致空闲容量浪费 → 先用小且明确的预算验收，按指标调整，不允许普通流量无限借用关键预留。
- 同一执行的大量数据仍可能竞争续租行锁 → 限制批次和持锁时间，必要时分离交付游标行；测试同执行竞争，不只测不同执行。
- 终态补传扩大权限与保留范围 → 固定执行身份、限定数据类型/大小、凭据重新认证、撤销与删除拒绝、不可重开生命周期。
- 结果同步与资源释放分离增加状态复杂度 → 控制摘要、协议结果和同步状态分别测试展示，退出码不能覆盖协议失败。
- 分表迁移及旧 Worker 过载行为不同 → 能力协商、暂停旧 API 写入迁移、灰度开关和回滚演练。

## Migration Plan

按可验收的纵向阶段实施，阶段完成不等于整体功能完成：

1. 先统一通道、预算、锁/事务、重试及观测；证明控制路径与普通流量隔离。此阶段不承诺完成后补传。
2. 完成观察状态迁移及所有读写路径、真实并发验证；停止旧 API 写入，回填后升级，不混跑新旧 API。降级须合并当前会话的最新观察状态，保留期望配置。
3. 实现断联继续执行、恢复对账、outbox、终态补传、结果完整性和界面同步状态，完成新旧能力协商；此阶段结束才具备完整的日志/产物不阻塞收尾能力。交付状态若需新增数据库字段，同阶段提供迁移与回滚测试，不能只迁观察表就宣称整体 schema 完成。
4. 混合容量、故障及统一覆盖率验收，更新操作指南和 Skill，再部署灰度。先验证新 Worker 对旧 API 兼容，再升级目标节点，最后启用服务端背压及新补传能力；不热替换在途任务代码或清除 journal。

回滚先关闭新入口策略，停止新能力任务；保留 outbox/日志与恢复记录，排空或导出未确认数据，再按已验证步骤回滚 API/schema。未排空新补传数据时禁止直接降级到不理解其状态的 API。存在离线执行时禁止降级为会自动回收过期租约的旧调度逻辑；须先完成对账或确认停止隔离。断联恢复及补传尚未完成上述阶段，不部署这一能力、不标记可发布；已完成的四角色隔离按其独立验收记录管理。

### 2026-11-25 控制权与超限补报场景补充

平台数据库中已提交、生效的任务生命周期与用户控制意图为权威；Worker 上报的是进程执行事实，不能修改平台已经生效的取消、业务执行超时或终态。已接受的取消先于后续完成对账生效；已完成事务不能被随后未获接受的取消重新打开。平台判定业务执行超时后，迟到的退出码 0 仍可保存，但不得把 TIMED_OUT 改为 SUCCEEDED。心跳失联与业务超时分离，不凭失联推断任务失败。

对账回复分别返回 platform_status 与动作/原因；用户取消/平台业务超时优先于 Worker 本地断联停止原因。保留 worker_stop_reason、实际退出码和回合事实，不将节点的成功结论覆盖到平台生命周期。资源释放仍必须等待清理确认，终态不是已停止的证据。

| 测试事件顺序 | 期望 |
| --- | --- |
| 有限容忍截止前一刻、恰好截止、截止后一刻再报运行 | 前者允许跟踪；后两者停止，不重置断联计时 |
| 超限一天/一年后上报运行、退出 0、进程消失 | 运行要求停止；退出/消失接收事实待清理，不重派、不臆造成功 |
| 默认不限，超出旧租约一年后重连 | 原身份且无平台停止/业务超时则可对账跟踪 |
| 取消已提交后收到退出 0 或成功回合 | 平台取消状态保持，真实退出和结果另存 |
| 平台业务超时已提交后收到成功结果 | 平台超时保持，不恢复运行、不改成功 |
| 续租/对账回复丢失，之后取消，再重放同请求 | 不续租，返回当前取消；不能返回旧运行许可掩盖取消 |
| 同序号重复、同序号不同正文、旧序号晚到 | 重复不续租；冲突/过时拒绝；都不能覆盖新状态 |
| 断联超限后节点重启、PID/unit 名复用或代次改变 | 核对 boot 与 InvocationID/container ID，冲突进入人工核对 |
| 进程退出记录后再次报运行 | 不复活原执行，保留退出事实 |
| 取消事务持有调度锁时恢复上报 | 有界拒绝并重试；取消提交后返回停止 |
| 服务重连但就绪会话仍旧 | 失效旧就绪，必须重新探测才能分配新客户端 |
| 本地持久化失败、迟到 ACK、收据误作控制响应 | 不授予新的本地运行许可，不撤销已到期停止 |


### 本地监督与网络解耦的实现边界

节点监督提供独立的本地观察/停止 tick 和有界网络 exchange；网络期间不持有本地监督锁。每个执行以文件锁防止双监督者，先持久化原始请求正文/序号再发送，丢响应后重放同一请求，只有匹配控制确认才推进；迟到重复响应不刷新控制时钟。重启沿用原业务起点与控制计时，不能使用新构造时间覆盖。进程正常退出后 unit 卸载只补充消失事实，不删除已确认退出码；很晚才观察到退出，不能据此推断此前发生了超时。

该实现阶段不调用启动或资源释放，不广告能力。实际 Worker 主循环必须在领取协商、可靠结果应用及清理确认都完成后一起接线，不能单独替换旧看门狗。测试将实际 systemd/Docker 进程与注入时钟、故障 HTTP、隔离 API 联合，真实业务时长与模拟断联时间分别报告。

### 原领取快照与启动许可分离

在原分配事务中绑定唯一 request_id/execution_id、不可变策略和完整任务快照摘要；响应丢失后只查询原快照，不重新渲染模板。恢复查询无需调度全局锁，不刷新租约或业务截止。平台取消、超时、撤销、删除或身份冲突时仅返回处置事实，不返回启动配置。所有恢复收据明确 launch_authorized=false，不能替代新的启动前对账。

节点先落盘请求后发送，重启沿用原 request_id、boot 和计时；先幂等写入执行 journal，再清除请求账本。两次落盘之间崩溃允许重复交接，禁止交接回调启动程序。后续必须把启动意图、进程身份绑定、主循环和结果清理统一接线，本阶段不单独启用。

### 首次启动确认与本地尝试记录

完成环境准备后，以原 request_id、分配代次、唯一 launch_id、boot 和模式申请首次启动确认；与取消事务同锁序，已生效的取消/超时优先。确认窗口最长 30 秒，仅约束首次启动，和已启动执行的断联容忍无关。重复请求保留首次发放时间，节点以原请求单调时间检查窗口，不能靠重试或重启续期。窗口过期保留待核对，禁止自动换启动标识重试。

节点持久化 attempted 后才调用实际启动，随后绑定带相同 launch_id 的运行实体。命令失败、启动响应丢失或身份写入失败均不能重试启动，只能核对原实体；找不到时保留未确认，不自行释放。主循环接线时，宿主机及 Docker 创建必须把 launch_id 写入可检查的运行实体元数据，不能只保存在普通 journal 中。HostBackend Description 与 Docker label 已提供可选标识，RecoveryRuntime.start/inspect_launch 核对原标识和运行身份；真实短程序同时验证隔离适配器和实际运行后端。生产 Worker 主循环尚未启用。平台在确认后接受取消，仍须后续对账停止；离线无法保证即时撤销已送达许可。

启动窗口还受原分配剩余断联容忍时间限制，可短于 1 秒；节点从原请求发出时刻计算，确认在截止点或之后到达即拒绝启动。重复请求保持原窗口，不增加容忍额度。

### 可靠结果应用的事务边界

恢复 results 接口以显式 apply:true 区分业务应用与原收据确认。按 Run→恢复授权顺序锁定，沿原回合/任务结果验证器保存事实，并与收据在同一事务提交；不用全局调度锁，不修改租约、平台终态或清理状态。已有收据可在同内容重放时幂等应用，校验失败不新增收据或消耗账本额度。Worker 仅在匹配摘要且 reconciled:true 时确认应用交付；旧 API 的仅收据响应不能使可靠结果丢失。该路径为完整主循环接线的一部分，尚不单独广告能力或启用生产执行。

### 恢复收尾的阶段接线

现有 complete/cleanup 通过显式恢复身份选择新路径，原旧协议行为保留。完成核对已保存的退出事实、原代次/boot/运行实体，以原完成正文实现幂等，不刷新租约、不直接确认清理。独立 cleanup 须在完成确认之后由节点移除原实体再发送。平台取消/超时/终态优先，迟到退出及原完成正文独立保存。恢复授权存在时禁止无证明旧请求旁路。当前协议成功仍沿用结果完整性验证，结果未齐时独立收尾与同步展示还需后续接线，不据此勾选4.1/4.4完成。

### Worker 完成收尾恢复阶段

完成正文及身份先原子落盘为 recovery_finalization；完成确认后持久化 remove，再按原身份移除已退出实体，再持久化 cleanup，最后收到清理确认才清除原执行journal。响应丢失或重启重放原阶段，不把旧完成记录送进启动分支。移除失败/身份冲突不确认清理。此入口是完整主循环的一部分，当前仅接通已有收尾记录恢复，不广告领取能力。

### 原领取API的接入边界

request_id与recovery_version成对提交；原收据在候选查询前读取，竞争资源锁后再次复核。首次分配事务保存完整任务快照与授权，再提交响应。原请求重试不续租、不重算模板；新请求不能接管已领取执行；原执行取消后只返回处置。已有收据的恢复在关闭新分配开关后仍可进行。新分配暂由默认关闭的实验开关及明确槽位能力共同保护，实际Worker未广告能力前不能启用。旧领取/裸清理列表不能交付恢复执行，以防降级绕过身份证明。

### Worker 持久领取交接实现边界（2026-11-25）

领取分流位于主循环，只有声明能力或持有未决领取请求时才使用恢复协议。收到合法收据后，顺序为收据落盘、原执行 journal 幂等提交、领取请求清空、进入派发。交接重复不得重写已保存的运行进度，身份/快照不一致保持阻塞。停止处置不携带启动任务，保留收据等待控制核对，不能假造运行身份发送旧 cleanup。尚未接通监督执行入口之前，execute 明确拒绝该 journal 进入旧 watchdog；未声明能力的生产流程维持原行为。

### 启动组合入口（2026-11-25）

恢复启动核对任务原快照、slot与boot。创建前保存created意图；已创建但对象缺失保持待核对，禁止重新创建不确定对象。运行准备完成后、持有跨执行start_lock之外调用prepare，避免网络请求占住其他执行启动锁。收到许可后，在原时间窗口内持久attempt并启动；已有attempt/bound时只调用inspect_launch核对标识及真实运行身份，不再create/start。父journal身份证明写入失败，从已绑定launch journal恢复。该入口尚不代替完整监督循环；未启用生产能力。


恢复监控组合入口：一个执行独占监督账本，本地线程只观察/停止原运行实体，网络exchange不占本地监督锁；退出与截止写入账本。关闭必须等本地线程和网络调用结束后释放账本锁；失败保留所有权。systemd停止后missing不推断退出码，后续完成核对必须使用可靠退出证据。

### 结果采集与清理后的同步确认（2026-11-25）

恢复执行的结果读取复用旧协议解析器，但 API 替换为本地可靠入队。执行记录固定来源，序号使用该来源的原偏移（单个任务结果为0），入队成功后才原子提交游标。final采集须检查原身份的退出证据；完整记录读取结束才持久保存recovery_results_collected。部分行、磁盘满及异常不能被空队列掩盖。

完成正文pending_results显式区分资源收尾和结果同步，未设置时兼容历史摘要。旧协议不得使用此字段跳过完整性检查。恢复完成允许推迟回合完整性检查，但仍验证最终指标格式/数量；snapshot.result_sync记录pending/complete。清理确认后，原授权可继续应用结果；results-finished再验证完整性并幂等确认。Worker同时检查采集封口、可靠队列排空和平台确认，之后才清除执行journal。缺少任一条件均保留本地证据。此阶段不改变界面或开启完整生产执行链路。

清理后的结果交付恢复入口仅使用原执行outbox，不得重建丢失队列伪装空队列；每轮有界交付后检查同步确认。results-finished仅采用Run→grant行锁，不获取资源全局锁，因为它不改变生命周期及分配；完成/清理继续采用原资源转换锁序。
