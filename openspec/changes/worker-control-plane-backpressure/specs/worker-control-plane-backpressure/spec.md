## Purpose

为多节点、多设备并发运行提供贯通请求处理、数据库和节点交付的过载保护，使日志与产物拥塞不损害调度及执行安全，并以有界重试、可靠补传和可重复混合测试明确容量边界。

## ADDED Requirements

### Requirement: 完整执行控制通道隔离
系统 SHALL 为续租、服务就绪及失效、取消、完成和清理确认保留入口、处理及数据库预算，并为调度保留预算；监控、领取轮询、日志、产物及 Web 不得耗尽执行控制预留。

#### Scenario: 普通流量饱和
- **WHEN** 日志、产物和 Web 达到普通预算上限而数据库仍可处理控制请求
- **THEN** 普通请求有界排队或收到背压，合法执行仍可续租、上报服务状态、完成及确认清理

#### Scenario: 监控或领取风暴
- **WHEN** 多卡节点大量采样和空闲 Worker 同时领取
- **THEN** 执行控制预留不被占满，调度继续获得其预算，取消指令不排在日志之后

### Requirement: 有界数据库和处理竞争
系统 SHALL 对入口队列、处理并发、连接获取、锁及语句等待设置预算，异常和取消时释放许可及连接，已识别过载返回明确可重试响应。

#### Scenario: 慢调度与行锁
- **WHEN** 调度或记录被长事务占用且多个请求竞争
- **THEN** 请求在预算内完成或返回繁忙，不无限占连接等待，不把未知程序错误掩盖为过载

#### Scenario: 等待者断开
- **WHEN** 请求在队列或处理中超时、取消或异常
- **THEN** 等待名额及处理许可被回收，数据库工作受其独立截止约束，不产生无限后台积压

### Requirement: 权威租约与最新观察分离
系统 SHALL 在权威租约提交后才确认续租，允许合并最新监控采样；配置与观察数据并发更新不得丢失期望配置、回退序号或复活失效会话。

#### Scenario: 仅入队尚未提交
- **WHEN** 心跳已到达入口但权威租约尚未提交
- **THEN** 平台不返回续租成功，Worker 不伪造心跳成功；已经确认的执行归属按断联执行规则处理

#### Scenario: 配置与多卡监控并发
- **WHEN** 配置更新持锁且已注册节点上报有效采样
- **THEN** 普通观察更新不依赖配置写锁，配置与采样均保留，设备观察仍遵守序号与会话边界

#### Scenario: 重注册及迁移
- **WHEN** 节点更换会话或暂停 API 写入后升级/降级观察数据存储
- **THEN** 保留当前配置及有效最新观察，旧会话上报不能覆盖新状态，节点协议兼容行为有测试证明

### Requirement: 执行局部竞争与安全资源转换
系统 SHALL 使运行中续租和执行内数据交付不依赖无关执行的全局调度锁，同时保留资源预约、释放、所有权及状态转换原子性。

#### Scenario: 全局锁被其他执行占用
- **WHEN** 当前执行仍运行且租约有效而无关调度持锁
- **THEN** 当前执行可独立续租，数据交付仍有自身有界等待和幂等保护

#### Scenario: 超时扫描遇到并发续租
- **WHEN** 扫描曾读到旧租约而执行正续租或已经提交
- **THEN** 扫描跳过忙记录或加锁刷新后复核，不依旧快照误回收资源

### Requirement: 程序结束与数据同步分离
系统 SHALL 分别记录程序执行、协议结果及数据同步状态；日志和产物积压不得阻止满足停止及清理条件的执行释放资源，缺失协议结果不得当作评测成功。

#### Scenario: 退出正常但结果未齐
- **WHEN** 程序退出码为 0，可靠协议结果仍待交付
- **THEN** 显示程序正常退出及结果待同步，收到有效完整结果后确定评测结果，超过告警阈值标记同步延迟但不删除未确认结果

#### Scenario: 批量交付持续拒绝
- **WHEN** 业务已停止且日志或产物通道持续繁忙
- **THEN** Worker 优先交付控制完成摘要和清理确认，平台按安全条件释放资源并显示数据同步状态

#### Scenario: 尚未确认业务停止
- **WHEN** 仅数据上报失败而业务停止或清理未确认
- **THEN** 平台不因希望减少积压而提前释放资源供其他任务使用

### Requirement: 有界可靠延后交付
系统 SHALL 持久化可靠待交付数据并限制节点及执行级容量，未确认状态及可靠结果不因离线时长自动删除；只有 ACK 后才推进，终态补传限定原执行身份及数据类型，并支持凭据到期后的重新认证对账，不能续租或重开执行。

#### Scenario: 响应丢失与重启
- **WHEN** 服务端接收数据后响应丢失且 Worker 重启
- **THEN** 以原执行身份、序号及摘要恢复重放，结果只记录一次，确认后推进游标

#### Scenario: 终态后补传或删除
- **WHEN** 已结束执行补传日志或结果，或对应批次已经删除
- **THEN** 有效授权补传不改变运行态与资源；删除后拒绝业务数据补传但仍接受停止/清理确认，保留未确认资源归属；撤销后不得恢复运行授权，不复活已删数据

#### Scenario: 队列容量或磁盘耗尽
- **WHEN** 节点待交付数据超过限制或无法持久化
- **THEN** 日志按策略显式标记截断，可靠结果报告交付失败而不静默丢弃，续租处理不被无限等待阻塞

### Requirement: 租约感知随机重试
Worker SHALL 分类暂时与永久故障，在 Retry-After 后保留随机退避，单次请求和退避间隔有界，已领取任务不因旧心跳租约超期停止，但有限断联容忍和业务时限仍生效，取消能够中断等待。

#### Scenario: 批量节点收到相同重试提示
- **WHEN** 多 Worker 收到相同 Retry-After
- **THEN** 不早于允许时间重试且保留抖动，不形成固定周期同步重试

#### Scenario: 持续无法续租
- **WHEN** 故障持续到租约截止，或建议等待已经超过剩余租约
- **THEN** 不伪造确认，容忍期内或不限制时继续已领取任务，有限超限则停止并持久化状态；平台保留资源和执行归属，恢复后对账补报

#### Scenario: 永久拒绝
- **WHEN** 权限失效、执行失效或协议数据非法
- **THEN** 按接口语义结束交付或报告失败，不作为无限繁忙处理

### Requirement: 可验证容量与兼容发布
平台 SHALL 用实际 HTTP/PostgreSQL 混合调度与上报测试记录成功延迟、拒绝、数据新鲜度、资源释放延迟及积压，并验证新旧能力协商；不得用连接数或短时模拟档位宣称生产 Worker 上限。

#### Scenario: 容量验收与首次失败档
- **WHEN** 持续运行包含 Agent、多卡、调度、执行控制、结果、日志、产物及 Web 的阶梯负载
- **THEN** 保留最后稳定档和首个失败档的配置、持续时间及原因，单列成功请求延迟，数据库不可用与普通流量拥塞分别验证

#### Scenario: 旧 API 或旧 Worker
- **WHEN** 一端不支持新的延后交付能力
- **THEN** 使用明确兼容路径而不发送不受支持的终态语义，运维指南说明过载保护所需升级范围

### Requirement: 断联完成已领取任务
系统 SHALL 对新协商策略默认使用不限制断联时长，并支持有限断联最大容忍时间选项，与心跳新鲜度及业务执行时限分别配置；容忍期内或不限制时允许 Worker 继续已确认领取任务，有限超限后 Worker 停止程序并保存状态。平台保留归属和资源直至安全停止清理确认，不得自动重派；断联不取消业务执行时限、失败处理规则或已收到的明确停止指令。

#### Scenario: 升级后自动具备恢复能力
- **WHEN** 纳管节点升级至支持恢复协议的 Worker，且具有可信绝对持久状态路径
- **THEN** Worker 默认从状态路径派生同机共享的可靠队列并上报恢复能力，不要求管理员逐卡编辑 JSON；任务工作目录不承载恢复账本
- **AND** 管理界面展示平台总闸及在线设备实际能力数量，平台未确认开启或旧 API 缺字段时新领取继续旧协议；显式关闭节点能力只影响新领取，不丢弃既有恢复记录

#### Scenario: 断联跨越多个回合
- **WHEN** 已领取多回合任务超过旧租约及告警阈值但仍在容忍期内，或设置为不限制
- **THEN** Worker 按原任务继续回合至完成，保存未确认状态及结果，不领取新任务；平台不误判业务失败或重派资源

#### Scenario: 有限容忍超限
- **WHEN** 原执行的有限断联容忍时间已到
- **THEN** Worker 停止程序和后续回合并保存已有结果，平台标记停止待确认，不凭超限推断停止或释放资源；停止失败继续保留资源保护

#### Scenario: 超限很久后恢复
- **WHEN** 有限容忍超限后长期离线的原 Worker 恢复且身份有效
- **THEN** 平台接受原执行的幂等退出、回合结果及清理补报，不能仅因时间已过拒绝；不恢复程序、不覆盖其他执行

#### Scenario: 有效确认与截止竞争
- **WHEN** 仅日志成功、其他执行确认、旧序号确认或超过本地截止后才收到控制响应
- **THEN** 不刷新当前执行的断联计时，不撤销已经作出的停止决定

#### Scenario: 配置及旧版本边界
- **WHEN** 用户选择有限正整数秒或显式不限制，或导入历史配置及连接旧 Worker
- **THEN** 策略随执行快照持久保存并回显，非法有限值拒绝；字段缺失走旧协议，不被当作不限制，能力不足不得静默启用

#### Scenario: 断联计时恢复
- **WHEN** Worker 重启或节点墙钟发生变化
- **THEN** 同 boot ID 从持久化单调计时恢复，不重新获得完整容忍期；机器重启按进程中断对账，不盲目重新启动

#### Scenario: 恢复时业务已经完成
- **WHEN** 原 Worker 恢复连接且业务已退出
- **THEN** 核对执行 ID、分配代次和退出状态，幂等补报回合及完成/清理信息，不重新启动已完成程序

#### Scenario: Worker 重启或授权凭据到期
- **WHEN** 断联期间 Worker 重启或补传凭据到期后重新认证
- **THEN** 从持久记录核对进程与原执行归属，合法未确认结果仍可补报，不凭进程名盲目重复启动

#### Scenario: 用户取消或真实执行时限
- **WHEN** Worker 收到明确取消，或用户配置的业务执行时限到达
- **THEN** 按既定规则停止及保存状态；平台对断联期间尚未送达的取消显示待确认，不提前释放资源

#### Scenario: 人工回收与旧执行恢复
- **WHEN** 管理员需要复用长期失联资源
- **THEN** 先确认停止或完成隔离后才允许重新分配，旧执行迟到报告不能覆盖新执行；失联服务不分配给新客户端

### Requirement: 领取和恢复不得重复启动
系统 SHALL 幂等恢复已提交领取，并在本地持久保存分配身份后启动；进程缺失或身份不明不得自动重跑，恢复不重置业务执行时限。

#### Scenario: 领取响应丢失
- **WHEN** 领取事务已提交但 Worker 未收到响应
- **THEN** 重试返回原执行及代次，不重复分配；本地持久化失败不启动业务

#### Scenario: 机器重启或身份记录缺失
- **WHEN** 恢复时原进程不存在且没有可信退出记录，或进程身份无法确认
- **THEN** 报告中断或待核对，不伪造退出码、不盲目重启，不因重新连接重置执行时限

### Requirement: 删除及取消保留安全收尾
系统 SHALL 区分停止意图与停止确认，删除业务展示后仍保留未确认执行的安全记录，并按服务端事务顺序处理取消与完成竞争。

#### Scenario: 断联中删除批次
- **WHEN** 用户删除含失联执行的批次
- **THEN** 隐藏业务记录并保留取消意图、归属和资源，恢复后接受停止清理确认，不能提前释放或复活业务数据

#### Scenario: 取消与完成同时到达
- **WHEN** 取消意图与完成报告并发提交
- **THEN** 已提交终态保持不变，较早提交取消意图决定生命周期取消，同时保留真实退出码及协议结果，不依赖节点墙钟排序

### Requirement: 已关联服务保持正确生命周期
系统 SHALL 保留失联任务的既有服务关联，不因客户端失联推断其结束；失联服务不得新增绑定，恢复后重新确认就绪。

#### Scenario: 客户端失联但仍使用服务
- **WHEN** 客户端无法访问平台但与原服务仍正常通信
- **THEN** 原服务不因该客户端心跳过期被回收，服务停止需关联结束确认、明确指令或服务自身有限断联容忍/业务时限到期，不能仅凭客户端心跳缺失停止

#### Scenario: 服务恢复在线
- **WHEN** 失联服务重新完成对账但尚未重新验证就绪
- **THEN** 不向新客户端分配该服务，已有连接按原业务规则处理

#### Scenario: 新策略默认不限制
- **WHEN** 新任务已协商断联恢复能力且用户没有设置有限断联时长
- **THEN** 执行策略明确保存 disconnect_tolerance_seconds 为 null，不因断联时长主动停止；业务时限与取消独立生效，历史执行缺少策略字段仍走旧协议

### Requirement: 平台生命周期权威
系统 SHALL 以平台已提交的生命周期及已接受的用户控制意图为准；Worker 迟到上报不得撤销已生效的取消、业务执行超时或终态，执行事实与平台生命周期分别保存。

#### Scenario: 平台取消后节点补报成功
- **WHEN** 平台已经接受取消，而原 Worker 后续补报退出码 0 或业务成功
- **THEN** 保留真实退出与结果，保持平台取消意图，不恢复执行，未确认清理前不释放资源

#### Scenario: 平台超时后收到成功结果
- **WHEN** 平台已经提交业务执行超时，而原 Worker 恢复并补报成功
- **THEN** 平台任务仍为超时，成功仅为迟到执行事实，不触发重派或恢复运行

#### Scenario: 旧运行回复在取消后重放
- **WHEN** 原运行回复丢失后平台取消生效，Worker 重放相同对账请求
- **THEN** 不续租并返回当前停止意图，旧回复不能覆盖用户取消

### Requirement: 诊断日志优先最新内容
系统 SHALL 在 Worker 上传前淘汰过旧的待传普通诊断日志并显式标记缺口，可靠结果不得随之丢弃。

#### Scenario: 断联后积压日志恢复
- **WHEN** 待上传诊断日志超过最新窗口
- **THEN** 仅准备最新 32 条环形记录（最多 64 KiB），标记 gap，保持已有发送限速和协议结果文件

#### Scenario: 旧日志块响应丢失
- **WHEN** 已持久化 pending 日志块未获确认且新的日志持续产生
- **THEN** 原序号原正文重试，确认后才跳过积压历史，不将新正文替换进原请求

### Requirement: 已确认回合摘要安全压缩
系统 SHALL 仅在确认和持久读取游标均满足时回收回合摘要，并保留禁止旧游标重入的边界。

#### Scenario: 长任务持续确认结果后释放队列条数
- **WHEN** 回合结果已被平台确认且源读取游标已持久越过该记录
- **THEN** Worker 可压缩该确认摘要并保留退休边界，释放记录额度；未确认记录不被回收，游标回退不得重新创建已退休结果

#### Scenario: 确认后读取游标落盘失败
- **WHEN** 平台已确认结果但 Worker 尚未持久推进读取游标
- **THEN** 保留原摘要供重放校验，不能依据内存中的新游标提前回收
