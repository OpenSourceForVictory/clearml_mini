# 设计

- `evaluation_batches.priority` 使用 0 到 9 的整数，默认 0，数值越大越先调度。既有批次迁移为 0。迁移 aa741b2 接在当前完整链路 c952f34 后。
- 优先级只排序同一用户的排队批次；用户之间仍按现有轮转顺序服务，避免一个用户靠持续调高优先级独占全局队列。
- 同优先级按批次 `created_at`、ID 排序；同一批次内沿用任务创建顺序。资源不匹配时仍跳过该任务尝试后续候选，优先级不形成资源预约。
- 仅当批次至少有一个 `PENDING` 任务时允许修改；已预留/运行的工作不受影响。只有批次所有者或管理员可修改。
- API 使用批次控制修订号做并发保护；优先级修改推进该修订号，避免过期页面覆盖新的控制状态。
- 列表显示优先级和仍排队数量；用户可以直接调整并保存。无需 Worker 协议变更。
