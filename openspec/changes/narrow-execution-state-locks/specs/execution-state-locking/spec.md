## ADDED Requirements

### Requirement: 单执行状态隔离
系统 SHALL 仅以当前执行行同步不涉及分配/释放的启动确认和原执行控制，所有竞争入口必须在锁内复查状态。

#### Scenario: 不相关调度正在运行
- **WHEN** 调度全局锁被持有而某已领取执行上报启动或有效恢复
- **THEN** 不因该全局锁拒绝上报，仍保留当前Run/设备/恢复账本的一致性

#### Scenario: 用户取消与迟到启动
- **WHEN** 用户取消与启动确认并发
- **THEN** 串行检查已提交状态，取消不会被迟到RUNNING覆盖，Run与Job保持一致

### Requirement: 资源变化保持互斥
系统 SHALL 保留涉及资源释放和服务就绪失效的调度互斥，禁止先锁执行再反向获取全局锁。

#### Scenario: 服务租约过期恢复
- **WHEN** 服务恢复将清除已过期的健康状态与探测epoch
- **THEN** 按全局锁到执行行顺序处理，跨过期边界则安全重试，不分配旧就绪地址

### Requirement: 繁忙原因可区分
系统 SHALL 区分全局调度锁、执行行竞争和状态需要重新检查，保持503可重试及Retry-After兼容。

#### Scenario: 同执行竞争
- **WHEN** 当前执行行被其他事务持有
- **THEN** 返回可区分的执行行繁忙，不将其统计为全局调度锁竞争
