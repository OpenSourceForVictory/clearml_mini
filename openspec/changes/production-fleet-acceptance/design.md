# Design

## Context

参见 proposal.md。现有控制端是 FastAPI/PostgreSQL/React，五节点使用共享 NFS，Worker 与 Agent 已分工。scripts/control.py 的默认 Compose 参数不包含 deploy/lan-compose.yml，而现有机群依赖该 overlay。现有备份命令支持 pg_dump 与摘要；新编排要求协议 10。最新验收报告是本机逻辑节点和隔离数据库，不是本次生产事实。

## Goals / Non-Goals

**Goals:** 固化可重复发布与验收边界，先验证备份和兼容性，再排空发布，以实际物理节点证据判断结果。

**Non-Goals:** 不把发布脚本变为第二个调度器；不通过直接改库伪造完成状态；不变更资源算法或承诺真实模型评测通过。

## Decisions

1. **独立发布编排层。** 发布工具复用现有纳管、升级与运行 API，维护本次 release ID 和阶段记录，不接管任务生命周期。相比散落 SSH 命令，可验证幂等和失败恢复；相比新增常驻发布服务，保持五节点部署简单。只读 inventory 和执行发布分开，默认不变更。
2. **白名单与现场核验。** 目标为 .151/.157/.177/.182/.183，连接入口使用已有 SSH 配置且核对主机密钥。记录实际 IP、节点 ID、GPU UUID、服务名称、版本摘要、目录修订和挂载来源。清单不保存明文密码/token；未知字段阻止门禁而非猜测。
3. **短维护窗口与逐节点放行。** 全局停止新准入但保持续租/日志/清理，完成排空后备份和迁移控制端。先升级一台空闲计算节点验证，再逐台更新其余节点；只在节点能力与版本确认后恢复准入。不承诺数据库迁移零停机。保留用户原暂停/禁用状态，仅撤销发布工具施加的状态。
4. **兼容表由代码与实际制品建立。** 核对目标 migration head、Worker 协议、Agent 协议与打包内容，不要求仅因版本号变化重装全部机器。部署保留 LAN overlay 与监听边界。升级工具复用现有锁/回滚机制，任何步骤失败停止后续节点。
5. **两层验证。** 隔离数据库与测试 Worker 执行破坏性故障注入；生产节点验证真实硬件、网络、目录与隔离任务执行。不关闭共享 NFS 服务、不停止 Docker daemon、不注入整机断网。NFS 故障用专用测试挂载或存储探针故障模拟，标明不等价于生产 NFS 停机验证。
6. **持续运行有完成标准。** 至少 2 小时、3 个测试用户、30 个三任务批次，控制队列压力，定期核对心跳、租约、状态与资源账本。每台节点至少执行成功一项；跨机 CS 覆盖四种 host/docker 组合及共享/独占。记录吞吐和延迟，不以未经基准验证的性能数字作为承诺。2 小时通过不代表长期稳定性已证明。

## Risks / Trade-offs

- [真实工作负载阻碍排空] → 超时后停止发布，报告执行与所有者，不杀任务；恢复本次引入的可恢复准入状态。
- [迁移后旧版本不兼容] → 先在恢复的隔离库验证迁移和回退保护；产生新数据后优先前向修复，不自动覆盖旧快照。
- [共享 NFS 为共同依赖] → 本次只验证隔离故障和恢复，不操作生产挂载服务；真实存储高可用另立变更。
- [服务与客户端共同占用额度] → 验收计算两端占用，以现有全局/用户/池上限设计批次，验证排队不会误报完成。
- [故障注入影响用户] → 校验测试 ID、进程/容器标签和归属，缺失归属即拒绝；升级重启仍须排空目标正式执行。

## Migration Plan

1. 采集五节点和控制端实际状态，生成发布计划与兼容表，保留旧制品摘要和启动参数。
2. 隔离环境执行完整回归、发布工具负向用例、备份恢复与迁移演练。
3. 停止新准入并排空；备份数据库及受保护的配置/执行记录，校验备份并在隔离实例恢复核验。
4. 迁移并更新 API/前端，保留内网入口；按兼容表逐节点升级 Worker/必要 Agent，检查身份和配置回执。
5. 执行生产冒烟、物理跨机矩阵、隔离故障与持续运行测试；清理测试资源，恢复本次变更前的管理状态。
6. 汇总实际版本、测试结果和未覆盖项。失败时停止扩散，按失败阶段恢复兼容组件或前向修复；存在新数据时不直接恢复旧库。通过后更新当前部署指南和提交验收证据。

## Acceptance Matrix

| 编号 | 场景 | 必须观察的结果 |
| --- | --- | --- |
| R01 | 五节点只读盘点、未知节点、SSH 身份不符 | 清单完整；越界拒绝；不变更状态 |
| R02 | 活动任务、未清理任务、排空超时 | 不替换组件、不杀用户任务，状态可恢复 |
| R03 | 重复发布、发布途中中断、并发发布 | 阶段可对账，不重复安装或覆盖执行记录 |
| R04 | 备份失败、摘要错误、隔离恢复 | 失败阻止迁移；恢复后历史关键记录一致 |
| R05 | 升级/降级演练、活动编排降级保护 | 版本一致；不兼容降级拒绝 |
| R06 | 控制端发布、LAN overlay、旧 Worker | 入口保留；不兼容任务无法被旧节点领取 |
| R07 | 单节点升级失败与继续发布 | 后续节点停止；旧身份/NFS/凭据引用不丢失 |
| E01 | 五台物理 GPU 逐机执行 | 每台真实 GPU 可见、回合结果及清理齐全 |
| E02 | host/host、host/docker、docker/host、docker/docker × 共享/独占 | 八组跨物理机，参数和服务绑定正确 |
| E03 | 外部地址、平台托管、无服务命令 | 三入口正常；普通命令不伪造回合指标 |
| E04 | 三用户多集合、容量不足 | 有排队且资源释放后推进；不超卖、不重复执行 |
| E05 | 同卡共享、独占互斥、CPU/RAM/VRAM 不足 | 按现有策略准入，未清理资源不释放 |
| E06 | 暂停、继续、取消、单项及批量重试 | 状态与服务生命周期一致，历史绑定保留 |
| F01 | 测试 Worker SIGKILL 与重启 | 同一次执行不重复启动，对账后清理一致 |
| F02 | 测试 Agent 慢采样/失联 | 控制循环有界，过期遥测阻止新准入 |
| F03 | 测试服务退出、健康超时、端口冲突 | 客户端不访问失效代次，重试有界 |
| F04 | 测试 Worker/API 通信中断和恢复 | 租约看门狗生效，不确定执行保持占用 |
| F05 | 隔离存储慢响应、磁盘不足、资产缺失 | 不阻塞心跳，给出明确环境错误与恢复路径 |
| F06 | 验收进程中断与重复清理 | 只清理测试对象，无遗留容器/单元/占用 |
| S01 | 至少两小时持续多用户提交 | 每批有终态与结果，最终资源账本及清理归零 |
| U01 | 真实浏览器提交、排队原因、关系/日志/结果、越权访问 | 用户流程正确，拒绝访问其他用户私有对象 |
| V01 | 后端全量、PostgreSQL 并发、前端与严格规范校验 | 明确通过/失败/跳过，不以跳过抵扣验收 |

## Open Questions

现场版本、活动执行数量与宿主机环境就绪程度在 R01 获取；这些事实决定发布窗口和前置准备，不改变上述门禁。若节点不可达，报告阻塞，不替换目标、不把四节点验收标记为五节点通过。
