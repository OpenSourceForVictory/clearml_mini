# Proposal

## Why
第一阶段的评测采用 CS 架构：推理服务由外部维护，平台负责启动和管理仿真客户端。现有任务只有固定 Mock/渲染参数且容器禁网，需要可复用的客户端接入契约。

## What Changes
- 管理员登记版本化客户端模板（镜像、启动参数数组、支持的服务协议），用户选择模板并提交服务地址、任务名、回合、种子、超时及 JSON 参数。
- 提交显式评测清单，创建批次及独立子任务，平台逐项追踪状态、进度与失败重试。
- 快照保存模板与任务配置；具备对应镜像能力的 Worker 才能领取 CS 任务，CS 容器使用 bridge 网络。
- 定义输入 JSON、标准日志/最终指标与输出目录协议，提供连接预检、总超时和 HTTP 示例客户端/测试服务。
- 支持报告、图片和短视频等有界产物的幂等上传、鉴权下载及页面展示。
- 用配套测试服务完成协议验收，不将其标记为真实 RoboTwin 模型评测。

- 提供用户实现单回合逻辑的 SDK 与基础镜像，统一回合计划、进度事件和结果校验。
- 增加用户拥有的版本化评测集合；每次运行固定集合快照，独立设置并发上限；资源不足保持排队，用户和集合两级轮询。
- 提供代码构建入口，保留版本化镜像登记路径；构建与评测执行分离。

## Capabilities

### New Capabilities
- `cs-evaluation`: 外部推理服务驱动的仿真客户端任务契约、模板、联网执行和产物回收。

### Modified Capabilities
无。

## Impact
涉及 FastAPI、数据库迁移、Worker 协议 v3、Runner SDK/示例、React 和部署配置。保留 Mock/渲染和 v1/v2 Worker 兼容。推理服务部署、模型 checkpoint 管理、完整 RoboTwin 适配不在本次范围。用户确认先实现接入协议，真实服务适配另行验收。
