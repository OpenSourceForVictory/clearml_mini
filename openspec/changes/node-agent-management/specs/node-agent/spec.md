## Purpose
为异构 GPU 节点建立统一管理入口，区分节点心跳、运行能力和任务执行状态，使配置下发、程序管理、日志诊断和升级恢复有明确责任边界，并兼容已有 Worker 及平台调度协议。

## ADDED Requirements

### Requirement: 节点身份和心跳
系统 SHALL 使用稳定节点身份上报 Agent 版本、启动身份和有序心跳；拒绝无效身份、旧会话和乱序覆盖，保留旧 Worker 接入兼容性。
#### Scenario: 重复或过期上报
- **WHEN** 相同序号重复上报或旧 Agent 会话发送心跳
- **THEN** 重复请求不重复执行操作，旧会话不能覆盖当前节点状态
#### Scenario: 尚未安装 Agent
- **WHEN** 老节点仅有 Worker 心跳
- **THEN** 页面明确显示 Agent 未安装，原有任务协议继续工作

### Requirement: 监测故障隔离
Agent SHALL 分别上报主机、GPU、运行环境和受管程序状态，探测有超时、采样时间和错误标识，不让慢探测阻塞心跳。
#### Scenario: GPU 探测失败
- **WHEN** GPU 工具超时
- **THEN** GPU 采样标记失败，其他监测和心跳继续；不将失败值当作零占用

### Requirement: 配置修订和回执
系统 SHALL 区分期望配置与已生效配置，拒绝并发旧修订写入；Agent 校验后原子保存回执，保留最后有效配置。工作区、运行环境及回合配置沿用现有专属协议。
#### Scenario: 非法配置
- **WHEN** 管理员设置越界采样周期或未知配置字段
- **THEN** 拒绝变更且不覆盖现有配置
#### Scenario: 下发后重启
- **WHEN** Agent 应用配置后重启
- **THEN** 恢复已应用修订，不重复执行已完成的配置动作

### Requirement: 受管程序协调
系统 SHALL 仅允许管理安装时登记的 Worker 服务；支持运行和排空后停止的期望状态，重复协调不重复启动。评测与推理服务使用现有任务及服务实例 API，Agent 不自行创建业务重试。
#### Scenario: 停止忙碌节点
- **WHEN** 管理员请求停止受管 Worker 且存在活动或未清理执行
- **THEN** 停止新任务准入并等待清理，原任务继续续租，清理完成后才允许停止
#### Scenario: 远程控制越界
- **WHEN** 请求任意 shell、未登记单元或修改其他节点程序
- **THEN** 拒绝请求且不执行命令

### Requirement: 本地恢复与日志
Agent SHALL 在本地磁盘持久化身份以外的运行状态和有界脱敏事件，限制缓存量，重启核对实际程序状态，绝不依赖业务 NFS 保存控制记录。
#### Scenario: 平台断连
- **WHEN** 上报失败后 Agent 重启
- **THEN** 已有任务沿用租约规则，Agent 恢复后核对服务而非重复启动任务，事件按序去重补报
#### Scenario: 共享盘失联
- **WHEN** NFS 工作区不可用
- **THEN** Agent 心跳及本地恢复仍可用，相关 Worker 依已有工作区协议阻止新任务

### Requirement: 安装升级与兼容
完整节点安装 SHALL 包含 Agent 和独立升级器，保留原 Worker 配置及服务依赖；Agent 自身升级使用独立执行器、排空、摘要校验、回连验证和失败回滚。
#### Scenario: 升级失败
- **WHEN** 替换后 Agent 未按目标版本回连
- **THEN** 回滚并保持准入关闭，报告失败而不标记升级成功

### Requirement: 管理界面与可诊断性
平台 SHALL 展示 Agent 在线/版本、配置修订、程序状态和近期事件，权限仅管理员可修改；节点心跳不替代执行心跳和资源就绪。
#### Scenario: Agent 在线但 Worker 未运行
- **WHEN** Agent 回连而 Worker 服务停止
- **THEN** 页面分别显示两类状态，该节点不因 Agent 在线而获得任务
