# Spec Delta

## Purpose

为逐回合启动的业务提供可区分的程序退出、协议结果校验和业务评测结果，使用户能够定位程序正常结束但协议输出缺失或不合法的情况，同时保留真实失败与既有任务控制语义。

## ADDED Requirements

### Requirement: 协议结果错误明确分类
系统 SHALL 将逐回合协议结果缺失、重复、结构或字段无效分类为明确且安全的诊断，包含修复提示，不回显业务原始输出。已知校验错误 SHALL 被受控处理，不再只报告笼统的 simulation episode raised an exception。

#### Scenario: 缺少结果
- **WHEN** 业务进程退出 0 且 stdout 没有可识别的 final JSON 行
- **THEN** 回合报告缺少协议结果，并提示独立 stdout JSON 行要求，保留退出码 0

#### Scenario: 多个或非法结果
- **WHEN** stdout 包含多个 final，或唯一 final 的类型、字段不合法
- **THEN** 分别报告重复结果或无效结果，不算业务成功

### Requirement: 程序退出与评测结果分别展示
界面 SHALL 按业务子进程退出码展示程序退出状态，独立展示协议结果状态和业务结果；缺少退出码 SHALL 显示未上报，不从整次执行退出码推断回合退出码。

#### Scenario: 正常退出但协议异常
- **WHEN** 回合退出码 0 且协议校验失败
- **THEN** 程序状态显示正常结束，结果显示校验异常及具体原因，最终评测不成功

#### Scenario: 未知或非零退出码
- **WHEN** 退出码缺失或非零
- **THEN** 分别显示未上报或异常退出，不将缺失结果误报为程序正常退出

### Requirement: 保留任务和回合控制语义
系统 SHALL 保留普通命令按退出码判断、有效协议按业务结果判断，以及失败后继续或停止的既有行为。已启动并完成的业务回合发生结果错误 SHALL 不被汇总成仅启动失败。

#### Scenario: 三回合继续执行
- **WHEN** 三个回合均以 0 退出但缺少 final，错误策略为继续
- **THEN** 三个回合均被尝试，各自结果异常，总任务失败并提示回合结果错误

#### Scenario: 普通命令和有效结果
- **WHEN** 普通命令退出 0，或协议模式提供有效 final
- **THEN** 普通命令正常完成且不要求 final，协议模式按真实 success_rate 判定业务成功或失败

#### Scenario: 旧记录和未知异常
- **WHEN** 读取旧通用 ERROR 记录或业务抛出未知异常
- **THEN** 保留原诊断而不伪造精确分类，未知异常详细信息仍可在 stderr 定位

### Requirement: 程序执行与协议回合结果独立统计
系统 SHALL 对同一次执行尝试提供独立的程序执行统计和平台协议回合结果统计，以全部回合而非当前分页计算。程序执行按退出码及生命周期分类，协议结果按有效业务结果或校验异常分类；普通命令协议统计 SHALL 显示不适用。未启动、未知退出和缺失结果 SHALL 不被推断为成功或程序失败。

#### Scenario: 三次正常退出但结果不合法
- **WHEN** 三个回合都退出 0 但协议结果缺失
- **THEN** 程序正常结束计数为 3，协议结果校验异常计数为 3，业务成功为 0

#### Scenario: 合法业务失败
- **WHEN** 回合退出 0 并上报有效的业务失败结果
- **THEN** 程序正常结束加 1，协议业务失败加 1，结果校验异常不增加

#### Scenario: 分页与普通命令
- **WHEN** 用户翻页查看同一次执行，或查看普通命令
- **THEN** 翻页不改变总统计，普通命令不显示虚假的协议回合成功或异常数量

### Requirement: 批次页面一致展示两种结果
运行批次结果页 SHALL 在批次汇总、任务列表和回合详情独立展示程序执行与协议回合结果，批次列表使用相同口径。批次汇总 SHALL 仅统计各任务最新尝试的全部记录，独立于分页筛选，并明确程序次数与协议回合数的单位。普通命令不纳入协议结果分母；生命周期与补跑语义保持不变。

#### Scenario: 缺失结果的批次
- **WHEN** 最新尝试有三个子进程正常退出但均缺少协议结果
- **THEN** 批次与任务分别显示正常结束 3 次、结果校验异常 3 回合；回合详情可见退出码 0 和具体原因

#### Scenario: 重试和翻页
- **WHEN** 任务重试后用户切换分页或筛选
- **THEN** 批次总汇总只包含最新尝试且不受当前页影响，旧尝试结果在历史中保留

#### Scenario: 单进程多回合
- **WHEN** 一次业务启动执行多个回合且仅有该业务进程的退出码
- **THEN** 程序执行只计一次，各协议回合结果分别计数，不为每回合伪造退出码

#### Scenario: 混合批次
- **WHEN** 批次包含普通命令与协议任务
- **THEN** 协议统计标明不适用任务，成功率仅使用有效已完成协议回合，异常及未上报单列；无有效协议结果显示暂无数据

### Requirement: SDK 及报告保持明确语义
系统 SHALL 将 SDK 命令结果文件缺失、无效和非法字段受控分类；原生 SDK 没有独立回合进程时退出码不适用。报告、CSV 和批次比较 SHALL 使用两套结果分类；普通命令成功率不适用，不对缺失成功率执行算术。

#### Scenario: SDK 文件缺失
- **WHEN** SDK 命令正常退出但未写入结果文件
- **THEN** 程序正常退出，协议结果异常并提示 MINI_EVAL_RESULT 文件要求

#### Scenario: 普通命令比较
- **WHEN** 两个正常完成且上报回合的普通命令批次进行比较
- **THEN** 返回成功响应和协议比较不适用原因，差值为空，不触发服务器异常

#### Scenario: 原生 SDK 回合
- **WHEN** SDK 在同一进程执行多个回合
- **THEN** 每回合退出码不适用，协议结果分别展示，不按回合数复制进程退出统计

### Requirement: 整任务普通命令按执行展示
系统 SHALL 对整任务启动且未接平台协议的普通命令展示单条执行状态及任务退出码，不显示计划回合列表或回合翻页。配置回合数和实际传参 SHALL 保留；协议单进程和逐回合进程仍按原规则展示回合。缺少退出码不得判定正常，生命周期状态保持独立。

#### Scenario: 十回合配置的整任务普通命令
- **WHEN** 普通命令一次启动且配置回合数为 10
- **THEN** 详情和批次仅展示一条执行记录，退出 0 表示执行正常，非零表示执行异常，配置仍保留 10，不伪造十条回合状态

#### Scenario: 协议或独立回合进程
- **WHEN** 一个进程上报协议回合，或 SDK 命令适配/逐回合模式启动独立进程
- **THEN** 保留回合列表，未上报结果不被退出 0 替代

#### Scenario: 无退出码的终止任务
- **WHEN** 整任务普通命令被取消、超时或未能确认退出码
- **THEN** 保留任务生命周期和诊断，不计为执行正常
