# Proposal

## Why
历史批次配置已经可以查看，但再次评测仍需手工填写向导，容易遗漏逐任务参数、服务实例数及资源限制。用户需要从实际运行配置创建可编辑的新任务。

## What Changes
- 在批次列表及详情增加“基于此批次创建”，导入现有五步评测向导，明确来源批次。
- 使用保存的任务和服务配置恢复清单、参数、环境覆盖、资源申请、超时及并发；每项差异独立保留。
- 允许查看修改，重新预检后提交新批次；不修改源批次，不复用旧任务、执行、实例或幂等键。
- 对缺失快照、模板不可用、权限变化和旧服务实例上限语义明确提示，禁止静默替换。

## Capabilities
### New Capabilities
- `batch-rerun`: 从历史批次快照生成可编辑向导草稿，并安全提交独立的新批次。
### Modified Capabilities
无。保留现有只读运行配置与普通集合提交行为。

## Impact
后端批次读取与编排接口；前端 batch-history、batch-detail、cs、run-wizard 及服务编辑器；新增 API 与 Playwright 回归；同步向导指南、批次监控文档和 Skill 参考。预计复用现有持久化快照，无数据库迁移，不改 Worker/Runner 或宿主机、容器启动协议。
