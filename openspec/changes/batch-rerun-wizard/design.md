# Design

## Context
RunWizard 目前只接收 suite 导入，提交时 suite_id 会让服务端从集合重建 cases；直接复用它会丢失历史任务差异。BatchParameters 已读取 job.client_spec 和 orchestration.definitions，但逐任务取数不适合作为整批复制接口。编排提交 compile_submission 已有参数、资源和权限验证。

## Goals / Non-Goals
Goals：将历史配置转换为普通可编辑草稿，提交仍复用现有编排校验；查询数量不随任务数逐项发 HTTP 请求。
Non-Goals：不恢复进程、不续跑旧执行、不克隆旧服务实例、不自动升级节点；不修改 Worker/Runner 及设备隔离。

## Decisions
1. 新增只读 GET /batches/{id}/rerun-draft，复用批次访问权限，批量查询任务及编排快照，按允许字段返回结构化草稿、来源和字段级问题。优于浏览器逐项抓取 jobs，可集中控制权限和缺失规则，不返回 token、日志或执行状态。
2. 草稿以 source_batch_id/title、schema_version、可编辑提交字段与 issues 表达。任务列表来自该批次的实际任务，suite_id 默认为空，以自定义清单进入向导；仅展示原集合引用，不重新读取集合替代。参数恢复为各任务已保存的最终值，共同值可放公共字段，但不得让公共编辑被隐藏的逐项覆盖静默抵消；界面显示逐项优先级与最终值。
3. 客户端公共配置仅在各项一致时归并；现有向导无法表达的异构模板、环境或时限差异返回明确阻塞问题，不取第一项代表全部。任务参数和 resources 保留逐项字段。适配新旧资源契约，保留 0/false/空值的语义。
4. 托管服务从 definitions 恢复 key、template_id、参数、环境、资源池、资源请求、实例数、访问模式及 stop_after_batch；只保留用户原本指定的固定槽位，不复制调度结果。旧 max_instances 不能当明确实例数，要求确认实例数。外部服务仅恢复候选地址，无服务模式保持 none。
5. 模板按原 ID/版本引用且与历史快照核对。失效或变更时提示并阻止静默替换；用户可主动选新模板，随后重新验证参数。快照不足的关键字段不给看似可信的默认值。实时资源/准入仍以现有 preflight 和 POST 再验证为准。
6. 前端 launch 扩展为集合/历史批次两类。列表和详情共用入口，向导一次性初始化完整状态，重置预检、试跑、提交消息和幂等缓存；标记 timeout/address 已导入，防止异步默认值覆盖。重复导入与请求竞态用请求序号处理。来源仅作草稿说明，本期不新增数据库字段持久化血缘。

## Risks / Trade-offs
- 历史快照字段不完整 → 返回字段级问题，不能恢复时禁用提交并说明原因。
- 当前模板不再可用 → 保留历史身份，用户明确重选，现有模板注册和权限流程保持不变。
- 大批次 → 服务端批量读取、只返回配置，避免日志、尝试和 N+1 查询。
- 公共参数与逐任务优先级 → 展示差异与最终预检值，测试修改后真实提交载荷。
- 机密环境值 → 仅沿用已有授权配置读取范围，不记录草稿到服务日志或浏览器持久化存储，不复制运行凭证。

## Migration Plan
预计无需数据库迁移或 Worker/Runner 升级。部署 API 后部署前端；回滚前端可隐藏新入口，不影响现有批次。实现阶段先跑相关后端、Playwright、类型检查与构建，按项目 coverage 工具口径记录覆盖率与未覆盖边界；不将界面模拟测试描述为真实模型评测。

部署验收应检查运行容器实际注册 rerun-draft（位于静态资源 catch-all 之前），不能以仓库存在源码或只更新静态页面作为接口上线依据。通用 Not Found 提示检查 API/代理，batch not found 则提示批次不存在或不可访问。
