# 设计

`Pool.cpu_per_job` 和 `ram_gb_per_job` 保持现有整数列，无数据库迁移。取值 0 只表示没有显式申请时该轴的有效申请为 0。资源契约、提交覆盖仍需正整数，不接受通过显式 0 绕过模板下限。

资源解析与预约账本使用同一个有效申请。预检、普通调度、托管服务配对调度以此检查节点预算、Agent host 最新样本和已有预约。CPU 实测使用总逻辑核数，不从利用率推算空闲核数；内存同时检查总量和 MemAvailable。未申请的轴跳过自身容量和样本检查，其他准入条件不跳过。

Docker 对零值轴省略 `--cpus` 或 `--memory`；宿主机 unit 省略 `CPUQuota` 或 `MemoryMax`，启动前只核验正值轴，进程数限制仍核验。旧的正数池值维持原默认申请行为。
