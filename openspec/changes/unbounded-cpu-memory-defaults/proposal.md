# 按实际申请调度 CPU 与内存

## 问题

资源池的每任务 CPU/内存目前既作为旧任务默认值又作为模板申请的硬上限，管理员不能表达“未申请时不设运行额度”。这会拒绝节点本可容纳的服务端模板。

## 方案

保留资源池正数值作为未申请时的默认申请，取消其单任务上限语义。允许将单轴默认值设为 0，代表未申请时不预约该轴，也不在 Docker/systemd 设置该轴额度。明确申请的任务仍按节点配置容量、Agent 主机采样和现有平台预约调度；并发、设备、生命周期等限制保持。

## 验证边界

覆盖请求解析、预检/单任务调度、客户端与服务端联合调度、Agent 主机样本和 Worker 两种运行后端。只运行相关测试；模拟调度不代表真实业务或模型评测验收。
