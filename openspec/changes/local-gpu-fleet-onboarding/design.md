# Design

## Context

控制节点位于 192.168.8.151，已运行 API/PostgreSQL，新库暂无 Worker。现有资源池允许不同 GPU 型号，安装器支持逐卡身份与持久 journal。已确认 .182/.177/.183/.157 的驱动正常，后三台新主机中的 .182/.183/.157 缺 Docker。用户已授权安装并提供 sudo 凭据。

## Goals / Non-Goals

Goals: 5 台可用机器（含本机）进入公共异构池；独立凭据、GPU 遥测、持久目录、退出 SSH 后常驻及开机恢复；有实际容器和任务证据。

Non-Goals: 不升级显卡驱动，不恢复 .174 的网络，不把 mock/协议自检称为真实模型评测，不迁移旧控制库。

## Decisions

- 使用 Compose override 增加指定私网端口映射，同时保留 loopback，现有 SSH 转发命令不变；不监听其他网卡。
- 采用已有 Worker v6 和用户 systemd，启用 linger；已有旧系统服务检查并排空/停止后接入，备份配置及恢复目录，不复用旧控制库 token。
- 公共池 `gpu_model=*`，初始每机并发 1、GPU 独占，避免未经测量即超卖；共享可后续通过平台设置。
- Runner 预置统一固定镜像；新节点只装 Docker/Toolkit，镜像从本机分发以减少网络下载。资产目录留空或复用经核对的只读路径，不复制大型仿真资产。
- 注册后使用成员 API 统一分配，验证平台目录配置回执和实际执行，验收记录只保存非敏感节点/任务标识。

## Risks / Trade-offs

- SSH 可达不等于可执行 → GPU 容器、挂载和任务分别验收。
- 旧 Worker 重试旧地址 → 检查无活动执行后停用旧服务并保留恢复记录。
- 私网 IP 改变 → 文档记录更新 API 监听与所有 Worker 地址的方法。
- 网络下载失败 → 保存日志、使用官方软件源和本地镜像分发；不关闭认证或签名校验。
- .174 离线 → 仅记录待接入，恢复后按同一流程纳管。

## Migration Plan

先保留配置备份，再开放内网地址、安装缺失运行环境、创建独立机器凭据、安装 Worker、纳入公共池、配置目录、逐卡验收。回退先停新 Worker 并保留 journal，再恢复已备份配置；控制节点移除私网 override 即恢复仅回环访问。已有系统驱动不变，已安装 Docker/Toolkit 不自动卸载。

部署发现并纳入修复：安装器错误地将 WorkingDirectory 作为 shell 参数加引号，systemd 249 拒绝该单元。仅修复单元路径编码并新增真实解析器回归，不改变 Worker/API 契约。
