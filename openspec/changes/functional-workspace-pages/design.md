# Design
## Context
上一轮广泛路由改造已按用户纠正撤回。本次以具体页面职责为界，不进行全站路由改造。
## Goals / Non-Goals
目标：机器配置按功能显示，模板只读展示与注册一致；任务列表不提交；向导与批次结果分别提供左侧入口。
非目标：修改评测协议、调度、后台权限、任务历史或重写注册表单。
## Decisions
共享 FunctionPages 仅用于局部配置，机器子页首次访问才挂载，切换后保留内存草稿；切换机器重置页签。TemplateForm 增加 readOnly，通过禁用整个表单阻止修改并移除提交入口，详情保留完整 JSON 供核对补充字段。
CSWorkbench 保留原 hash 批次详情和比较路径；新增 /cs/results，左侧向导和结果使用同一个组件实例以保留向导草稿、列表分页、比较选择。集合发布回调将选中集合传入向导。
批次参数按所选任务读取 jobs/:id 的提交快照，避免一次请求整个批次所有任务；服务参数从既有编排 definitions 读取，服务状态和任务关系沿用既有监控。所有读取保留后端权限校验。
集合管理默认移至管理设置；镜像与代码接入移至运行模板。普通成员有评测配置入口，只展示其有权操作的集合、镜像、代码和模板副本，不展示管理员机器及账号设置。
## Risks / Trade-offs
- 表单只读模式显示缺省值可能与历史旧模板未配置字段混淆：保留原始 JSON；详情不发送写请求。
- 表单嵌套和长命令可能撑开 grid：子项 min-width:0，pre 换行，真实浏览器覆盖桌面与 390px 窄屏。
- 入口移动会影响旧测试流程：更新导航步骤，保留参数提交、日志、补跑和状态断言。
- 静态发布不重启 API，保留旧资源供已打开页面使用；通过基于当前 API 镜像的前端覆盖镜像保存可重建部署。
