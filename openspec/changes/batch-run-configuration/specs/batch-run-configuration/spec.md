## Purpose
为用户提供与提交向导顺序一致的批次运行配置回顾，基于已保存的任务和服务快照核对实际提交内容，明确历史配置、缺失记录与实际分配结果的边界，避免模板后续修改导致历史运行解释错误。

## ADDED Requirements
### Requirement: 按向导分组查看运行配置
系统 SHALL 在批次详情提供只读“运行配置”，按任务集合、客户端、服务端、资源与执行限制分组显示保存的配置，并支持按任务切换。
#### Scenario: 同批次不同参数
- **WHEN** 用户切换批次中的两个任务
- **THEN** 显示各自的回合、种子、业务参数、环境覆盖和资源申请，不把首个任务参数当作整个批次的统一值
#### Scenario: 运行方式与限制
- **WHEN** 配置包含宿主机登录环境、逐回合继续和不限总时限及 CPU/内存
- **THEN** 页面明确显示这些选项和正数调度预约量，区分预约与硬上限
### Requirement: 使用历史快照
系统 SHALL 使用本次提交保存的模板、业务参数及服务定义，不以模板或节点的当前配置填补历史值。
#### Scenario: 模板已修改或归档
- **WHEN** 本次运行使用的模板后来被修改或归档
- **THEN** 仍能查看本次模板快照，并显示快照记录的命令、模式和参数
#### Scenario: 历史记录缺失
- **WHEN** 历史批次未保存集合名称版本、节点业务账号或预检结果等信息
- **THEN** 显示未记录或仅显示可确认的标识，不伪造当前值或重新预检冒充历史结果
### Requirement: 区分服务配置与实际分配
系统 SHALL 展示托管服务定义或外部候选地址，并将配置值与实际分配的节点、设备及地址区分。
#### Scenario: 多个托管服务定义
- **WHEN** 批次包含多个逻辑服务及明确实例数
- **THEN** 逐一定义展示模板快照、参数、资源、实例数与就绪策略，实际实例仍可在服务端与关联页查看
#### Scenario: 外部服务或无需服务
- **WHEN** 批次使用外部服务或普通命令无需服务
- **THEN** 分别显示候选地址与访问模式，或明确显示无需服务，不误报为待分配
### Requirement: 配置读取状态可靠
系统 SHALL 明确展示加载、失败、无任务和缺失快照状态，切换任务或批次时不残留上一项配置。
#### Scenario: 快速切换或读取失败
- **WHEN** 用户快速切换任务，旧请求晚于新请求返回，或新请求失败
- **THEN** 不显示错误任务的配置，并提供失败提示和重试入口
### Requirement: 模板名称可直接识别
系统 SHALL 在客户端与各服务端配置分组直接显示本次模板的名称和版本，不要求通过模板 ID 或展开 JSON 识别。
#### Scenario: 多服务端模板名称
- **WHEN** 批次使用一个客户端模板及多个服务端模板
- **THEN** 客户端名称版本和每个服务端名称版本分别可见，均来自历史快照

### Requirement: 完整展示历史动态映射
系统 SHALL 在客户端和服务端运行配置中合并展示平台映射与类型化业务参数绑定，不依赖用户展开原始快照。
#### Scenario: 业务与平台字段同时绑定
- **WHEN** 历史模板同时包含 task.task_name 命令行映射及业务字段 argv/env/input 绑定
- **THEN** 展示各来源、目标、接收名称、编码及已保存值，切换任务时值随当前任务更新
#### Scenario: 旧快照或可选值缺失
- **WHEN** 绑定元数据或字段值未保存
- **THEN** 明确提示未记录或值未提供，不从当前模板补充或伪造节点分配值
