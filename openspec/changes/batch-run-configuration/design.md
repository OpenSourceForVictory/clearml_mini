## Context
见 proposal.md。当前 batch-parameters.tsx 按选中 job_id 调用 jobs/{id}，用 JSON 展示 parameters/resources/client_spec；batch-detail.tsx 已提供独立参数页。提交向导顺序为选择集合、客户端、服务端、资源配置、预检确认。jobs.client_spec 保存模板与参数快照；orchestrations/{id} 返回 definition 中的 services。批次只有 suite_id，不应将实时集合元数据作为历史快照。

## Goals / Non-Goals
Goals：向导式只读分组、历史真实性、任务差异可见、模式与单位一致。
Non-Goals：不重新提交、不编辑历史、不变更调度，不加载节点当前 shell 环境，也不增加自动探测请求。历史未保存预检报告时不伪造第五步结论。

## Decisions
1. 保留现有独立详情页，将“运行参数”改为“运行配置”。使用与向导一致的分组标题和字段卡片，允许直接跳到各组；不是可编辑的禁用表单。无需为了查看配置逐步点击下一步。
2. 复用 job 快照与托管编排接口，按需加载当前任务，避免一次请求全部完整配置。普通批次不请求 orchestration。保留完整 JSON 为折叠高级详情，但常用字段不依赖它；不增加当前节点环境转储。
3. 客户端展示模板名称版本、模式、镜像或批准环境名、命令、工作目录、登录/显式环境来源、协议、回合启动及错误策略、参数和环境覆盖。未保存的 Python 绝对路径/业务账号不从节点现值推断。
4. 服务端展示无服务/外部/托管来源；托管逐定义展示实例数、旧 max_instances 的按需上限语义、参数/环境、资源、端口及就绪策略。实际地址与位置用单独“实际分配”说明并链接现有服务状态页。
5. 资源展示池标识及可确认的名称、设备类型/型号、独占共享、显存预约、CPU/内存预约与硬上限、客户端执行时限、请求时限及批次并发。0 总时限显示“不限制”，缺失值不误判为 0；字段有明确向后兼容语义时标注默认语义，否则显示未记录。
6. 集合组显示 suite_id（存在时）、本次实际任务清单及回合种子；缺少名称/版本快照明确说明。预检确认不作为伪造历史步骤，仅提示提交预检结果未保存及进入实时调度诊断的入口。

## Risks / Trade-offs
- 快照字段多 → 常用字段优先，命令、参数与环境可折叠；小屏换行且横向溢出有边界。
- 请求竞态与任务过滤 → 参数选择以完整批次任务为源；切换清空旧内容并取消过期响应。
- 旧快照不全 → 明确未记录，不读取实时模板补历史。已有后端响应不足时只扩展授权只读投影，不新增数据库字段。
- 敏感配置 → 沿用既有本人/管理员授权；常规视图环境变量默认收起，不加载 Worker/SSH 凭据或节点全量环境。

## Migration Plan
预计仅更新前端；若补充只读响应，先更新兼容 API 再前端。无需 Worker 升级或数据库迁移。回滚前端即可恢复旧参数页。专项 UI 与类型构建检查后，用现有已结束真机批次做浏览器只读验收，不再启动设备业务。
