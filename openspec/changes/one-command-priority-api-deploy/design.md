# Design

入口 `python3 -m scripts.deploy_priority_api --drained` 只处理已存在的 Compose 项目。管理员先停止新提交并排空；脚本再查询 `evaluation_runs` 中活动或未清理执行，非零即退出。旧配置与新四角色配置分别验证，核对所有 API 角色与迁移/初始化镜像一致，使用新迁移镜像读取 head。备份以新建文件独占创建，校验归档后才停止旧入口，避免无效备份导致停机。数据库配置上调后复核 `max_connections>=200`，迁移完成复核 current=head，再等待新服务健康。

环境文件、项目名和原/新覆盖文件由参数指定，不猜测用户的私有覆盖。脚本不输出环境文件、数据库密码，不覆盖旧备份。若停止旧 API 后失败，不自动降级或回滚，因为迁移可能包含不可逆数据变化；保留备份供人工恢复。

专项测试替换 Compose 执行器，验证顺序、活动执行拒绝、备份失败拒绝、新旧覆盖校验。真实部署需要维护窗口以及健康和业务验证。
