# Design

## Context

见 proposal.md。job_resources.Request 已包含 cpus/ram_gb/gpu_mode/requested_vram_gb/required_gpu_model，批次和编排保存任务资源快照；独立服务部署仍有独立解析路径。TemplateCreate/ServerCreate 未定义资源契约。现有 Worker 能力声明不包含 NPU 执行，不能将遥测中的 NPU 变成可领取 GPU 任务的槽位。

## Goals / Non-Goals

建立同一资源契约在全部提交入口的一致性，避免不同页面分别填默认值。保留单加速设备任务粒度；跨卡 gang 调度、CPU 核绑定、硬件级切片和利用率百分比硬限制不在本期。CPU 核数和内存为申请额度，不把设备独占描述成整机独占。

## Decisions

1. **契约独立于执行命令。** 模板增加版本化 resource_requirements，包含 CPU/RAM 的 minimum、default，accelerator 的 type(gpu/npu)、memory minimum/default、mode(shared/exclusive)、可选型号，以及 allow_overrides 白名单。默认值不得低于下限；类型与模式默认锁定，仅显式开放才能修改。资源字段不从业务参数名猜测。
2. **单一解析模块。** 后端解析顺序为模板默认→提交显式值→集合单项显式值，最后验证最低要求、覆盖权限和资源池限制。模板缺失时完整沿用旧逻辑。显式零、空值和未传值分别处理，不能以 truthy 合并。解析结果包含有效值及来源，由预检、提交、重试和服务启停共用；服务 restart 使用已保存快照。
3. **加速类型与账本。** 新契约使用 accelerator_type/memory 等中性字段，对旧 GPU 字段提供集中兼容转换，冲突双写拒绝。设备使用 Agent 稳定 ID、类型、型号和能力；旧 GPU 槽位身份、任务和租约不重写。迁移增加可空/默认字段，并在兼容层映射旧 NVIDIA 任务。
4. **占用规则。** CPU/RAM 按节点有效预留求和；设备共享按预留内存、系统保留和有效遥测准入，独占持有整个设备。资源释放须有清理确认。不能用瞬时低利用率替代资源预留。客户端与服务端同时占用时用同一账本联合预检。
5. **执行能力门禁。** Agent 上报硬件及采样时效；Worker 上报 GPU/NPU 与 host/docker 后端能力。NPU 后端只接收分配设备和节点批准的驱动/运行时映射，不传整机所有设备。不具备必要驱动、隔离或共享能力时明确列出原因；不得静默按 GPU 模式运行。协议升级采用现有版本管理机制。NPU host 采用管理员明确批准的系统级 Worker 管理 systemd unit，业务进程用指定非 root 用户运行，DevicePolicy=closed 与逐设备 DeviceAllow 限制访问，配合 ASCEND_RT_VISIBLE_DEVICES。该系统级后端同时验证 cgroup v1/v2 的 CPU/RAM/pids 实际约束；普通用户 GPU host 后端保留 v2 委派要求。后台能力探测和启动前检查均验证未分配设备不可打开，不能只设置可见性变量。
6. **界面与语义。** 注册和只读查看增加“资源要求”分组。常用字段为 CPU、内存、GPU/NPU、型号、设备内存和共享/独占；高级区域设置最低值和覆盖权限。提交向导带出默认值、锁定项和来源，超界就近提示。服务实例共享与设备共享使用独立标签和解释。

7. **纳管与权限。** SSH 检查阶段读取用户控制器并启动有界验证任务；需要委派时展示修复计划并检查 sudo。确认纳管、平台停用该节点后，写入专用用户级 systemd 委派 drop-in，刷新用户管理器再实际验证。配置幂等、拒绝覆盖冲突文件、不修改启动参数、不重启节点。cgroup v1 等不能在线修复的条件标记待维护。Docker 不走用户 systemd 委派流程。Worker 升级后由后台宿主机环境检查重新验证，未通过的环境不可调度，Agent 不持有提权密码。

## Risks / Trade-offs

- [仅某个入口校验导致绕过] → 单任务、集合、编排、独立服务及重试均以同一解析和持久化契约验证，参数化集成测试比对预检与实际任务快照。
- [GPU/NPU 共享不保证显存硬隔离] → 清楚展示预留语义，仅允许已声明共享执行能力的后端，实际异常保留占用直到清理。
- [迁移影响历史任务] → 使用旧数据库快照演练升级、旧字段兼容和恢复；活动任务不重算需求。
- [当前 NPU 机器不可用] → 开发时可做模拟契约测试，但真实后端验收任务保持未完成，不将模拟测试当作物理 NPU 通过。

## Migration Plan

先定义解析契约和接口一致性测试，再增加兼容数据模型、设备能力及执行适配；更新模板/向导/查看。隔离环境回归和旧库迁移通过后，等当前持续验收结束，按排空流程升级一台试验节点，再扩至授权节点。分别记录 NVIDIA/NPU、host/docker 的实际验证结果。未验证组合不得宣告可用。
