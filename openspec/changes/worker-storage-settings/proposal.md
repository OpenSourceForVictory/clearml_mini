# Proposal

## Why

目前机器注册后只能在宿主机 JSON 中设置 `workspace_root`，资产和缓存被固定在其子目录，界面无法获知配置是否有效。需要让管理员在机器管理中选择工作、资产和缓存目录，并由真实 Worker 校验、报告和安全切换，便于多卡机器复用大型仿真资产。

## What Changes

- 为已注册机器增加版本化存储配置：工作基目录、资产目录、缓存目录及最低可用空间，管理员可在页面修改。
- 展示期望配置、每卡实际配置、校验结果、空闲空间与最后报告时间；保存不等于已生效。
- Worker 主动取得配置，空闲并完成遗留执行清理后才切换；待切换槽位停止接收新任务，已有任务继续使用原路径。
- 支持每台机器不同的宿主机路径，保持客户端容器内资产/缓存路径稳定；多卡执行目录隔离，资产/缓存可共享。
- 保留旧配置与旧 Worker 的兼容性；不移动恢复状态、不自动搬迁或删除任务数据、不下载资产。

## Capabilities

### New Capabilities

- `worker-storage`: 机器级存储配置、Worker 路径校验与确认、逐卡安全生效和存储状态展示。

### Modified Capabilities

无。已有平台注册、任务持久化和恢复要求保持不变；本变更新增存储配置及准入约束。

## Impact

- 后端：`core.py` 的 Worker/Slot 模型与 Alembic 迁移、`execution.py` 管理接口与心跳协议、`scheduling.py` 准入。
- Worker：`workspace.py` 路径解析/权限/磁盘检查，`client.py` 配置确认、容器挂载和执行路径快照；标准库实现。
- 前端：`main.tsx` 机器管理和资源状态，增加存储表单及逐卡生效状态。
- 安装文档、恢复/调度/API/浏览器测试；不改变任务提交契约或新增 SSH 管理依赖。
