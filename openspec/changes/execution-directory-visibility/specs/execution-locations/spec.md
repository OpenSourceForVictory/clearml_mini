## Purpose

帮助有权限的用户从任务及批次详情准确定位某次执行在计算节点上的数据目录，明确任务、执行尝试和实际执行身份之间的区别，并在历史目录迁移、扫描延迟和数据清理时提供可信的状态提示。

## ADDED Requirements

### Requirement: 按尝试展示执行身份
系统 SHALL 在任务详情及批次任务排查中展示所选尝试的执行 ID，区分任务 ID 和尝试记录 ID，未分配时明确提示未分配。

#### Scenario: 重试后查看旧尝试
- **WHEN** 用户选择之前一次执行尝试
- **THEN** 展示该尝试的执行 ID，不能显示最新重试的执行 ID

#### Scenario: 任务尚未分配
- **WHEN** 所选尝试尚无执行 ID
- **THEN** 显示尚未分配，不提供空值复制按钮

### Requirement: 展示有来源的实际目录
系统 SHALL 根据所选尝试的节点目录上报显示宿主机路径、扫描时间和数据状态，不根据节点当前配置拼接历史目录，不要求记录存在清理操作。同一尝试存在多个上报路径时 SHALL 列出各记录。

#### Scenario: 未执行清理的记录
- **WHEN** 目录已上报且尚无清理状态
- **THEN** 用户仍可查看该目录路径与扫描状态

#### Scenario: 工作目录已修改
- **WHEN** 节点当前工作目录不同于所选历史执行上报目录
- **THEN** 展示历史上报路径，不替换为节点当前目录

#### Scenario: 目录未上报或已删除
- **WHEN** 没有上报记录，或记录表示数据已清理、缺失
- **THEN** 分别展示目录尚未上报或对应清理、缺失状态，不承诺文件仍存在

### Requirement: 权限和可复制文本
系统 SHALL 限制任务目录查询为任务所属用户或管理员，并在两个详情入口提供执行 ID 和每个已知路径的复制按钮。剪贴板失败 SHALL 明确提示并保留可选择的原文。

#### Scenario: 越权读取
- **WHEN** 其他普通用户请求该任务目录
- **THEN** 返回与任务不可见一致的拒绝响应，不泄露目录信息

#### Scenario: 复制成功或失败
- **WHEN** 用户复制执行 ID 或路径
- **THEN** 成功时反馈已复制，浏览器拒绝时提示手动复制且不报告成功

### Requirement: 标明目录用途
系统 SHALL 明确路径为节点宿主机数据目录，不等同于业务启动 cwd 或容器内路径；回合目录存在不代表每回合完整日志已经单独保存。

#### Scenario: 多回合任务查看目录
- **WHEN** 用户查看逐回合启动任务的执行目录
- **THEN** 页面说明 work/episode-N 与 output/episode-N 的用途，以及控制台日志仍按整次执行采集
