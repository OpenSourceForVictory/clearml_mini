## Context
Planner.structural_pair 排除忙碌与遥测，仅证明某些容量配置不可能同时满足，但当前返回 bool/None 并丢弃原因。
## Decisions
抽取同一判定遍历产生结构性原因；原 public bool/None 保持兼容，新增诊断接口提供一组安全的类别。失败消息包含 case、服务逻辑名及用户已经选择的池名。候选缺失仍返回 None，留给预检的角色/池环境提示；仅全部明确 False 才拒绝。所有原因都基于配置，不输出节点私有地址、凭据或临时占用。
## Risks / Trade-offs
多个候选组合可能各有不同阻塞原因，提示列出可能的配置障碍而非宣称某一项是唯一根因；现场配置仍需核对。原调度与预留逻辑不改。
