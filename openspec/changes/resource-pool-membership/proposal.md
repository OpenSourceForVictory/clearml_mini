# Proposal

## Why

目前 GPU 注册必须提供资源池，管理员在平台发现设备之前就要决定归属；换池需要修改宿主机配置。需要把机器接入与资源分配分开，让管理员在平台按实际设备加入、移除和调整资源池，并保护正在执行的评测。

## What Changes

- 支持机器及 GPU 不指定资源池先纳管，展示未分配设备；安装工具支持一次选择多张 GPU，沿用每卡一个 Worker 实例。
- 注册页面明确真实/模拟设备，提供可编辑的 Worker 接入地址和连通性检查，避免直接把浏览器隧道地址当成接入地址。
- 新增资源池管理子页签，按整机已登记 GPU 或选定 GPU 批量分配；一个槽位同时只属于一个资源池，同机不同卡可分属不同池，池允许混合型号。
- 管理员可移除、换池；立即停止新准入，未领取预留回队列，已有执行及遗留清理结束后才改变实际归属。
- 展示实际/期望归属、未分配/排空状态、离线及存储阻塞；池展示设备型号分布和运行/排队统计。
- 平台管理过的归属不会被 Worker 重连时的旧本地 pool_id 覆盖；保留未托管的旧 Worker 配置兼容。
- 完成验收后部署到现有 API、前端及两台 Worker，并验证真实页面与现有池归属。

## Capabilities

### New Capabilities

- `resource-pool-membership`: 未分配 GPU 的纳管、单池归属、批量成员管理、排空迁移及状态展示。

### Modified Capabilities

无。已有异构槽位、任务持久化和执行恢复要求不变。本次不修改主规范中遗留的 ClearML 实现描述。

## Impact

- `core.py`/Alembic：可空 Slot.pool_id、版本化期望归属和变更审计。
- `execution.py`/`scheduling.py`/`main.py`：注册兼容、成员管理、准入和资源汇总。
- `worker/client.py`、`scripts/install_worker.py`：无池接入、多卡安装、API 连通性诊断；不改变执行 SDK。
- React 管理设置/计算资源、文档及单元、PostgreSQL 并发、浏览器、双机验收。
- 无新基础设施依赖；沿用现有机器凭据，不在本次引入一次性邀请认证、自动镜像分发或远程 SSH 管理。
