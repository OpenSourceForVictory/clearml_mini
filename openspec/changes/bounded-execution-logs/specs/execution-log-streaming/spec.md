## Purpose
为宿主机和容器执行提供可持续观察的有界日志，保留最新诊断信息并标识缺口，使日志采集和上传不会阻塞心跳、取消与执行结果上报，同时支持旧版本平滑升级。

## ADDED Requirements

### Requirement: 有界日志保留
系统 SHALL 限制单执行日志的节点和平台占用，并在淘汰旧日志后继续接收最新输出，明确显示缺口。
#### Scenario: 持续大量输出
- **WHEN** 宿主机或容器程序输出超过保留窗口后打印最终错误
- **THEN** 用户能看到最新错误和已截断提示，单执行存储不随总输出无限增长
#### Scenario: 标准错误
- **WHEN** 服务仍运行并写入标准错误
- **THEN** 日志面板能在运行期间看到该内容及输出流标识

### Requirement: 日志与执行控制隔离
系统 SHALL 使慢日志请求不阻塞有效心跳、取消和结果处理，缓存满时记录缺口而非无限堆积。
#### Scenario: 上传超时
- **WHEN** 日志上传连续超时但心跳接口可用
- **THEN** 业务继续按有效租约执行，取消仍生效，日志内存和磁盘占用保持有界
#### Scenario: 结果在大量输出之后产生
- **WHEN** 程序输出超过日志窗口后上报回合事件、最终结果并退出
- **THEN** 回合与结果不因展示日志被淘汰而丢失，保持现有协议判定
#### Scenario: 恢复执行在断联期间退出
- **WHEN** 容器业务在 Worker 与平台断联期间退出，连接恢复后控制确认先于诊断日志尾部完成上传
- **THEN** Worker 在有界期限内补传最新日志尾部，成功上传后才报告日志完整；期限内仍失败则标记缺口，但不阻止原执行结果和清理
#### Scenario: 恢复执行租约过期后的日志补报
- **WHEN** 原 Worker 在断联恢复授权仍有效、执行尚未终态时补报日志，但普通执行租约已过期
- **THEN** 平台按原 Worker 与槽位绑定接受恢复日志；未授权、授权撤销或终态后的新日志仍被拒绝

### Requirement: 幂等与权限
系统 SHALL 按执行隔离日志上传、重试和游标，拒绝越权、序号冲突和已关闭执行的新写入。
#### Scenario: 响应丢失后重传
- **WHEN** Worker 重传已接收的同序号同内容日志块
- **THEN** 不重复展示；同序号不同内容被拒绝
#### Scenario: 删除与上传并发
- **WHEN** 批次删除与迟到日志请求并发
- **THEN** 不产生孤立记录，不恢复已删除任务，不因外键竞态导致 500

### Requirement: 游标读取与版本兼容
系统 SHALL 支持客户端和服务实例按尝试增量读取，并兼容旧 Worker 及历史记录。
#### Scenario: 游标已被淘汰
- **WHEN** 用户携带早于当前窗口的游标读取
- **THEN** 返回明确缺口及可用日志窗口，不静默漏报或无限等待
#### Scenario: 关闭或切换日志
- **WHEN** 用户关闭面板或切换尝试
- **THEN** 停止旧轮询且迟到响应不会串入新面板
#### Scenario: 混合版本
- **WHEN** 旧 Worker 上报旧日志协议
- **THEN** 更新后的 API 保留旧接口语义，界面可读取历史日志
