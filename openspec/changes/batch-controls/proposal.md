# Proposal

## Why

批次已经可以查看等待原因和补跑失败任务，但用户还需要逐项取消，无法暂缓整批后续执行。增加批次控制，方便调整评测计划并及时释放不再需要的资源，同时保持执行历史和清理保障。

## What Changes

- 批次增加持久化调度开关和控制版本，提供暂停、恢复及整批取消 API，仅本人或管理员操作。
- 暂停阻止新准入，撤回尚未领取的预留；已领取的任务继续执行。恢复只重新允许调度，不复活终态任务。
- 整批取消先暂停调度，再取消等待任务、向已领取任务发出取消请求；保留成功、失败和历史结果，等待 Worker 确认资源清理。
- 控制请求携带预期版本，避免网络重放或旧页面操作覆盖之后的控制决定。
- 批次列表/详情展示调度状态、暂停原因、待停止/清理数量和操作反馈；整批取消需页面内确认。
- 增加迁移、数据库竞争测试、浏览器与真实双机验收，以及中文使用/回退说明。

## Capabilities

### New Capabilities

- `evaluation-batch-control`: 批次暂停、恢复、取消及其与调度、领取、重试、监控的协调语义。

### Modified Capabilities

无。现有平台通用权限和执行清理要求保持不变；本能力补充 CS 批次控制行为。

## Impact

涉及 EvaluationBatch 模型和 Alembic、scheduling.tick、execution.claim、单项取消共用逻辑、批次 API/monitor、CS 摘要及详情界面。沿用 PostgreSQL 调度事务锁和现有 Worker 取消协议，不增加外部依赖，不要求升级 Worker。不实现进程挂起、回合断点续跑、自动重试或定时运行。
