## Decisions
新增可选 instance_count（1–20），与旧 max_instances 互斥。界面新提交总是携带 instance_count，旧请求/历史快照保持按需上限。新快照同步保留 max_instances 作为安全上限。
正常客户端/服务配对调度后，单独补足显式目标的服务实例；使用同一 Run 资源账本及事务锁，每个新增服务仍验证卡、节点、CPU/内存、端口及全局/用户并发。若没有活跃客户端，补实例需要留出至少一个客户端的配对容量，避免服务吃满资源导致死锁。暂停、终态或账号停用不补实例；失败和手动停止记录占目标位置，不自动绕过显式恢复。已有正常实例就绪即可运行客户端，不等待全部实例。
详情返回目标、已创建、就绪、启动中、失败/停止、待创建，并在未足额时继续返回服务资源诊断；每实例显示 ID、地址、节点和设备。
## Validation
共享两实例、客户端并发1也补服务、资源不足后恢复、全局上限、重复 tick 幂等、暂停/结束不补、故障不自动复制、旧上限兼容、API无效值和界面目标计数。只专项验证，不宣称覆盖率达标。

## 实例列表补充（用户追加）
服务端与关联以每个实例一行展示：名称/唯一ID、逻辑服务、节点及设备、地址、调度与运行状态、就绪诊断和操作。日志在所属实例行下展开，异步结果只更新对应实例，错误不清空其他实例日志。缺失目标仍展示数量和调度诊断，不能伪造尚未创建的实例ID。

## 逐回合显示补充（用户追加）
批次任务行增加展开回合入口，按需读取最新尝试的分页回合记录。episodes 接口增加 include_planned 可选参数，以固定计划回合区间分页并补充未上报占位，不修改已有事件或旧分页行为。返回判定来源（协议/退出码）、执行状态和上报能力。协议回合按 success 布尔值判断目标结果，ERROR 为执行异常；普通命令逐回合由现有宿主机适配器的退出码报告判定执行成功，普通一次启动只展示整次执行，不虚构多个回合。终态但仅有 STARTED 标记未上报结束，不继续声称运行中。

## 退出码与位置补充（用户确认）
服务实例行明确展示实际执行分配的节点名和 GPU/NPU 卡号，待分配标注等待调度，未知历史位置不推断。执行完成接口添加可选 exit_code 并独立保存到 Run 可空整数列；旧 Worker/历史记录为未知，不能由状态猜测。逐回合适配器在进程 wait 后记录实际子进程退出码（包括协议缺失时的 0）；纯 SDK 内部回合没有子进程时不虚构。事件增加可选 exit_code，STARTED 不允许。整次执行退出码与回合进程退出码分开展示，协议缺失不因退出 0 判为成功。此项需要迁移 x407a89；部署 API 后更新 Worker/Runner 才能获得新上报，不能仅更新前端。
