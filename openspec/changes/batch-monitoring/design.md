# Design

## Context

动机与范围见 proposal.md。当前 batch_view 返回所有 case 及最新尝试进度，CSWorkbench 将每个批次的完整表格直接展开。EpisodeList、ArtifactList 和主界面任务详情已有尝试级内容。preflight.inspect_batch 面向新提交请求，不能直接用于已提交任务：其校验依赖当前模板/集合，而历史任务应该使用快照；同时缺少已有批次的并发占用判断。

现有单任务 retry 在调度锁与用户行锁内检查终态、cleanup_confirmed 及额度，再创建 Run。它没有 expected_run_id，因此批量操作需要额外的尝试前置条件，不能只循环调用当前 HTTP 接口。

## Goals / Non-Goals

**Goals:** 共享准入判定，新增只读监控视图；每次请求共用一个资源快照，避免按每个任务重复查整台机群；复用尝试级数据接口；批量操作与单项重试互斥。

**Non-Goals:** 不改变调度优先级、公平轮转、任务执行协议或结果存储，不通过日志文本猜测具体基础设施故障根因，不以本功能替代真实模型评测。

## Decisions

1. **独立监控接口。** 新增 GET /api/v1/batches/{id}/monitor 返回 checked_at、现有批次数据、配置摘要、summary 和逐任务诊断。保留现有批次列表与详情接口字段，以免破坏向导试跑或脚本。列表改为摘要和“查看批次”入口，只为当前展开批次轮询 monitor；日志、回合和产物按用户选择加载。相比扩大所有列表项的每次响应，这样限制诊断和渲染成本。
2. **共享诊断上下文。** 从 preflight 提取资源快照和诊断函数，供提交前与监控使用。一次批量读取占用、槽位、机器和任务；在内存按 owner、node、slot、batch 计数，未确认清理的 Run 仍占额度。对每个 PENDING Job 使用保存的 client_spec 和资源要求，复用 eligibility_codes、slot_codes、node_codes 和 endpoint_conflict。新增 batch_concurrency、pool_disabled、owner_disabled、awaiting_scheduler 原因；不对已有任务重新检查新提交积压限额。非 PENDING 不做等待诊断，只返回阶段和所属节点。预检保持原行为，不将新提交批次错算为已达并发。
3. **统计口径。** 对最新 run_id 批量读取回合记录，计算完成回合、目标成功/失败、ERROR 回合及有回合报告的任务数。执行失败任务数独立统计 FAILED/TIMED_OUT；未知故障只展示原错误，不自动将它归为模型失败。成功率为 successes/completed，而非各任务成功率平均；分母为零返回 null。总计划回合包括未上报客户端，同时展示上报覆盖情况；重试后最新进度可能下降，界面注明按最新尝试统计，历史可查。
4. **详情导航和轮询。** 采用当前应用内 hash 路由如 #/cs/batches/{id}，避免静态服务刷新路径 404，不引入新路由依赖。从列表、提交成功和试跑结果提供详情入口，返回列表保留本会话的运行草稿、页码及过滤条件；刷新恢复批次定位，不承诺草稿跨刷新保存。详情顶部摘要，下方任务搜索/筛选和排查区，复用现有组件，按 job_id/run_id 固定查询。2 秒轮询仅在视图活动时工作，前次请求未完成不叠加，标记代次拒绝旧响应；失败保留数据并提示更新时间。
5. **安全批量重试。** 新增 POST /api/v1/batches/{id}/retry-failed，body 为 1–100 项唯一 {job_id, expected_run_id}。归属或批次成员验证在写入前完成；随后持有同一调度锁和 owner 行锁，按稳定任务顺序判断状态、最新 run_id、清理和剩余额度，创建允许项的新 Run 并返回 retried/skipped（稳定代码和中文原因）。全部结果在一个事务提交；额度不足或状态变化只跳过对应项，不导致已允许项隐式回滚。expected_run_id 令重复请求最多产生一次副作用；重复响应可返回 attempt_changed 和当前尝试，而非承诺逐字相同响应。提取单任务重试内部函数共用，保留原单项 HTTP 契约及 CANCELLED 的单项重试能力。
6. **批量选择。** UI 提供选择执行失败/超时任务、展示待补跑数量和逐项结果。只提交用户实际选择且捕获的 expected_run_id，失败响应重试复用原请求，轮询不悄悄更新已选尝试标识；已过期选择由服务端拒绝并在界面说明。目标失败但任务执行完成不会自动选中。

## Risks / Trade-offs

- [实时解释与调度状态变化] → 展示 checked_at，不承诺预留、顺序或 ETA，用固定时刻场景测试与调度一致性。
- [批量请求每项扫描数据库导致延迟] → 共用上下文、批量读回合，覆盖最大 100 项的查询次数和响应验收；禁止为每项重复加载全部占用。
- [重试后完成率下降被误解] → 最新尝试口径明确标注，历史尝试可独立查看。
- [前端旧响应串任务] → 批次、任务、尝试为查询键并丢弃过期响应，测试快速切换和断网。
- [重复补跑或绕过清理] → 共用锁和校验，PostgreSQL 并发测试覆盖批量与单项竞争、旧请求重放和额度耗尽。

## Migration Plan

无需数据库迁移。先完成后端、浏览器和 PostgreSQL 并发回归；在隔离部署通过真实 Docker 制造执行失败、排队和清理等待，再补跑验收。保留旧 API 镜像与代码备份后部署，使用专用验收集合检查双机监控和结果入口，不修改原集合或节点配置，清理测试服务并记录证据后 Git 提交。
