# 全量测试设计

所有条目为待实施/执行的验收用例，本文不是通过记录。单元测试验证纯契约；SQLite API测试验证事务与权限；并发必须使用独立PostgreSQL；真实执行采用受控测试任务，不使用生产业务结果充当软件测试。

| 编号 | 模块 / 场景 | 必须断言 |
| --- | --- | --- |
| P01 | string/integer/number/bool/enum/object/array，空值、NaN、超长 | 类型严格、边界正确、错误包含字段不泄露值 |
| P02 | 模板/集合/case/运行四层覆盖 | 最终值及来源准确、对象整体替换、输入不被修改 |
| P03 | 非overridable覆盖、未知字段、平台保留键 | 拒绝，未创建任何执行 |
| P04 | 客户端/服务端同名业务字段 | 各自保持独立值，不跨端合并 |
| P05 | argv空格/引号/分号/美元符号及bool/array映射 | 逐参数传递，无shell求值、无二次展开 |
| P06 | env与业务映射冲突、设备变量和平台地址覆盖 | 配置阶段拒绝 |
| P07 | 模板路径、不同节点资产路径、Docker挂载路径 | 程序获取执行空间实际路径，无需知道宿主机目录 |
| P08 | 普通程序JSON读取、SDK读取、本地dry-run | 相同有效输入，不要求网络或管理凭证 |
| P09 | 调整业务batch_size但资源申请不变 | 调度账本保持原资源申请 |
| P10 | 每case资源覆盖、未支持的设备类型 | 正确预留或明确拒绝，不虚报NPU执行能力 |
| C01 | 复制集合/客户端模板/服务端模板 | 新ID、独立草稿、完整schema/默认/运行设置 |
| C02 | 编辑草稿、发布、同版本冲突 | 乐观锁正确，发布后另存版本修改 |
| C03 | 两页面同时编辑 | 一个成功一个冲突，不丢输入 |
| C04 | 私有源越权、公共源复制 | 无越权，副本私有，不继承管理员权限 |
| C05 | 修改参数类型/删除字段导致case不兼容 | 定位受影响任务，拒绝静默丢值 |
| C06 | 发布新版本后查看旧运行 | 旧参数、映射和模板快照均不变 |
| A01 | none/external/managed，各种集合来源 | 正确任务清单与配置，一次原子提交 |
| A02 | 一项服务/任务非法、端口固定约束冲突 | 完整回滚，无孤儿集合或服务 |
| A03 | 相同键并发提交和响应丢失重发 | 单一批次，无重复实例或任务 |
| A04 | 同用户同键不同内容、不同用户同键 | 前者409，后者独立 |
| A05 | 提交成功后模板停用再重发 | 返回原结果，不重复验证并重建 |
| A06 | 预检前后表行数/端口/资源账本 | 无持久化变化，无网络探测 |
| A07 | 普通用户可用模板选项及关联日志控制 | 仅允许使用公开/自有模板与自有实例 |
| A08 | 服务端协议与客户端不兼容 | 预检及提交都拒绝 |
| S01 | 服务+客户端跨节点/同节点共享可容纳 | 资源预留准确，健康前客户端不领取 |
| S02 | 同卡独占或CPU/RAM/用户配额确定不可满足 | 预检解释冲突，不能启动堵死资源的服务 |
| S03 | 暂时被其他任务占用 | 可提交排队，释放后自动启动 |
| S04 | 两调度器竞争、联合预留转普通预留 | 无双分配、无双扣、总资源不超预算 |
| S05 | 全局/用户/节点额度恰好边界 | 正确等待或准入，服务启动也计入账本 |
| S06 | 独占服务多个客户端及旧执行清理延迟 | 同时一个占用，清理前不释放 |
| S07 | 共享服务多个客户端与独占冲突 | 可共享时并行，存在独占时阻塞 |
| S08 | 不同case引用不同服务配置 | 只选择允许服务，启动参数不串用 |
| S09 | 独占副本按需扩展、批次公平轮转 | 不预先占满集群，不超过并发/副本上限 |
| S10 | 端口数据库竞争、实际bind被占、范围耗尽 | 无重复预留，有界恢复，失败可诊断 |
| S11 | 无健康/过期健康/旧服务执行健康/节点离线 | 新客户端不领取，正在运行者保留原绑定 |
| S12 | 分配后领取前服务失效 | 拒绝领取，预留可回收，无僵死地址占用 |
| S13 | API/调度器重启及重复reconcile | 依靠持久化状态恢复，不重复创建实例 |
| L01 | 启动服务失败/健康超时 | 释放未用客户端预算，服务预算待清理，错误可见 |
| L02 | 暂停/恢复 | 不再启动客户端，服务保留，恢复继续 |
| L03 | 排队/预留/启动/运行各阶段取消 | 客户端和联合预留正确清理，服务按策略处理 |
| L04 | 全部客户端结束但一项未清理 | 不提前停止依赖服务或释放其预算 |
| L05 | stop_after_batch与keep_running | 前者清理后停止，后者保留且显示占用 |
| L06 | 外部服务批次取消/结束 | 不发送部署或停止外部服务命令 |
| L07 | 自动停止后重试、故障后显式重启 | 不混淆自动停止与用户停止，新增服务执行后再绑定 |
| L08 | 服务运行中失败及客户端重试 | 无静默换址，历史服务执行ID不变 |
| E01 | 普通命令退出0/非0/超时/取消 | 正确终态，不要求final指标，不伪造回合 |
| E02 | SDK命令与原生回合上报 | task/seed/episode准确，目标成功率与执行成功分离 |
| E03 | 宿主机与Docker两端模板组合 | 输入语义相同，路径/环境/端口各自正确 |
| E04 | Worker旧协议与新输入能力 | 不领取不支持的任务，旧CS路径继续通过 |
| E05 | 最小服务回显实际接收的case/参数/客户端ID | 与批次快照及绑定一致，无手工地址传递 |
| U01 | 五步向导前进/返回/刷新数据 | 草稿不重置，普通路径无节点/端口必填 |
| U02 | 来源切换、类型化字段、复制编辑取消/保存 | 隐藏字段不误提交，新版本成功后才切换 |
| U03 | 修改配置后预检迟到、提交响应丢失 | 旧结果不覆盖、幂等键重用、不重复任务 |
| U04 | 排队/服务未就绪/执行关系和日志 | 用户能区分等待原因并看到真实绑定 |
| U05 | 桌面/窄屏/键盘和普通用户权限 | 关键操作可达，无管理员控件误开放 |
| R01 | 旧批次/外部地址/独立服务/集合导入/报告 | 原行为不回归 |
| R02 | 数据库升级、旧数据读取、受控降级 | 无伪造关系，活动编排禁止不安全回退 |
| R03 | 三任务、两执行节点、多个批次连续提交 | 参数准确、并发受控、排队能推进、清理后资源归零 |
| R04 | 后端全量、TS/构建、Playwright、真实执行 | 分别记录结果；跳过项说明环境，不宣称全场景通过 |

验收证据记录代码提交、测试命令、环境、通过/失败/跳过数量、样例批次ID及故障恢复结果。新失败修复后重跑受影响模块，再做最终全量回归；不要用放宽超时或只跑模拟API掩盖执行问题。
