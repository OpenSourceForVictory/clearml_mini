# Design

同一独立PG200、相同硬件与12进程/168连接、100用户/100节点/100Worker及100任务批次。A原配置；B执行控制排队/取连接各1秒；C在B基础上观察/日志入口等待1秒、取连接0.5秒，同时批量/观察队列分别从24/48增至96/128以容纳100节点同时到达的突发（C不作为只改等待的单因素对照）。其他参数不变；控制SQL4秒和HTTP5秒不变。各档60秒、日志排空10秒，之后根据证据选择与复测，优选档有界持续验证180秒。若没有收益保留原值，不预设必须调大；不修改调度锁行为或放宽测试通过判据。

指标包括分类成功/503原因、成功P99、心跳最大间隔、日志最大积压年龄/最终积压、任务和恢复流程完成。仅增加等待不能解决scheduler_lock，区分此类与request_concurrency、connection_pool。基准对照保留失败证据。部署前确认无活跃执行、备份，逐角色健康和节点回连，异常回退原配置。

A/B实测均通过，但心跳P99约0.476/0.478秒，503为22/26且均为调度锁；没有证据支持扩大控制等待。增加D对照：保留C的观察/日志队列调整，恢复控制等待0.5/0.5秒，与C及A同负载比较后复验。
