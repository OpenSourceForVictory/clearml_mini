# Design

## Context

动机见 proposal.md。Job.client_spec 已保存任务、种子、参数和客户端快照；Run/EpisodeRecord 按尝试记录结果。monitor 按最新尝试批量聚合，但还加载实时资源诊断，报告不应依赖调度诊断。现有集合导出只导出清单，产物接口按尝试下载，尚无批次结果导出。外部服务 checkpoint 不在平台控制范围内。

## Goals / Non-Goals

**Goals:** 同一份报告的状态、尝试和结果一致；比较条件透明；最多两个批次各 100 项的查询和响应有界；复用已有权限与统计口径。

**Non-Goals:** 不保管报告快照、不导出所有历史尝试或逐回合事件、不打包二进制产物、不统计自定义指标平均值、不建立模型注册表。下载文件本身是该时间点快照；再次请求可能产生新结果。

## Decisions

1. **专用只读聚合。** 新增报告模块，批量获取最新 Run 和按 run_id 分组的 EpisodeRecord 计数，不调用资源诊断。JSON 包含 schema_version、generated_at、batch、summary 和 cases；每项包含 job_id/run_id/attempt、任务定义标识、状态、计划/完成计数、成功率、上报标志及可公开的运行配置。参数仅输出规范化摘要供复核，不导出原始 parameters/environment、命令、挂载路径或自由文本错误；查询/比较内部使用保存的参数定义。报告不访问文件系统产物目录。
2. **一致快照。** PostgreSQL 使用独立短生命周期只读 REPEATABLE READ 事务，在该事务内核对两个批次权限并读完聚合。鉴权使用既有用户身份，但不能在已经执行鉴权查询的 session 上迟改隔离级别。不取得全局调度写锁；SQLite 测试使用明确读事务。双批次同一事务，完成读取后释放连接再序列化；并发测试验证重试和回合更新不混合。
3. **接口。** GET `/api/v1/batches/{id}/report?format=json|csv`，固定 batch-id 安全附件文件名；JSON 为完整汇总加逐任务，CSV 为固定列的逐任务数据，包含 batch/run 标识、生成时间、指标和参数摘要。GET `/api/v1/batch-comparisons?left_id=...&right_id=...` 返回两个报告及对齐行，左右必须不同，参数数量固定。两接口只读，不创建任务。CSV 用标准库 writer、UTF-8 BOM，字符串首个非空白字符为 = + - @ 或含前导控制字符时加文本保护前缀；数值列保持数值类型。
4. **比较规则。** case_id 联集按稳定顺序对齐；task_name、seed、episodes、规范化 JSON parameters 必须相同。任务双方状态 SUCCEEDED、episode_reporting=true、completed=planned 且 errors=0 才有 delta_success_rate=right-left（页面换算百分点）。不要求 suite_id 相同，因为自定义清单/复制集合也可能一致；suite_id 相同也不跳过快照核对。缺项、定义不同、未上报、未完整成功执行分别返回稳定原因码。整体差值仅在所有项可比时返回，并对原始完成回合加权，不平均各任务成功率。客户端镜像/版本、环境摘要、资源配置和 endpoint 差异单独标记为解释因素；不会把数值差异表述为模型质量结论。
5. **界面。** 详情提供 JSON/CSV 下载，下载通过带现有 Authorization 的 fetch，不将 token 放 URL。列表保存跨分页的最多两个选择，并进入 `#/cs/compare/{left}/{right}`；直接刷新恢复。比较页展示时间、配置差异、两侧汇总、任务对齐/不可比原因与百分点差值，保留返回列表的运行草稿和页码。采用手动刷新而非每两秒改变比较快照，使用请求代次和不重叠刷新保护，错误保留已有快照。下载失败显示错误且不触发空文件下载。

## Risks / Trade-offs

- 参数/环境可能含用户秘密 → 导出仅包含定义/环境摘要，不含原值；比较显示哪些维度不同，不回显任意值。推理地址已由现有契约禁止凭据、query、fragment。
- 相同推理地址可能换 checkpoint → 报告明确“外部模型版本未验证”，用户用批次名称标识实验；不提供虚假的版本溯源。
- 两批次各 100 项、大量回合影响查询 → 使用数据库分组计数、不加载完整事件内容，测试查询预算及边界，不将整批下载实现成逐任务 HTTP 请求。
- 不完整任务暂不能给差值 → 保留两侧原始数据与原因，待完整执行后用户主动刷新。

## Migration Plan

无数据库迁移或 Worker 更新。通过单元、PostgreSQL 一致性、浏览器和隔离容器验收后，备份旧 API 镜像并上线。使用现有专用验收数据做只读报告/比较及下载验收，不修改正式集合或节点；记录证据、清理临时服务并提交。回退恢复原 API/UI 镜像即可，报告接口不写入业务数据。
