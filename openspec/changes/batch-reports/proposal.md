# Proposal

## Why

批次已有进度、回合和产物查看，但用户仍需逐项收集结果，无法方便地导出整批报告或判断两次运行的差异。提供统一报告和显式可比性检查，让不同运行结果可以复核，避免把部分完成、不同任务清单或重试历史混在一起比较。

## What Changes

- 导出批次最新尝试的 JSON 报告及逐任务 CSV，包含生成时间、批次/尝试标识、计划与完成回合、目标结果和执行状态。
- 增加两个批次的并排比较，以 case_id 对齐，核对任务、种子、回合数和参数，显示缺项及配置差异。
- 保持已完成回合加权成功率；未上报、部分执行及不可比项明确标识，不自动做模型优劣结论。
- 详情加入下载入口，列表允许选择两个批次进入可刷新恢复的比较页；支持结果错误提示、权限保护与大集合查询验证。
- 外部推理服务实际 checkpoint 无法由地址推断，报告以批次名称及保存配置标识运行，不声称自动识别模型版本。

## Capabilities

### New Capabilities

- `evaluation-reporting`: 批次报告导出、任务对齐及运行结果可比性判定。

### Modified Capabilities

无。现有最新尝试统计、归属权限、产物下载与控制接口保持兼容。

## Impact

涉及批次/回合只读聚合、报告和比较 API、CS 列表/详情/比较页面及中文文档。不修改 Worker 协议，不新增数据库表，不打包产物文件，不引入报告服务。不实现 PDF、自动自定义指标平均、统计显著性或模型排行榜。
