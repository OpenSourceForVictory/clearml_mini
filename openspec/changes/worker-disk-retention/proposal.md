# Proposal

## Why

任务视频、轨迹和工作文件会持续占用 Worker 磁盘。目前只有空间不足阻止新任务的机制，管理员不能从平台了解各次执行的目录占用，也无法安全地预览和清理已结束执行的数据。

## What Changes

- 在机器管理中查看逐次执行目录占用、扫描时间、可清理状态和阻止原因；区分未扫描、部分扫描、离线旧数据及未知目录。
- 提供管理员清理预览和显式确认；请求绑定执行、目录身份与扫描版本，Worker 复核后异步执行并回报逐项结果。
- 提供机器级保留策略，默认关闭；管理员可设置保留天数、预览到期项后启用，自动清理复用相同的保护规则和审计。
- 只清理已终止、服务端清理已确认、本地恢复完成且无容器引用的执行目录。不删除公共资产、缓存、镜像、凭据或恢复日志，不改变任务结果、已上传产物和历史指标。
- 低空间不自动降低保留期限或删除运行中数据；清理失败、断线和重启能够对账恢复，界面明确不可逆的数据范围及真实结果。

## Capabilities

### New Capabilities

- `execution-data-retention`: Worker 执行数据盘点、清理预览与受保护删除、显式启用的保留策略及审计。

### Modified Capabilities

无已发布主规格需要修改。既有 `worker-storage-settings` 变更中的“系统不自动清理数据”保持为默认行为；本变更新增管理员明确启用保留策略后的例外，目录配置切换仍不触发迁移或删除。合并/归档规格时需保留这一条件，避免无条件自动清理的歧义。

## Impact

涉及数据库迁移、Worker 能力协商与执行收尾记录、存储目录盘点、异步清理协议、管理界面和运维文档。需要升级 Worker，但旧 Worker 仍可评测，展示清理能力不可用。API 不直接访问宿主机文件系统。无第三方存储服务、Docker prune、磁盘硬配额、回合续跑或通用宿主文件管理器。
