# clearml_mini 项目导航

先读仓库根目录 `AGENTS.md`；每次代码变更同步受影响的界面指南、文档或本 Skill 的参考资料。面向用户的说明必须从平台界面可达，不能只让用户去仓库找文档。

按问题选择 [实现与操作索引](references/project-map.md)，只读相关模块。以当前代码、API 返回和测试为事实，历史验收文档不代表当前节点状态。

## 工作流程

1. 识别实体：模板版本、集合版本、批次、任务、执行尝试、节点、设备和服务实例不可混为一谈。
2. 查明数据流：模板/集合快照 → 编排与准入 → 资源预约 → Worker 启动 → 事件/结果 → 清理确认。跨模块改动检查上下游契约。
3. 使用 OpenSpec 记录用户可见行为和验证用例；实现后更新相关指南主题或文档，不修改无关文档充数。
4. 按影响运行测试。协议改动须验证 SDK、命令包装和 Worker/API 边界；界面改动验证草稿保留、权限和失败提示。
5. 发布先检查活跃执行与清理，遵循现有部署配置；不要把 API 更新扩展成所有节点升级。记录实际验证范围，功能完成后提交 Git。

## 必须保持的语义

- 进程退出 0、任务成功、回合完成、业务成功率不同。模拟回显测试不是模型质量验收。
- 资源在清理确认后释放；取消请求不等于可立即重用。服务端同样消耗资源与活动配额。
- 共享显存是预约与准入，不是硬显存隔离；不要承诺无限并发。
- 平台分配端口、服务地址和路径；用户业务无需自行调度。WS 应用消息由业务定义。
- 不在 Skill、指南、样例、Git 或日志中写入凭据，不输出 `.env`、私钥和私有登录文件。
