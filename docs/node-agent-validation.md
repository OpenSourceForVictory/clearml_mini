平台位于本机18000。五节点运行 `mini-eval-agent.service`、`mini-eval-updater.service` 和原 `mini-eval-worker-nfs.service`。Agent状态位于节点本地磁盘，评测工作区继续使用 `/mnt/eval-share`。逐台关闭准入、确认执行清零、安装完整发布、检查摘要和回执，最后恢复准入。

## 自动故障用例

新增 `backend/tests/test_agent_faults.py` 覆盖：

- 配置保存遇到ENOSPC、EACCES、EIO：重复协调不得把未落盘的修订标为已应用；恢复写入后才允许成功。
- 事件写入或确认失败：事件序号和未确认事件保持原状。
- 探测线程长期阻塞：重复采样不增加线程，标记失败，探测恢复后重新得到正常样本。
- 程序启动超时或非零退出：限制重试频率，恢复后只启动一次。
- 程序状态unknown/activating/deactivating：不发出破坏性控制命令。
- 非法持久化结构：拒绝加载、保留原文件、释放实例锁以便修复。
- 非法JSON和超大API响应：拒绝处理。
- 并发事件写入与确认：序号唯一、缓存有界、落盘与内存一致。
- 凭据/会话失效：退出控制循环，不继续操作Worker。

新增API跨模块回归验证：Agent过期阻止新任务但不阻止既有执行续租；重复心跳不能刷新过期时间，新序号才能恢复在线。另有显式启用的真实挂载丢失集成用例。

本轮故障测试发现配置/事件持久化先修改内存的问题。修复为构造候选状态、原子持久化成功后再发布到内存；配置和`config_applied`事件同一次提交。写入失败保留此前已确认的内存状态，不能靠第二次重试绕过持久化。

## 连续观测方法

可重复运行只读脚本，密码通过环境变量提供，不写入命令示例或输出文件：

```sh
python scripts/observe_node_agents.py \
  --api-url http://127.0.0.1:18000 \
  --password-env MINI_EVAL_ADMIN_PASSWORD \
  --duration 600 --interval 5 \
  --node local4090-151 --node rtx3080-182 --node rtx4090-157 \
  --node rtx4090-183 --node rtx8000-177 \
  --output /本地记录目录/agent-observation.jsonl
```

逐行记录节点心跳年龄、序号、期望/应用修订及Worker状态；汇总文件记录离线和未应用次数、API错误及事件数量。脚本每20分钟重新登录以支持较长观测，最长24小时；它不部署程序、不重启服务，也不改变调度配置。异常样本必须结合故障注入时间解释。

本轮另每20秒读取systemd的MainPID、NRestarts、MemoryCurrent、TasksCurrent。连续观测包含故障与重启窗口，结束后单独统计最后一次受控重启之后的稳定窗口。测得的进程内存不等同整个主机、推理服务或评测容器占用。

## 边界

短时观测及故障演练不证明数日稳定性。未执行整机断电、内核故障、生产NFS硬挂载超时、真实磁盘写满或跨版本业务兼容性测试；磁盘错误通过自动测试注入，挂载丢失在隔离命名空间中验证。后续可将只读观测延长至24小时，并在维护窗口做整机恢复验收。

详细结果与执行日志保存在忽略入库的 `.runtime/agent-fleet/`；测试临时模板最终停用，测试任务保留结果供平台查看。
