# 批次控制验收（2026-10-31）

实现批次暂停后续调度、恢复和整批取消，采用持久化调度开关与控制版本。执行状态保持原有契约；暂停不挂起已领取的任务，取消遵守停止和清理确认。

## 测试

- 后端全量 136 项通过；补充 API 重载后仍暂停且不阻塞其他批次的场景，控制相关 5 项通过，合计 137 个不同后端用例。
- 独立 PostgreSQL 15 项通过，包含暂停/取消与领取、调度、重试和相反控制请求竞争。
- 独立迁移库 1 项通过：旧批次默认值、升级/降级、拒绝存在活动/未清理执行或暂停排队任务的降级；Alembic check 无差异。
- 浏览器全量 24 项通过，包括取消确认、控制按钮互斥、旧版本冲突、响应丢失后重放原版本、轮询不覆盖确认版本及筛选保留。
- TypeScript、Vite 构建和 OpenSpec strict 校验通过。
- 隔离真实 Docker：暂停后已有任务完成，其余任务持续等待；恢复后领取新任务，整批取消后 1 项完成、5 项取消，全部确认清理，历史回合保留。恢复调度不会复活取消任务，旧暂停请求被拒绝。

正式双机验收：本机 `local-4090` 和 `r8000` 同时执行，暂停后 2 项完成、其余持续等待；恢复后再次双机领取，整批取消后共 2 项成功、4 项取消，所有执行确认清理。恢复没有复活取消任务，旧版本请求返回 409。专用集合已归档，原集合和节点配置未修改。正式浏览器确认控件、取消确认关闭、任务排查和刷新恢复通过。

双机验收结果及发布材料记录在 [结构化证据](validation/batch-controls-20261031.json)。验收采用临时 SDK HTTP 推理测试服务，不表示真实 RoboTwin/模型成绩。
