# API 共享存储直读产物

运行结果 → 任务/回合 → **查看产物**，选择“共享存储（API直读）”。API 从管理员配置的共享挂载读取本次执行的 output 目录，可逐层浏览、预览 JSON/TXT/CSV、图片和视频、下载文件。文件不复制进数据库，不经 Worker 转发；节点离线但共享存储仍可访问时也能读取。

支持平台输出目录，以及客户端模板声明的自定义共享结果目录；Worker 文件转发仍未启用。升级到配套 API 与 Worker/Runner 0.21.12 后，SDK 首次使用 episode_output_dir 或平台逐回合包装器创建目录时写入隐藏的 .mini-eval-artifacts 回合元数据；该目录及下级文件按显式登记归属。协议 artifacts 的逐文件声明优先，可关联多个回合。回合筛选作用于当前目录页，目录始终可进入；没有登记或有效声明的文件显示“未声明”，不凭文件名推测回合。

## 简化部署：只设置一个总目录

API 主机和节点能访问同一份文件、且节点产物根位于同名路径下时，在部署 `.env` 只增加：

```dotenv
SHARED_ARTIFACT_HOST_ROOT=/data/artifacts
```

保留原项目名、环境文件和全部 Compose 覆盖文件，沿用原构建及启动命令即可，**不需要新增 `-f deploy/shared-storage-compose.yml`**。代码与API镜像更新后重建容器，例如基础源码部署：

```bash
docker compose --env-file .env -p mini-eval -f deploy/compose.yml \
  up -d --no-deps --build --force-recreate api
```

主 `deploy/compose.yml` 将总目录只读挂载到 API 的 `/mnt/mini-eval-artifacts`，并传入配置变量。仅改 `.env` 或 `restart` 不生效。预构建镜像部署须先更新镜像，`--build` 不替代镜像发布。未配置变量时只挂载仓库占位目录且不启用API映射，不需要准备外部产物目录。目录必须已存在，不自动创建空目录代替挂载。节点界面的整机产物根填 `/data/artifacts` 或其子目录；卡留空继承整机配置。无需手填 JSON、节点名单或创建 `.mini-eval-storage-id`，后续所有子目录自动包含。

默认映射适用于各节点，但只能读取用户有权访问、已登记执行的输出目录，不能通过浏览器传入任意宿主路径。拒绝 `/`、相对路径、穿越及链接。简化模式不验证磁盘身份标识，管理员须保证挂载来源正确；需要校验存储身份或节点/API路径不同时使用下面的高级配置。

非空 `MINI_EVAL_SHARED_STORAGE` 优先，`[]` 明确关闭映射，非法 JSON 报错而不自动降级。已有高级映射请保留，切换为简化模式不会自动迁移历史目录登记；旧映射身份不匹配的记录会拒绝读取。无新增数据库迁移或 Worker 协议变化，停止上传仍需已有支持共享传输的 Worker。远端节点只有本地磁盘、API 主机看不到文件时不能使用此功能。

以下为高级配置说明。

## 1. 准备已有共享挂载

节点产物根（未设置独立根时为工作区输出）必须位于共享存储内；平台服务器也须挂载同一存储。例：

- 节点名（与机器管理中的名称完全一致）：node-a
- 节点共享根：/efs/project
- 平台服务器已有挂载：/srv/eval-shared
- API 容器内只读挂载：/mnt/mini-eval-artifacts

节点输出 /efs/project/node-a/gpu0/runs/执行ID/output 对应 API 内 /mnt/mini-eval-artifacts/node-a/gpu0/runs/执行ID/output。映射按路径组件匹配，不是字符串前缀替换。相同节点、同一路径必须只有一个匹配项；不要配置重叠根。

在确认是正确共享盘之后，由存储管理员**一次性**建立根目录标识文件（示例值不是密码；每个存储使用稳定的不同标识，已存在时先核对，不覆盖）：

```bash
test -d /srv/eval-shared
# 先使用 findmnt -T /srv/eval-shared 核对来源，不能在未挂载的本地空目录初始化标识。
test ! -e /srv/eval-shared/.mini-eval-storage-id &&
  (set -C; printf '%s\n' 'eval-shared-project-001' > /srv/eval-shared/.mini-eval-storage-id)
```

节点业务账号负责写文件；API 容器账号需要沿途目录搜索权限及文件读取权限。通过现有组/ACL授予读取权限，不要递归改成全员可写。API 不切换为业务账号、不执行登录 shell。只读挂载不会绕过 NFS root_squash 或文件权限。

## 2. 配置与升级

在原部署环境文件中增加（JSON 单引号是 Compose env-file 的外层引号）：

```dotenv
SHARED_ARTIFACT_HOST_ROOT=/srv/eval-shared
MINI_EVAL_SHARED_STORAGE='[{"id":"project","node_names":["node-a"],"node_root":"/efs/project","api_root":"/mnt/mini-eval-artifacts","marker":"eval-shared-project-001"}]'
```

多节点访问同一根可添加 node_names；不同节点根路径或不同存储使用不同 id 的映射项。多存储挂载自行扩展 overlay，全部使用 read_only: true 和 create_host_path: false。该环境变量必须进入 API 容器，仅修改 .env 而不重建容器不会生效。

高级模式同样沿用原项目名、原环境文件及原有全部 overlay；主Compose已内置挂载，例如：

```bash
DC=(docker compose --env-file .env -p mini-eval -f deploy/compose.yml)
```

如果原部署使用 lan-compose.yml 或固定镜像版本文件，保留这些文件及其顺序。按[数据库迁移指南](database-migration.md)构建同版 API/migrate/bootstrap、排空任务、备份并升级到 **a730d12**，随后用这个 DC 数组启动。原命令已使用 shared-storage-compose.yml 的可继续保留，相同目标挂载会合并；无需为此删除既有覆盖文件。无需新增文件存储卷，不要执行 down -v。

更新相应节点到 **Worker 0.21.9**。当 API 对该节点下发 artifact_transport=shared 时，新 Worker 只登记输出路径，不再主动上传产物正文；未配置映射的节点沿用旧逻辑。旧 Worker 会忽略新标记、继续旧上传行为，因此仅升级 API 不能保证停止上传。Runner/SDK 不需要为了直读而升级。

活动任务保存了旧下发配置，升级后的新任务才保证采用新行为。API 先升级并迁移，再更新节点。移除映射只会撤销读取授权，不会自动转存或删除文件。

## 3. 目录身份与历史兼容

新执行由 Worker 在启动及完成阶段幂等登记 runs/<execution_id>/output；登记失败写 Worker warning，不能改变业务执行结果。历史执行可使用该执行已上报的 ExecutionData 实际目录登记；没有记录或存在歧义时明确提示“执行输出目录未上报”，不从当前工作目录设置推断旧位置。

新表 shared_artifact_roots 只保存执行与目录映射元数据，不存文件正文。已登记执行不可重新绑定目录；API 本地挂载位置可以变化，但存储 id、marker、相对路径保持身份约束。修改 marker 或撤销节点授权会拒绝访问。删除批次会删除登记与旧数据库产物，**不会删除共享盘上的文件**；节点原有保留/清理策略仍适用。

产物来源默认选择“共享存储（API 直读）”。未启用时保持选择并提示配置总目录、更新并重建API，可点击“查看历史上传产物”或手动切换来源；不再自动跳回历史来源。配置生效后可点击“刷新共享目录”重试；已启用但挂载、权限或目录出错时明确报错，不伪装空目录或自动隐藏到历史页。仍可手动选择历史页查看旧 RunArtifact 正文。

## 4. 读取边界及错误

- 每页最多100条，下一页带目录版本；目录变化需从首页刷新。
- 按需1 MiB分块读取，不加载整段视频；支持单一 Range、HEAD、ETag/If-Range。文本预览最多256 KiB，下载不限文件总大小。
- 鉴权和目录元数据查询后立即释放数据库连接，再启动隔离子进程读共享盘。每次 I/O 超时10秒；每个 API 进程最多8个 I/O、每用户2个；媒体响应另有相同数量的全程并发限制。多进程部署上限按进程累加。
- 读取超时杀子进程；处于不可中断 NFS 等待的子进程在实际退出前仍占额度。流中途文件变化/存储失败会中断传输，浏览器可刷新后重试，不拼接不同版本。
- 媒体授权使用5分钟以内、且不超过登录会话的文件限定 HttpOnly cookie；URL不携带登录 token。正在下载跨过授权截止时间会停止，重新授权后可继续范围读取。浏览器不支持视频编码时可下载。
- 拒绝路径穿越、符号链接、多硬链接及非普通文件；HTML/SVG只下载，不执行。
- 403：文件权限不足或不安全路径；409：版本变化/映射冲突/目录未登记；410：文件或目录已清理；429：读取繁忙；503：共享挂载缺失、标识不符或无权读取根标识；504：共享存储超时。

只读 overlay 防止 API 写共享盘；根标识用于识别错挂载，不是认证秘密，也不是文件备份。API 能看到的范围取决于管理员映射及任务归属授权。不要把密钥输出到产物目录。

## 节点独立产物根（Worker 0.21.10）

进入 **管理设置 → 机器 → 查看配置 → 工作目录与资产 → 存储配置**，填写“产物根目录”，例如 /efs/project/artifacts。产物根逐字段继承：即使卡已有单独工作目录，卡的产物根留空也使用整机产物根；卡显式填写则优先使用卡的值。整机和卡都未设置时兼容旧工作区输出。其他目录仍按整份卡级配置覆盖。已有配置在更新 API 后重新保存整机存储配置，触发新修订下发；旧回执产物根与期望不一致时显示待校验并阻止新调度，不迁移正在运行的执行目录。产物根不能与资产根、缓存根或工作根相互包含。整机与卡均未设置时兼容旧工作区输出。

保存后等待各卡应用版本一致；缺少 artifact_roots_v1 能力的旧 Worker 显示“需升级 Worker”，不能调度新布局。运行中的任务在清理前保持原存储快照。产物根无需加机器名或卡号，平台按稳定 ID 隔离：

```text
产物根/批次ID/任务ID/执行ID/
  output/                  公共产物
  episodes/1/output/       回合1
  episodes/2/output/       回合2
```

没有批次的独立任务/服务使用 standalone 替代批次ID。重复执行使用新的执行ID，不覆盖旧结果。工作区继续保存输入、临时文件、状态和日志；业务 cwd 不改变。首次领取时把目录计划保存到现有 SharedArtifactRoot，配置修改后领取重放不会重新定位；无需新增迁移，仍要求已完成 a730d12。

宿主机按批准业务账号创建目录，权限不足会阻止本次启动并显示原因，不自动提权或递归修改已有共享目录权限。容器执行持久绑定该执行产物根及公共 output，按镜像账号写文件；支持自定义容器内 output_dir 和 output 通用挂载别名。平台为容器输出叶目录提供写权限，不改共享根所有者；API 读权限仍需要现有 NFS 组/ACL配置。独立目录不会随工作区 runs 的清理删除，批次删除仅删元数据；本轮没有独立产物自动清理/容量配额，存储管理员负责保留与容量管理。

### 模板如何传产物目录

创建客户端或服务端模板，在 **动态参数映射 → 选择要传递的参数 → 产物目录** 添加映射，传递到“命令行参数”，程序接收名称填 --output-dir。基础命令仅填程序本身，不重复手写同一个参数。平台字段为 platform.paths.output，不需要新增类型化业务字段。

也可映射到自定义环境变量 OUTPUT_DIR，或不配置映射直接读 MINI_EVAL_OUTPUT_DIR / 输入 JSON platform.paths.output；模板 argv 支持 ${output_dir} 占位符。示例：

```json
{"command":["python3","evaluate.py"],"platform_bindings":[{"source":"platform.paths.output","target":"argv","name":"--output-dir","encoding":"literal"}]}
```

- 普通命令/直接协议整任务启动：传公共 output，业务自己组织内部回合目录。
- 宿主机每回合启动：命令行、占位符、环境变量和输入 JSON 一致指向 episodes/N/output。
- 原生 SDK：context.output_dir 保留公共目录；context.episode_output_dir 返回当前回合目录；context.artifact_path 生成相对此执行产物根的引用。不修改进程全局环境。
- SDK命令适配器：每次业务子进程获得对应回合目录；逐回合模式保留原有 episodes=1/递增seed规则，旧整任务配置的参数计数语义不因目录调整改变。结果 artifacts 仍相对本次子进程输出目录，适配器转换成执行根引用。
- 容器：传给程序的是容器路径，而非节点物理路径。

业务硬编码写 cwd 的文件不会自动搬到产物目录。未启用独立根时旧布局和旧引用不变。启用需要新版 Worker 和 Runner/SDK；平台注入适配器的模板随 Worker 更新，依赖镜像内旧 Runner/SDK 的旧式镜像需重建/更新 SDK。API 只读映射仍须覆盖新产物根，错误映射不会回退上传文件。

当前部署可见的宿主机逐回合与 Docker 功能样例、入口及升级验收边界见 [2026-11-19 上线记录](validation/artifact-root-release-20261119/README.md)。样例为文件生成与浏览验证，不代表模型评测。

原生SDK显式声明产物的真实CUDA三回合批次及回合筛选验证见 [SDK/GPU 验证记录](validation/artifact-runner-gpu-20261119/README.md)。这是张量计算与文件归属验证，不是模型评测；未声明文件的普通命令不会自动获得协议回合归属。

### 目录归属登记边界（0.21.12）

元数据只含格式版本和回合编号，不含任意读取路径，不作为鉴权依据。API 仍先按任务与已冻结共享根授权，使用不跟随链接的目录句柄读取；损坏、超大、链接或非法元数据不赋予回合归属。业务账号能修改自己的元数据，因此这是业务输出归属声明，不是防篡改审计。

SDK 旧 output_dir、artifacts 相对路径、setup 上下文均保持原语义；不使用 episode_output_dir 就不创建空回合目录。嵌套 SDK 沿用父回合编号；已创建目录在业务异常后仍可浏览。元数据写失败打印不含路径或环境的诊断，业务结果不变。保留旧单进程/共享输出语义，不把普通目录 episode-1 误认为已登记回合。

无新增数据库迁移。先更新 API 读取模块，再更新实际使用的 Runner/SDK；注入式容器随节点组件获得新 Runner，旧式内置 Runner 镜像由维护者更新。新 SDK 下载包包含归属模块。历史没有元数据的文件仍按原显式引用显示，不批量回填。此版本代码验证不代表已部署。

### 无法读取时查看输出路径

产物窗口的“产物输出目录（节点路径）”独立读取本次执行元数据，始终位于来源选择上方。共享未启用、挂载或权限失败、切换历史上传时仍显示节点路径；独立布局另显示执行产物根及公共output。仅有计划时注明尚未收到节点登记确认；没有唯一历史记录时显示未知，不读取当前节点配置推算。目录记录不证明文件仍存在，容器任务展示的是宿主节点路径，不是容器内部路径。无需数据库迁移。

### 目录导航与窗口

“查看产物”使用居中大弹窗，桌面宽度最多1280px，窄屏自动缩小并内部滚动，关闭按钮保持可见。可用“返回上一层”逐级返回，也可通过“输出根目录”和路径导航跳转；根目录的返回按钮禁用。目录切换清空分页与当前文件预览。关闭按钮或Escape关闭后恢复入口焦点，不清空批次筛选。


## 客户端模板自定义结果浏览目录

管理设置 → 运行模板 → 客户端模板，填写可选的“自定义结果浏览目录”。例如 `${output_dir}/reports`、`${assets:dataset}/results/${business.scene}`；容器也可用 `${mounts:shared}/results`。业务字段必须先在类型化参数中声明为文本或数值。该字段只指定结果页浏览位置，不修改启动命令、业务输出参数或环境变量；业务仍需自行写到对应目录。

首次领取任务时 API 根据该任务的模板、业务参数和节点配置冻结实际节点路径。宿主机路径必须位于批准的代码根、工作/输出/缓存目录、模板引用的资产或节点批准的目录中；容器路径必须能够反向映射到持久挂载，不支持容器临时文件层。拒绝父目录穿越、未声明参数及有歧义的挂载。运行中修改模板或节点目录不改变已登记路径；历史执行不从当前模板补造路径。解析失败只在目录元数据中记录原因，不将成功的业务程序改为失败。

查看产物 → 产物来源 → “自定义共享目录（实时浏览）”。这类目录可能包含其他任务写入的文件，明确显示为共享实时文件，不按文件名或 manifest 推断本次回合归属，不上传、不删除。平台输出目录的既有归属和保留规则保持不变。即使尚未设置共享映射，窗口仍显示已登记的节点路径；读取文件仍需前文的 API 只读共享挂载和授权。自定义根首次成功绑定映射后，不会随配置自动改绑其他存储。

部署前迁移到 **c952f34**（前驱 b841e23），新增客户端模板字段及 execution_browse_roots 元数据表，不搬迁任何文件。仅此功能无需更新 Worker/Runner；正在运行的旧执行不补录。降级删除这部分目录元数据，优先保留表回退应用。详见[数据库迁移指南](database-migration.md)。

快速切换目录或来源时，API可能因仍在结束的旧读取返回429。浏览器遵循 Retry-After（等待1–5秒）最多自动重试两次，关闭或切换来源会取消等待；仍繁忙时保留明确错误和手动刷新入口，不增加API并发额度。
