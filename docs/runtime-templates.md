# 通用运行模板与业务协议

管理设置 → 运行模板管理，分客户端/服务端。每类下有“已注册模板”和“注册新模板”页签，切换页签保留未提交草稿；每类都有 Docker 与宿主机执行模式，版本不可变；复制新版本后修改，归档只停止新引用，旧任务保存快照。现有模板默认 Docker/direct。

客户端注册 API 为 `/api/v1/admin/client-templates`，服务端为 `/api/v1/admin/server-templates`。注册使用 POST，启停 PATCH `/{id}`，归档 DELETE `/{id}`，复制 POST `/{id}/clone` 带 name（可选）和 version。宿主机模板只能由管理员注册，使用 `host_runtime.environment_name` 指向节点批准环境，不填 image/runtime；Docker 使用 image 和 runtime。环境准备/实例部署由后续同一 OpenSpec 任务实现，模板注册不代表已经可以执行。

## SDK + 业务命令

宿主机客户端模板可以在“宿主机环境来源”选择已批准业务账号的登录 shell 导出变量，并在“客户端回合启动”选择每回合启动一次业务程序。两个选项都需 Worker 协议 15；不填写时沿用旧模板行为。登录环境由业务账号在节点上提供，平台分配的设备可见变量始终覆盖同名值。Docker 与服务端模板不提供逐回合启动选项。具体执行、错误与权限边界见 [宿主机执行](host-execution.md)。

`integration_mode: sdk-command` 表示一次业务命令只运行一回合；平台 SDK 循环调用命令。命令为 argv 数组，无 shell 展开；支持 `${task_name}`、`${episodes}`、`${seed}`、`${episode_id}`、`${episode_seed}`、`${endpoint}`、`${input_path}`、`${work_dir}`、`${output_dir}`、`${result_path}` 和 `${assets:逻辑名}`。

每回合自动设置 `MINI_EVAL_EPISODE_ID`、`MINI_EVAL_EPISODE_SEED` 和 `MINI_EVAL_RESULT`。业务程序须把结果写到 MINI_EVAL_RESULT 指定文件（不超过16KiB），例如：

```python
import json, os
from pathlib import Path
# 在这里调用仿真及推理服务；success 应由业务判定。
Path(os.environ['MINI_EVAL_RESULT']).write_text(json.dumps({
    'success': True, 'metrics': {'reward': 1.0}, 'artifacts': []
}))
```

SDK 校验结果并生成原有 STARTED/COMPLETED/ERROR 回合事件，最终生成 report.json 及汇总。success 必须为布尔值，评测失败 success=false 不等于程序异常；非零退出、没有结果、结果不合法会让执行失败。业务命令仍可输出普通日志，不能以零退出码替代评测结果。

## 直接协议

`integration_mode: direct` 让程序一次执行完整任务，可使用既有 `runner.sdk module:ClientClass`，也可自己实现 `runner/episode_contract.py` 事件及最终结果格式。启用 episode_reporting 时，事件写入 `MINI_EVAL_WORK_DIR/episodes.jsonl`，逐行完整 JSON；Worker 持久化游标并重试，服务端按执行与回合身份去重。不要自行携带 Worker token，业务程序不需要平台管理凭据。

两种模式读取同一 `MINI_EVAL_INPUT` JSON，使用同一工作/输出/资产目录约定。业务参数放 parameters，任务名和回合数来自集合快照。普通日志不能推断回合完成；未集成协议的程序只能显示进程日志，不能伪造逐回合进度。

## 服务端模板

服务端模板固定 direct，额外描述 port、protocol、health_type（http/tcp）、health_path、startup_timeout。启动命令可使用 `${port}`，部署实例时指定宿主机端口并由平台做冲突和资源检查。健康描述属于模板；实例管理和执行能力在同一 change 后续任务中交付。

## ClearML 参考

参考 [ClearML Agent 官方仓库](https://github.com/clearml/clearml-agent) 的任务配置与队列拉取，以及 [执行环境文档](https://clear.ml/docs/latest/docs/clearml_agent/clearml_agent_execution_env/) 的 Docker/虚拟环境分离。当前平台先接入管理员已准备的宿主机环境，不自动复制 ClearML 的依赖安装流程。推理服务持有 GPU 资源；[ClearML services-mode](https://clear.ml/docs/latest/docs/clearml_agent/clearml_agent_services_mode/) 是轻量维护服务的模式，不能直接用其默认 services 队列承载 GPU 推理。

## 注册界面操作

1. 打开“注册新模板”，根据顶部说明准备镜像或批准的宿主机环境。可展开“从完整样例开始”，预览并载入六种配套样例；存在草稿时确认替换，载入不会自动注册或启动。
2. 填写名称与新版本，在“业务参数”勾选“启用类型化业务参数”，添加并命名业务字段。启动命令按程序和固定参数逐项填写，动态参数在“动态参数映射”选择来源，再填写 --task、--server-url 或环境变量名。已在业务字段卡片中绑定的字段仍列于选择框并标注“已映射”；选择后可定位并修改原映射，不会重复添加。未启用或未命名字段时，映射区会说明缺少哪一步。业务字段的映射与业务参数编辑器共享配置；重复目标会提示，原始命令数组保留在高级配置。
3. 在统一“目录挂载”区选择工作、输出、缓存、资产或批准目录，填写逻辑名和容器目标。节点负责解析真实路径。旧资产声明标为兼容声明，原 assets 占位符保持有效；资产和缓存只读。
4. 注册成功回到列表。“查看配置”按注册分组只读展示，复杂参数、挂载和补充配置均可查看；需要修改时复制新版本。配置查看不会修改模板。

完整样例、镜像构建和三任务 CS 演示见 [运行模板样例](../examples/runtime_templates/README.md)。示例是协议连通性回显，不是模型质量评测。

### 环境变量与实时启动预览

在“环境变量”中逐行填写名称和值（例如 `LOG_LEVEL` / `info`），不需要 JSON 引号。空字符串是有效默认值；若只允许用户提交时提供变量，取消“提供默认值”并勾选“允许提交时覆盖”。Docker 与宿主机分别保留环境草稿，切换执行方式不会丢失编辑。动态环境变量通过“启动命令”的参数映射配置，不能与固定环境变量重名。

模板环境变量是直接传给程序的固定值或允许提交时覆盖的值，不会作为“业务参数”来源重复映射。需要把集合任务或服务部署时填写的业务值传给命令行或环境变量，应先定义类型化业务字段，再为字段选择传递方式。原先已绑定字段从下拉框消失的问题已修正；定向界面测试覆盖新字段添加、已有绑定定位、编辑后复制版本及重复目标拒绝，使用模拟 API，不代表真实业务程序验收。

“启动命令”包含程序、固定参数、动态映射及实时预览。修改程序参数、映射名称、传递方式或业务编码，预览立即同步。预览中每个带引号的固定项表示一个 argv 参数，`⟪task.task_name⟫` 等标记表示运行时取值来源，不是需要用户填写的文本。业务映射先追加、平台映射后追加；布尔开关标注条件，数组重复映射标注逐项重复。环境映射单独展示。预览仅作配置说明，平台保存原始命令和绑定关系，不执行预览字符串或 shell 展开。

## 普通命令任务注册

客户端模板注册页可选择“任务类型”：评测任务或普通命令。普通命令使用直接执行；默认关闭逐回合上报，宿主机选择逐回合启动时由平台上报回合完成。成功依据退出码（0成功、非零失败），无需SDK、结果JSON或回合事件。运行环境仍支持Docker和已批准的宿主机环境；命令按argv执行，不隐式解释Shell管道。业务程序与依赖必须预先准备。

查看配置和复制版本保留任务类型；切回评测任务会恢复表单中的评测接入选择。服务端模板不提供该选项，仍按服务生命周期与健康检查管理。

普通命令默认每项执行一次，不统计评测回合；保存及自定义提交的兼容 episodes 字段为 1。仅宿主机客户端模板选择每回合启动时，集合项可以填写多个回合，平台逐回合启动命令并记录完成进度；进程退出 0 仍不代表评测成功，也不产生评测成功率。向导选中普通命令模板后默认“无需服务（普通批处理）”，也可按实际需要显式配置服务；切换回评测模板需提供推理服务。已有程序可使用业务参数映射接收参数，不必读取平台任务文件。

## 配置详情导航

机器、运行模板和评测集合点击“查看配置”后进入独立详情，列表暂时隐藏。顶部显示所选名称与返回入口；返回恢复列表筛选、分页、焦点与滚动位置。机器与集合详情返回时保留已挂载表单，重开同一对象保留输入；集合的新建草稿可从“继续查看当前配置”恢复。切换对象或重新开始会覆盖未保存草稿时提示。模板配置只读，修改需复制新版本。

草稿仅在当前组件存续时保留，刷新、关闭页面或离开整个管理模块不保证保留；返回列表不代表保存成功。API 保存失败仍显示错误并保留表单。配置内容较多时使用原有功能页签；发布与权限规则不变。

提交时的 CPU/内存硬上限可独立取消，但仍按模板最低要求预约，且受对应字段覆盖权限控制。详见 [可选执行限制](optional-execution-limits.md)。

## 产物目录参数

客户端/服务端模板均可在动态参数映射选择“产物目录”，绑定 argv --output-dir 或自定义环境变量；底层来源为 platform.paths.output。不要再定义同名业务参数或在基础命令重复写 --output-dir。也可使用 ${output_dir}、MINI_EVAL_OUTPUT_DIR 或输入 JSON。独立节点产物根不会改变业务 cwd；宿主机每回合启动时传当前回合目录，整个任务启动时传公共目录，容器传容器内路径。配置与升级见[共享产物指南](shared-storage-artifacts.md)。


### 自定义结果浏览目录

客户端模板可填写“自定义结果浏览目录”，如 `${output_dir}/reports` 或容器持久挂载 `${mounts:shared}/${business.scene}`。这是只读浏览位置，不是业务输出参数；要改变业务写入位置，仍需配置启动参数映射或业务环境。任务首次领取冻结解析路径，旧任务不按后来修改的模板推测。宿主批准根、容器持久映射、共享挂载和迁移要求见[共享产物指南](shared-storage-artifacts.md#客户端模板自定义结果浏览目录)。服务端模板不提供此字段。
