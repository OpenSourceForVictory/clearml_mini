# 批次监控与补跑

在「CS 评测批次 → 评测集合运行」选择「查看批次」，或在提交、试跑成功后打开对应批次。详情使用 `#/cs/batches/<id>`，可收藏、刷新；返回列表保留当前运行草稿和列表页码，再次打开批次保留本会话的筛选条件。

详情汇总每项任务的**最新尝试**。目标成功率为所有已完成回合的成功数之和除以完成数之和；没有完成回合时显示暂无数据。客户端未声明回合上报时，显示未上报，不推算进度。执行成功但目标失败的任务不会纳入批量补跑。

任务表与执行尝试详情另列“数据同步”：旧执行标记为历史执行；新恢复协议执行可显示执行中、结果待同步、同步完成或同步失败。完成后超过五分钟仍待同步会提示延迟，诊断日志有缺口会单独提示。同步失败保留业务程序原有退出状态和已收到的有效回合，不能把退出码 0 或摘要中的成功率当作缺失协议结果已补齐。点开尝试可查看拒收原因；认证、归属和临时服务错误不会被当作已同步，节点会保留待确认记录重试。此状态仅适用于新恢复协议，平台尚未向生产 Worker 广告该能力。

平台取消或业务时限已优先终止原执行时，Worker 即使稍后带来“业务成功”摘要，界面仍按平台终态显示取消/超时。可靠队列全部交付并封口后，同步状态可显示完成；被平台停止的服务或客户端不因缺少完整成功指标而被误标为同步失败。真正的成功执行缺回合或结果失配仍显示同步失败。

Worker 完成全部本地结果采集并排空可靠队列后，会发送最后的 `results-finished` 封口确认。若此时仍缺计划回合或成功率与摘要不符，平台返回同步失败及原因，不再让节点无期限重试同一无效封口；程序退出与清理确认保持原值。尚未完成采集或队列仍有未确认结果时，Worker 不会发送封口。

可按任务名、执行状态、等待原因筛选。等待诊断在上次请求结束后约五秒刷新，包含批次/用户/平台并发限制、推理服务互斥，以及各 GPU 的镜像、环境、显存、磁盘等条件。检查不预留资源，不保证启动时间；有符合要求的节点时仍由调度器公平分配。已提交任务使用保存的配置快照，不受模板之后停用影响。

「排查任务」集中展示所选尝试的日志、回合、产物。切换历史尝试后，自动刷新不会跳回最新尝试。「详情 / 重试」保留原有单项操作。

批量补跑需显式选中失败或超时任务。每项绑定选择时的尝试 ID；轮询不会替换该 ID。旧容器未确认清理、额度不足、状态变化或尝试变化时逐项跳过，显示原因。网络错误后保留原选择，可安全再次提交；想补跑新的失败尝试，需要清空并重新选择。历史日志、回合和产物保留，但不会重复累计到最新汇总。

## API

`GET /api/v1/batches/{id}/monitor`：仅本人或管理员可读，其他用户返回 404。保留批次原字段，增加：

- `checked_at`：诊断时间。
- `summary.states`、`execution_failures`：最新任务状态计数及执行失败/超时数。
- `summary.completed_episodes/successes/goal_failures/episode_errors`：最新尝试上报数据；`success_rate` 为加权比率或 null。
- `summary.reporting_tasks/unreported_tasks`：声明上报与未声明上报的任务数。
- `cases[].data_sync`：最新执行尝试的独立数据同步状态、延迟提示、日志缺口和拒收原因；`GET /api/v1/jobs/{id}` 的 `attempts[].data_sync` 为各次尝试对应状态。历史执行为 `legacy`，没有恢复授权的执行不推断为同步完成。
- `cases[].waiting`：仅排队任务有诊断，包含总体原因和逐 GPU 节点原因；已执行任务为 null。
- `cases[].reason_codes`：筛选用原因码；包括候选节点原因，某节点不满足不代表所有节点都不满足。
- `cases[].config`：提交时的客户端版本、推理地址、资源要求和池名称；不公开宿主机目录。
- `cases[].node_name/gpu_index/cleanup_confirmed`：当前尝试分配和清理状态。

`POST /api/v1/batches/{id}/retry-failed`：

```json
{"items":[{"job_id":"任务 ID","expected_run_id":"选择时的尝试 ID"}]}
```

1–100 个不重复任务。归属或成员校验失败时整批不写入。返回 `retried`、`skipped` 和 `items`，逐项包含 `job_id/outcome/run_id/attempt`；跳过项增加 `code/message`。原因码为 `attempt_changed`、`not_retryable`、`cleanup_pending`、`backlog_limit`。同一事务内持有调度锁和用户额度锁，与单项重试串行化。同一预期尝试最多创建一个后继尝试；重复请求不保证相同响应，但不会重复补跑。

原单项重试仍允许取消任务重试，批量入口仅允许执行失败和超时。

## 批次详情布局
顶部概览显示任务结束、回合完成、执行失败/超时和待清理任务；结束不等于业务成功。下方默认“任务与结果”，可筛选、补跑及排查日志；“运行配置”按任务查看提交快照；“服务端与关联”查看服务健康、分配关系和日志。切换保留任务筛选与补跑选择，返回列表后仍保留原筛选。窄屏任务表在表格内部横向滚动。运行控制保持独立，取消后仍需等待清理确认。

托管服务批次在默认的“任务与结果”页显示“服务端启动状态”。实例尚未创建时，按服务定义显示服务端资源池、当前可用候选数、候选设备的环境或资源阻塞原因；服务端候选就绪仍需等待两端联合调度。实例创建后显示资源分配、启动、健康检查、就绪、失败或停止状态。点击“查看服务端与关联详情”查看探测、日志和客户端绑定。外部服务由用户维护，平台不显示其启动状态。诊断复用当前持久状态，只读且不预留资源；轮询失败会显示错误并自动重试。进程启动不等于服务健康，模拟界面测试不代表真实模型评测。

本次问题的触发条件、线上发布和验证边界见[服务端调度可见性记录](validation/service-scheduling-visibility/README.md)。

删除批次诊断：HTTP 500 的文本响应由 frontend/src/api.ts 显示为“请求失败 (500)”，不再出现 JSON 解析错误。失败时保留批次及比较选择；记录批次 ID、请求时间并检查 API 异常日志，必要时刷新确认状态后再重试。正常删除允许运行中的批次：立即隐藏并请求停止，待原节点确认清理和结果同步后再清除执行数据；不能把隐藏视为资源已释放。节点工作目录不由该接口清除。测试见 batch-history.spec.ts、test_batch_deletion.py、test_recovery_finish.py；前端错误展示修复不代表现场后台 500 根因已修复。

两端运行位置：批次默认“任务与结果”页提供独立“客户端分配位置”列；托管服务启动摘要和“服务端与关联”详情展示服务端分配位置。位置来自当前任务最新执行尝试的 Run.slot_id，包含节点、GPU/NPU 类型、卡号及型号；悬停可查看设备身份。位置表示资源分配，预约/运行/停止仍以状态为准。尚无分配或历史槽位不可用时明确提示，重试不会回退显示旧尝试的位置；软删除但仍保留的槽位可显示历史位置。外部服务只展示地址，不推测其节点或卡。旧 API 缺少 placement 时显示位置信息不可用，需要同步更新平台 API 和前端；无需数据库迁移或 Worker 升级。


## 服务实例数量与逐回合详情

新批次填写“服务实例数”（1–20），代表每个逻辑服务希望创建的数量；共享访问同样按目标调度。资源不足会显示未创建数量和具体阻塞原因，已有就绪实例可以先为客户端服务。服务消耗独立资源和全局/用户活动配额；客户端并发为 1 不限制服务只能有 1 个。失败或手动停止不会被自动创建新实例掩盖，需要修复并恢复。旧批次只有 max_instances 的仍显示“旧配置实例上限（按需启动）”，不自动扩容。

“服务端与关联”每个实例单独一行，显示唯一实例 ID、逻辑服务、实际节点、GPU/NPU 卡号和型号、地址、调度/运行状态、探测诊断。日志在对应行下展开，可独立刷新/关闭；同名实例通过 ID 区分。等待调度没有实际位置时不显示候选节点为运行节点。

服务显示“执行心跳租约过期”表示平台未收到该次执行的及时续租，任务已标记超时；对应加速卡会被隔离，资源清理仍需原 Worker 确认。在“服务端与关联”点击“停止”会禁止后续继续运行；服务任务已结束时无需再次取消，停止请求仍可成功。只要实例仍显示“执行资源尚未释放”，就不能恢复服务或排空升级该机器；先恢复节点 Worker 心跳并等待它核对原执行、停止残留进程及确认清理，不要直接改数据库状态或删除执行 journal。若提示“服务实例状态已变化”，刷新批次后核对实例再操作。停止请求成功不表示资源已立即释放。本次修复覆盖已结束任务、完成与停止竞态和版本冲突；尚未在其他部署机器复测。

支持回合展示的任务行点击“查看回合”展开当前尝试的回合计划，每页最多 100 条。未上报开始或结果的回合也显示；重试切到新尝试，不混用旧结果。协议 COMPLETED 的 success 决定业务成功或失败，ERROR 表示执行异常。普通命令退出码 0 表示执行成功，非 0 表示失败，不生成评测业务成功率；一次启动的普通命令只能表示整次执行。

退出码与协议结果独立保存。整次执行退出码是 Worker 观察的宿主机执行单元/容器退出码；逐回合退出码是适配器 wait 得到的业务子进程退出码，二者可能不同。程序选了协议却没有实现时，仍显示实际退出码及缺失结果，0 不能冒充协议成功。纯 SDK 内部调用没有独立子进程时，或旧 Worker/历史记录未上报码时，显示“未上报”。信号终止的 subprocess 可能报告负数。

发布退出码功能需要迁移 x407a89、更新 API/前端，并升级 Worker/Runner 至 0.18.2；协议版本仍为 15，可选字段兼容旧上报。先升级 API 再升级节点；旧 API 的逐回合严格校验不接受新事件字段。更新平台不会自动替换已纳管 Worker 或业务镜像中内置的 Runner。服务数量及位置展示不要求更新节点。

## 本次运行配置

在批次详情点击“运行配置”，按任务集合、客户端、服务端、资源与执行限制四组查看历史快照；顶部分组按钮可跳转，不必逐步点下一步。选择任务后，回合、种子、客户端模板名称版本、启动命令、业务参数、环境覆盖与资源预约均切换为该任务的记录。参数来源显示模板默认、集合公共参数、向导公共参数、任务单独配置或运行时覆盖；旧记录无来源时不推断。普通参数后层覆盖前层，任务单独配置优先于向导公共值。

基于历史批次创建的新批次会把导入的最终参数写入各任务单项；新批次“运行配置”中的来源按这次提交重新计算，不能据此倒推原批次的参数来源。切换任务核对最终值和映射后的命令；服务端模板参数则在服务定义中核对。命令是按保存快照推导的预览，未采集节点实际启动 argv 或登录 Shell 环境。

客户端展示宿主机/容器、批准环境名或镜像、登录/显式环境、逐回合方式与失败策略。命令是模板快照中的argv（映射前），不是实际运行进程的argv转储。环境覆盖、映射与完整JSON默认收起。仅显示快照中的设置，不读取当前节点Shell环境；集合名称版本、业务账号与节点Python路径未保存时明确“未记录”。

托管服务按逻辑定义显示模板名称版本、目标实例数、参数、资源和就绪策略。只有旧max_instances时显示按需启动上限，不当成固定实例数；“查看实际服务实例、节点、加速卡与日志”跳到已有服务状态页。外部候选地址与最近执行尝试的实际地址分别展示，无服务模式明确提示。资源池显示已保存的ID，不使用可能已改名的实时名称冒充历史名称。

CPU/内存调度预约与执行硬上限分别显示；总执行时限0显示不限制，缺失显示未记录。批次最大并发与单任务全部回合共用时限分别展示。提交时预检报告未保存，不重新预检冒充历史结论。配置读取失败可重试，快速切换任务忽略过期响应；空批次和无快照任务有独立提示。

本功能仅更新前端，无数据库迁移、Worker升级或调度行为变更。验证证据与部署边界见[运行配置验证](validation/batch-run-configuration/README.md)。

运行配置页已发布到实验平台，并在正式静态前端复验已有direct/SDK批次；部署范围与证据见[发布验收](validation/startup-lease-release/README.md)，不代表其他用户部署已更新。


### 已调度服务批次删除的外键修正（2026-11-18）
包含实际服务实例及服务任务的批次，旧实现可能在同一次 ORM flush 中先删除服务实例，导致外键异常并返回 500。现在每层子记录删除后显式 flush，再删除父记录；全部操作仍在同一事务内，失败整体回滚。无需数据库迁移或 Worker 升级，需更新平台 API。专项复现与验证边界见 [验证记录](validation/batch-delete-foreign-keys/README.md)。这不替代其他部署的异常日志核对。

日志面板的滚动保留、缺口提示、停止轮询及旧 Worker 兼容见 [执行日志说明](execution-logs.md)。新旧执行日志不可据界面长度推断完整性。


## 两套结果统计

程序执行按业务进程统计正常结束、异常退出、运行中、退出码未上报和未启动；平台协议回合结果统计业务成功、业务失败、结果校验异常、未分类回合异常及未上报。退出码 0 与业务成功不同。没有独立回合进程的 SDK 回合退出码显示不适用。单进程多回合不重复计算进程退出；普通命令不进入协议结果分母。

批次只汇总各任务最新尝试，历史重试保留在详情，不受任务筛选或分页影响。有效结果成功率仅基于有效已完成协议回合，页面同时展示有效/计划回合数及异常、未上报。例如 1 个成功、9 个结果异常时，应读为“有效结果成功率 100%（1/1），有效结果 1/10，结果异常 9”，不是整个批次成功。

程序退出状态、回合协议结果和任务生命周期分别显示；FAILED 不直接映射为程序异常退出。具体协议诊断及升级边界见 [宿主机执行](host-execution.md#程序执行与协议结果workerrunner-0215)。

### 执行身份与目录

“排查任务”选择执行尝试后展示对应的执行 ID、节点和已上报目录，支持复制。任务详情使用同一入口。尚未分配和目录尚未上报分别提示；复制失败可手动选择文字。目录是宿主机路径，可能已清理，不能把 `work/episode-N` 当成独立回合日志文件夹。旧 API 暂无该接口时只显示目录不可用，不影响日志和结果查看。

### 整任务普通命令的执行状态

整任务启动的普通命令只显示一条“整次执行状态”，不展示计划回合表或回合翻页。配置回合数仍保留并按原契约传入业务程序；平台不解析其内部回合。退出 0 表示整次执行正常，非零表示执行异常（可能包含启动/包装器错误）；超时、取消、启动失败及诊断仍按任务生命周期显示，没有退出码不能判定正常。输出查看本次执行公共日志。

整任务接入 SDK/直接平台协议时仍显示协议回合；SDK 命令适配和每回合启动模式仍显示回合记录。判断使用任务保存的模板及进程模式，不能仅根据 episode_reporting 标记决定。旧回合记录不删除，不从任务退出码补造回合成功。此调整只需更新 API 和前端，无需数据库迁移或 Worker/Runner 更新。

## 基于历史批次创建新运行

在“评测运行与结果”的批次列表或详情点击“基于此批次创建”，导入五步业务评测向导。向导显示来源批次、原模板名称/版本，默认选中原集合并标注“历史运行快照”，恢复原客户端与当次实际任务，不重新读取后来修改过的集合。原集合不可用时保留其ID并提示；原模板不可用时保留名称/版本，说明需重选集合允许的可用模板。选择“使用该集合当前配置”才改用当前任务清单。历史快照模式提交仍携带逐项cases而不绑定实时suite_id，避免覆盖历史差异。导入仅查询，不创建任务或占用资源。

逐项检查回合数、种子、参数 JSON、单项资源与服务关联。历史最终参数会预填到清单；所有任务相同的业务参数也会预填到客户端步骤。修改预填的共同业务参数后，按普通向导规则应用到新批次；无类型化旧模板可编辑客户端业务参数 JSON。任务间不同的值在清单中逐项修改；单项值优先于公共值。想统一取值时须逐项修改这些任务，预检时核对逐项有效参数。资源按各项恢复，可在单项资源 JSON 中修改；清空对象才改用公共申请。无效 JSON 必须修正。

客户端恢复模板引用、运行变量覆盖、请求超时和每项总执行时限（包括不限）；批次恢复原断联容忍时长，历史没有该字段时按默认不限回显，新提交前仍可修改。服务端恢复逻辑名称、原模板、业务参数、环境、资源、固定槽位约束、实例数及结束策略。固定槽位只来自原提交约束，不复制平台实际分配结果；托管地址重新调度，外部候选地址保持原访问模式。有限断联容忍仅对启用恢复能力的新执行生效，旧批次不会追溯更改。

原模板、资源池不可用或模板内容已变化时，向导展示问题，需明确选择或确认当前配置后重新预检。旧服务“实例上限”不会直接转成实例数，必须填写明确数量。缺少关键快照、空批次、无法表达的不同客户端配置不会被首项或默认值静默替代。恢复失败可重试；重新导入会清空旧预检、试跑与提交状态。

最后检查有效业务参数和资源申请，再提交独立的新批次。原批次、执行、日志和结果保持不变。同次网络失败重试仍幂等；重新导入使用新的提交身份。本功能无需数据库迁移或 Worker/Runner 更新；API 与前端需要同步更新。普通命令仍受当前提交规则检查，历史配置不能绕过准入。

### 结果统计布局

批次列表的“程序执行”和“回合结果（平台协议）”分别占一列，长统计文字在各自列内换行；窄屏请在表格内横向滚动查看。详情汇总使用独立的两张卡片，桌面并列、窄屏上下排列。此布局修正不改变退出码、协议结果或成功率的统计口径。

## 独立日志抽屉

更新后的 Worker 为新执行登记日志后，可在任务尝试、回合和服务实例区域选择对应日志按钮。逐回合各自采集，单进程多回合共用公共日志。抽屉显示执行 ID 和登记的节点路径，支持来源过滤、有限翻页、跟随/暂停和最多 8 MiB 的保留日志下载。缺口不等于业务失败，执行退出状态与协议结果仍分别显示。旧执行继续查看原有日志。详见 [执行日志](execution-logs.md)。

### 运行配置中的动态映射
客户端和各服务定义下的“动态参数映射”同时展示平台字段与类型化业务字段绑定，包含来源、传递方式、程序接收名称、编码及本次快照值。切换任务后任务名和业务值随之更新。输入 JSON 字段不追加命令，flag 为 false 时不追加开关，可选值未提供时不追加。服务端分配地址、端口和节点路径未保存在此快照时标为启动时解析，不推断当前节点值。

“启动命令（模板快照，参数映射前）”仍是基础命令，不是 Worker 实际 argv；动态参数在业务启动时追加。旧版页面遗漏 parameter_schema 中的业务绑定，仅展示折叠的 platform_bindings，因此看不到映射不代表节点没有传参。本修正只需更新前端，无数据库迁移或 Worker 更新。浏览器测试使用模拟 API 快照，不代表真机执行验证。

2026-11-19 本机 18000 已发布统计列布局与动态映射展示修复，见[前端发布验证](validation/ui-layout-release-20261119/README.md)。其他机器仍需部署前端；此次不含实际启动快照功能。

### 参数映射后的启动命令
“运行配置 → 客户端”按本次保存配置展示模板基础命令和映射后的 argv。先展开已知任务占位符，再追加业务参数映射，最后追加平台参数映射；flag=false 不追加，repeat 按项重复参数名，JSON 保持单个参数，env/input 不拼入命令。合并后的显式环境变量单独展开查看。
宿主机逐回合可选择预览回合，task.episodes=1，seed 按基础种子加回合序号减一并对 2147483648 取模。整任务保留总回合数。未保存的运行地址、端口和节点路径保留占位；这只是配置展示，不采集节点实际进程，也不包含登录 shell 的全量环境。不新增数据库表，不需升级 Worker。

“基于此批次创建”依赖 GET /api/v1/batches/{id}/rerun-draft。仅更新前端会在旧 API 返回通用 Not Found；必须发布配套 API 并确保路由在静态资源兜底之前注册。batch not found 则表示批次不存在、已删除或无权访问。

### 成功率摘要与详情
批次列表、任务行及结果卡显示两个独立摘要：正常退出率=正常退出次数/(正常+异常退出次数)，评测成功率=成功回合/有效结果回合。汇总使用总计数，不平均各任务百分比。未启动、运行中、退出码未知不放进退出率分母；协议异常与未上报不放进有效结果分母。旁边保留已知退出码/程序总数、有效结果/计划回合及任务完成进度，所以部分完成的 100% 不代表全部成功。
无数据不会显示 0%；普通命令显示“未接入”，协议异常但没有有效结果显示“暂无有效结果”。进入批次或任务详情，点击“查看程序执行详情”“查看回合结果详情”展开完整计数；逐回合退出码、异常原因、日志入口保留。本次仅前端展示，无数据库迁移、Worker 或 Runner 更新。

展开入口修正：批次列表及任务行的两列也提供“查看程序执行详情”“查看回合结果详情”，在当前行独立展开/收起；无需先进入顶部统计卡。轮询保留展开状态，无统计数据时详情明确显示未上报。此前仅顶部统计卡可展开的遗漏已补齐。

## 运行产物侧栏

批次任务行点击“查看产物”，或从回合详情点击同名按钮，打开右侧面板；可切换执行尝试和“全部/任务级/回合”筛选。回合归属来自已保存协议事件的 artifacts 引用，不根据文件夹名猜测。尚未声明归属的旧文件显示为任务级。面板关闭不清空列表筛选。

已上传的 MP4/WebM 和常见图片可申请短期文件访问授权后预览，视频支持 Range 读取和拖动；浏览器编码不支持或授权过期时提示重新加载或下载。媒体凭据为短期 HttpOnly 路径受限 cookie，不把平台登录 token 放进视频 URL。HTML/SVG 等主动内容只下载。原下载入口保留。

共享存储已支持 API 直读：管理员配置只读挂载与根映射后，默认浏览共享输出目录。新 Worker 0.21.9 在收到 shared 标记时只登记路径、不上传文件。支持目录分页、文件预览和 Range 下载；未配置映射时使用历史上传产物。挂载错误会明确提示，不能当作空目录。自定义目录、Worker 转发及自动回合目录归属仍待实现。部署、迁移与权限见[共享存储产物](shared-storage-artifacts.md)。


通用预览：JSON 支持格式化、逐层折叠展开，解析失败显示原始文本；TXT/LOG 显示纯文本；CSV 支持带引号的逗号、换行与双引号；图片支持 PNG/JPEG/WebP/GIF，视频支持浏览器可解码的 MP4/WebM。HTML/SVG 只提供下载，不作为页面执行。

文本最多预览前 256 KiB，超出时明确提示截断，截断 JSON 不尝试当作完整 JSON 解析。CSV 最多显示 200 行、50 列；JSON 每层最多显示 50 项、最多展开 12 层，更多内容请下载。切换文件或关闭面板会取消文本读取；授权过期或读取失败可点击“重新加载预览”。这些上限仅约束在线预览，不修改原文件。共享直读复用相同预览界面；旧 Worker 的上传行为只有升级后且接收 shared 标记才会改变。

历史恢复阻塞会在错误中列出字段路径和具体原因；集合默认显示修复不会忽略缺失快照或异构配置。用户需要提供具体批次或问题条目才能确定现场原因。

历史批次导入：每步底部的“历史配置确认”列出待核对字段与所属步骤，可返回已访问步骤修改。旧服务实例数必须先填写 1–20 的整数；修改配置后需重新确认并预检。无法恢复的问题仍禁止提交，无需数据库迁移或节点升级。

## 执行时间（execution-duration-display）

批次顶部显示“批次历时（含排队）”：从批次创建到所有客户端任务的最新尝试结束；补跑期间继续计时，包含排队、暂停和补跑间隔。不是任务耗时求和，不统计服务常驻时间。任务列显示当前尝试的执行耗时和等待时间；详情切换历史尝试可查看原起止时间。

任务执行耗时从 Worker 领取进入 STARTING 到终态，包含准备、启动和结果处理；不包含排队及终态后的清理。未领取即取消显示“未启动”，旧记录缺少时间显示“未记录”，真实 0 显示 0 毫秒。等待时间使用本次最早 PENDING 事件；首次尝试事件缺失可回退到任务创建，重试缺失则未知。

仅独立回合进程（sdk-command 或宿主机 per_episode）显示回合耗时列，含输入准备、子进程执行及结果解析。运行中按平台接收 STARTED 的时间显示“约”，最终使用 Runner 单调时钟；失败回合也记录。单进程直接协议/Python SDK 保留回合结果，但不显示独立进程耗时；普通整任务命令只显示整次时间。缺少最终事件而任务终止时显示已中断，不虚构结束时间。

API 的 `timing.as_of` 是同一次响应的基准，`seconds` 为非负秒或 null。批次使用 `elapsed`，尝试使用 `execution/waiting`，回合使用 `state/seconds/source/quality`。前端只用 performance.now 短时推进，6 秒未获取新响应就冻结并提示更新中断；恢复后校准，不使用浏览器墙钟计算。每行不新增请求。时间不是退出成功或业务成功的判据。


## 列表与详情读取优化

运行记录使用批次摘要读取，只返回列表所需状态、进度、优先级和结果统计；任务明细仍在批次详情查看。摘要与详情均按最新执行尝试统计，历史尝试可独立查看。

详情顶部的控制状态与任务概览继续刷新。切换到其他页签后，隐藏区域的服务、回合和日志停止轮询；返回时立即刷新，筛选、展开状态和日志游标保留。服务概览与服务详情不会同时轮询。已经打开的读取请求可能完成，但隐藏后的迟到响应不会覆盖新页面数据。此行为不改变任务运行、暂停恢复或重新评测。

模板、资源池和集合选项在进入界面、返回窗口焦点及主动保存/提交后刷新，不再随批次列表每两秒重复读取。读取失败会显示错误；重新进入或切回窗口可重试选项读取。

兼容 API：`GET /api/v1/batches?view=summary&page=1` 返回摘要（没有 `cases`），不带 `view` 仍返回完整视图；`GET /api/v1/orchestrations/{id}?view_mode=status` 返回服务与客户端绑定，省去重复批次结果统计，不带参数仍返回完整编排。权限、分页和控制修订检查保持原行为。

无需数据库迁移或更新 Worker/Runner。部署时先更新 API，再更新前端；查询性能的隔离测试边界见 [验证记录](validation/ui-query-20261124/README.md)。

## 监控繁忙与自动重试

批次监控连续失败时保留上次成功数据，提示错误及 `request_budget`、`lock_timeout` 等后台原因，并明确说明已有数据不是最新结果。失败后间隔逐步增加（批次约10、20、30秒，带少量随机抖动），自动退避最高30秒；服务端 Retry-After 更长时按该值等待。成功后恢复5秒刷新。

单批次几十到 100 个任务时，后台只在**本次监控读取**中复用配置快照和资源申请完全等价的待调度诊断。每个任务仍单独展示状态和等待原因；申请不同的任务各自诊断，下次刷新重新读取节点资源。这个优化不改变调度顺序或准入结果。旧版后台在 100 任务混合负载中曾有监控 `503 request_budget`；修复与失败证据见[大批次验证](validation/disconnected-execution-20261124/large-batch-monitor-20261125.md)。

使用通用轮询的页面在浏览器标签页隐藏时暂停并取消在途读取，返回可见立即读取；关闭详情或切换批次后旧响应不会覆盖新页面。其他使用通用轮询的视图保留原正常刷新间隔，但同样具备失败退避。日志有独立的读取生命周期，不代表所有后台请求都已停止。

托管服务候选在单次诊断中按批次和服务集合复用，下次请求重新核对就绪与租约；这只优化展示，不改变任务调度、容量判断或服务地址分配。更新 API 与前端即可，无新增数据库迁移或 Worker 升级。监控降载不能替代对持续持锁事务的定位，参见 [控制操作排查](control-operation-backpressure.md)。
