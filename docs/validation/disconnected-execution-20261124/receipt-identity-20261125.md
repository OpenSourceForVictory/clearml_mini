# 业务收据原身份检查（2026-11-25）

触发条件：原 Worker 的恢复授权尚在，但槽位已经转给其他 Worker，或批次已标记删除。此前显式 `apply: true` 会拒绝槽位归属变化，但仅收据入口仍可保存业务消息；删除标记也未在仅收据入口核对。

修正后，仅收据业务结果同时核对原执行/代次、当前槽位归属、任务与批次存续；托管服务通过服务实例关联批次。归属变化返回 409，删除返回 410，不新增业务收据。原身份的受限控制证据仍可在凭据有效时提交，便于安全停止核对；撤销的 Worker 凭据仍由认证入口返回 401。本变更不提供删除时的 Worker 丢弃确认，也不替代 4.3/4.9 的完整删除事务与补传验收。

测试：`test_recovery_records.py` 和 `test_recovery_results.py` 在 SQLite 下 63 通过、6 条 PostgreSQL 条件跳过；隔离 PostgreSQL 再跑 69 通过、无跳过。相同专项独立覆盖率统计中 `backend/app/recovery_records.py` 为行 93.79%、分支 90.00%；这不是全项目覆盖率。新增归属改变和删除标记两条失败路径测试，均验证业务收据为零、控制证据仍可保存。没有真机断联或重新纳管测试，不把这项边界补丁称为完整发布。
