# 四角色部署纳管 404 修复

触发：四角色部署后，SSH 纳管检查读取节点安装包时显示 `control_api_rejected_404`。纳管执行器的镜像默认回调 `http://api:8000`；此地址在四角色模式是交互进程，而 `GET /api/v1/admin/node-installation-bundle` 被明确路由至批量进程。修复前在本机纳管容器中，不带凭据请求该接口：直连 `api` 得 404，经 `api-gateway` 得 401。401 是预期鉴权拒绝，说明请求已经到达正确角色；未复现用户另一套平台的完整 SSH 操作。

修复：四角色 Compose 覆盖文件将纳管执行器的 `--api-url` 设为内部网关。原单/双 API 的镜像默认地址不变。更新本机 `onboarding` 容器后，其健康检查为 healthy；容器内经网关请求机器列表和节点安装包均返回未认证时的 401，没有角色 404。Compose 展开配置显示 `onboarding.command` 使用 `http://api-gateway:8000`；角色路由与纳管专项 21 项通过。此次只重建纳管容器，没有执行完整带凭据的远程 SSH 注册，不把路由验证当作纳管端到端验收。
