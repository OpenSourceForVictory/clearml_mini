# 原执行终态补传验收（4.3）

原执行的控制证据和业务结果按执行 ID、Worker 身份、分配代次、当前槽位归属及不可变序号/摘要核对；收据和结果应用不续租、不重开已终结的执行、不释放或重新占用资源。相同序号同内容可重复确认，异内容拒绝。用户删除批次后，控制证据仍可用于安全收尾，结果应用返回明确 `discarded`，既不复活结果也不让 Worker 无法确认丢弃；最终同步确认丢响应可由同一身份重放。

鉴权边界：Worker 凭据本身没有按时间自动到期；旧凭据在管理员轮换后立即 401。更新为同一 Worker 的新凭据后，原执行的已提交终态收据仍可幂等重放，状态和租约不变。Worker 被撤销则鉴权 401，重纳管导致槽位归属变化则拒绝原身份的业务补报。这一验证不代表节点会自动获取轮换后的凭据；运维需按节点更新配置并重启 Worker。普通用户登录会话与 Worker 凭据不是同一机制。

证据：`test_recovery_records.py` 覆盖过期租约/终态、不变摘要、旧代次、撤销、删除、重纳管槽位和真实 API 鉴权；`test_recovery_results.py` 覆盖取消/超时后的迟到结果、结果冲突、已删批次的显式丢弃和可靠队列 ACK；`test_recovery_finish.py` 覆盖最终封口和丢失的确认响应。SQLite 专项及隔离 PostgreSQL 组合此前 149 项通过、1 项测试变量错误修正后定向 2 项通过；轮换凭据的隔离 PostgreSQL HTTP 新用例 1 项通过。首次测试变量错误保留在阶段记录，不被描述为生产故障。

完整恢复能力仍未生产启用。真实节点断联、凭据轮换与批次删除同时发生的发布演练属于 5.3；本项证明接口和原执行授权逻辑，不声称真实模型任务已经验收。
