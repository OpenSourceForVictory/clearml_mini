# GPU/NPU 共享批准与双执行环境纳管验证（2026-11-17）

触发条件：SSH 纳管表单只选择 GPU/NPU 与宿主机/容器，新 NPU 安装脚本无条件写入 `npu_runtime.allow_shared: true`；旧节点重新纳管保留原字段，但检查计划不展示。资源池共享开关不能替代节点本地批准。

修正后：新 GPU/NPU 安装默认关闭共享，明确选择“允许共享”才写入批准；重新纳管默认逐卡保留原值，可明确开启或关闭全部所选设备。宿主机和容器可同时勾选，并分别检查两类前提；只读预检将每卡原值展示在确认计划中，不暴露完整 JSON 或凭据。显式修改 NPU 必须存在已批准的 NPU 配置；失败按原有事务恢复配置和程序。Worker 在注册时把本地批准转为相应的 `gpu:*:shared` 或 `npu:*:shared` 能力，普通心跳不发送原始字段。资源池仍需单独允许共享。
