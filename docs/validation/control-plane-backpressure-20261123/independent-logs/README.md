# 独立日志上报与压测客户端连接复用

这是隔离 PostgreSQL、单 API 进程的短时模拟负载，不是生产部署或真实业务程序验收。每个模拟 Worker 每约 2 秒独立生成一条 1024 字节日志，日志发送与心跳、服务健康、产物登记、领取分开；日志队列按 Worker 限制为 256 条，遇到 503 按 Retry-After 加抖动重试，测试结束额外排空 5 秒。`backend/tests/control_plane_load.py --independent-logs` 实现该负载。API 关闭调度分配循环，未包含 Agent、Web、实际业务进程和多卡节点。

| 负载与连接预算（普通/控制） | 最大心跳间隔 | 日志生成/确认/结束待发 | 结果 |
| --- | ---: | ---: | --- |
| 100 Worker，30 秒，10/5 | 4.80 秒 | 1500/1500/0 | 通过本轮短测 |
| 200 Worker，30 秒，10/5 | 22.10 秒 | 3000/3000/0 | 未通过 |
| 200 Worker，30 秒，5/10 | 21.52 秒 | 3000/2896/104 | 未通过 |
| 200 Worker，30 秒，5/10，压测客户端增加 HTTP keep-alive 复用容量 | 13.08 秒 | 3000/2772/228 | 未通过 |

前三轮脚本最多允许每 Worker 两条并发 HTTP 连接，但采用 HTTPX 默认的 20 条空闲连接保留上限；第四轮将保留上限同步到最大连接数，排除压测客户端频繁关闭连接造成的偏差。第四轮 10 秒预试跑曾通过（最大心跳间隔 8.43 秒），30 秒正式复测仍失败，所以不能把预试跑当作 200 Worker 容量验收。首次新增独立日志后，10 Worker 冒烟测试在空队列年龄统计处触发 `TypeError: 'float' object is not iterable`；修正聚合表达式后 10 Worker 重跑通过，原始失败与修正后的输出保留在本地 `.runtime/log-independent-sanity*`。

第四轮数据库首次借连接等待 P99 为 0.054 毫秒，压测客户端事件循环延迟 P99 为 0.031 秒，心跳客户端请求耗时 P99 为 5.14 秒；心跳并发准入拒绝 80 次。API 已处理的控制请求耗时远低于客户端端到端耗时，现有指标尚未把 HTTP 客户端连接排队、服务器接收/事件循环排队、数据库查询执行及其他主机调度等待完整拆开。不能据此断定 PostgreSQL 已达到自身容量上限，也不能断言增大数据库连接池即可通过。

原始汇总分别保留在 [100-default.json](100-default.json)、[200-default.json](200-default.json)、[200-rebalanced.json](200-rebalanced.json) 和 [200-keepalive-30s.json](200-keepalive-30s.json)。这些 JSON 不包含连接凭据；完整 API 诊断日志留在本地 `.runtime/`，未提交。后续混合负载、长时 100/200 档和容量结论仍按 OpenSpec 5.1/5.2 待办执行。

## HTTP 分段定位与独立客户端复测

原压测器所有模拟 Worker 共用一个 HTTPX 客户端，即使空闲连接上限提高到 400，仍会在客户端连接池内排队。为区分客户端和服务端等待，工具新增可选的 HTTP 阶段计时 `--trace-http-phases` 和每 Worker 独立客户端 `--client-per-worker`。阶段计时只记录耗时聚合，不记录请求体、凭据或地址；`client_before_transport` 包含 HTTPX 取连接等客户端等待，`response_headers_wait` 包含服务端接收及处理，不能单凭它细分服务端内部阶段。

| 200 Worker，30 秒 | 客户端进入传输层前 P99 | 响应头等待 P99 | 最长心跳间隔 | 心跳准入拒绝 | 日志结束待发 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 共享客户端，普通5/控制10 | 5.45 秒 | 0.13 秒 | 17.89 秒 | 16 | 37 |
| 每 Worker 独立客户端，普通5/控制10 | 0.0013 秒 | 0.315 秒 | 11.95 秒 | 628 | 234 |
| 每 Worker 独立客户端，普通5/控制20 | 0.0018 秒 | 0.343 秒 | 6.03 秒 | 160 | 490 |
| 每 Worker 独立客户端，普通10/控制20 | 0.0028 秒 | 0.366 秒 | 7.27 秒 | 492 | 45 |

共享客户端会把真实平台没有的连接池争用引入压测结果。独立客户端消除这一项后，200 Worker 的请求能迅速进入传输层，但控制通道仍有突发准入拒绝。控制池/准入额度从 10 提到 20，短测心跳间隔改善；普通日志通道仍积压。两种额度一起调整并不单调改善心跳，可能涉及同机 CPU 调度、短时抖动和不同类别的工作量；不能把任一组解释为通用容量配置。所有组数据库首次借连接 P99 约 0.05–0.06 毫秒，尚无 PostgreSQL 自身容量耗尽证据。单 API 进程的 CPU 曾观察到接近一个核心满载；没有连续 CPU/锁等待剖析，仍不能确认唯一根因。

原始汇总：[共享客户端](200-shared-client-trace.json)、[独立客户端控制10](200-per-worker-control10.json)、[独立客户端控制20](200-per-worker-control20.json)、[独立客户端普通10/控制20](200-per-worker-ordinary10-control20.json)。

## 50 Worker 同时上报

每 Worker 独立客户端、普通10/控制5、单 API 进程、30 秒，日志与心跳并行生成。Worker 模式下心跳携带设备遥测；Agent 模式额外模拟每节点一条 `agent/heartbeat`，每约 5 秒上报宿主机和 GPU 采样，Agent 作为权威资源来源，Worker 心跳中的遥测不覆盖它。两组均只使用模拟服务和隔离数据库，不代表 50 台真机、多卡或真实评测。

| 50 Worker，30 秒 | 最长心跳间隔 | 日志生成/确认/待发 | Agent 成功/临时拒绝 | 过期租约/遥测 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| Worker 内嵌遥测 | 4.05 秒 | 750/750/0 | 不适用 | 0/0 | 本轮通过 |
| 另有 50 路 Agent 遥测 | 3.96 秒 | 750/750/0 | 300/34 | 0/0 | 本轮通过，Agent 拒绝后重试成功 |

原始汇总：[Worker 内嵌遥测](50-per-worker.json)、[Agent 独立遥测](50-agent.json)。30 秒短测不能证明长期无日志积压；30 分钟持续负载单独记录。

### 提前停止的 50 Worker 持续观察

同样的 50 Worker + 50 Agent、普通10/控制5、单 API 进程负载原计划持续 30 分钟。用户在观察到指标没有随时间恶化后要求可提前停止，因此在约 25 分钟主动发送 SIGINT；工具按 `finally` 停止隔离 API、删除本轮临时数据库。每 30 秒的记录见 [50-agent-25m-progress.jsonl](50-agent-25m-progress.jsonl)：最后一条为 1500.45 秒，累计日志 37500 生成 / 37500 确认 / 0 待发，全程记录中的最长心跳间隔 2.17 秒，日志待发始终为 0，心跳入口拒绝 0。由于主动中断，没有正常结束的汇总、最终租约/遥测 SQL 检查，也没有完成原计划的 30 分钟验收。此观察不包括真实调度、Web、业务程序或故意制造的日志积压。

### 故意制造日志积压的短测

单 API 进程、50 Worker + 50 Agent、每 Worker 独立 HTTP 客户端、120 秒，普通池缩为 1、控制池保持 5，日志生产间隔缩为 0.5 秒。结束时日志 11918 生成 / 11211 确认 / 707 待发，最大待发年龄 63.35 秒；普通类发生日志 3330、产物 2293、领取 2294 次准入拒绝，负载工具整体判定 **未通过**。同时心跳准入拒绝 0、最长心跳间隔 4.08 秒、过期租约 0、遥测过期 0。第 120 秒尚有 1304 条待发，额外 5 秒排空后降至 707，说明积压仍在增长，不能把最终数量较低误判为稳定。证据：[完整汇总](50-agent-forced-backlog-120s.json)、[逐 30 秒进度](50-agent-forced-backlog-progress.jsonl)。这是人为压缩普通通道的压力故障注入，不代表推荐配置或双进程部署的容量。
