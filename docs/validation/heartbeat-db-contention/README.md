# 心跳与探测连接池争用验证

触发条件：多节点 Worker/Agent 心跳和服务探测同时等待 PostgreSQL 全局调度锁，等待请求占着连接，五秒 HTTP 超时后 Worker 记录 `TimeoutError`。该错误不等于 token 失效。原上报本就只更新数据库最新状态；本次没有增加本地落盘。

修正后：无执行租约的 Worker 心跳、Agent 采样和服务探测结果不再获取全局调度锁，按节点/服务记录串行更新，仍保留最新样本时间、序号、阈值与代际检查。运行中执行的心跳仍同步租约状态，锁忙时立即返回可重试 503。探测会话启动仍使用低频全局锁。新增争用测试 3 通过；相关回归分组分别为 115 通过、34 通过、76 通过/12 跳过、78 通过，其中有重复用例。新 API 镜像在生产数据隔离副本上启动且 `/healthz` 正常。未运行用户要求暂停的全量测试，也未模拟真实生产连接池耗尽或模型业务验收。

发布后核对：生产 API 和纳管容器健康，`/healthz` 正常；数据库迁移版本为 `w396f78`，13 个槽位的心跳及遥测均在核对时刻最近一分钟内。该结果说明新版本能接收上报，连接池高峰改善仍需在真实负载下观察。
