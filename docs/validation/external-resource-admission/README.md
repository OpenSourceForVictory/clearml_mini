# 非平台任务占用资源的准入验证

触发条件：平台运行中的任务尚未用满预约额度，而非平台进程也占用了设备显存或主机内存。旧规则只将尚未启动的预约从实测剩余量中扣除，可能高估下一项任务可用空间。

修正后：新申请与所有未清理的平台预约之和必须同时不超过物理总量扣安全余量、实测剩余量扣安全余量。主机内存也用同样的保守条件；CPU 仍按配置核心数和平台配额管理，不把瞬时 CPU 使用率视为可保证的空闲核数。实时样本仍有时效检查，Worker 在实际启动设备任务前仍复查。

该规则在无法区分平台任务实际占用和外部进程占用时偏向安全，可能使部分本可并行的任务等待。测试是模拟资源数据，不代表真实 GPU/NPU 业务验收。按用户要求不运行全量测试，覆盖率门槛是否满足需在后续完整统计中确认。

边界：历史独占任务可使用零显存申请；这种任务仍独占整卡，但因没有申请额度，无法对其所需显存与非平台占用做容量核对。CPU 的瞬时利用率也不是可保证的剩余核心数，现阶段仍按平台配额与节点核心容量准入。

定向验证：`test_accelerator_resources.py`、`test_gpu_sharing.py`、`test_resource_reporting.py` 共 49 通过；再与 `test_preflight.py`、`test_orchestrations.py`、`test_pair_capacity_diagnostics.py` 合并运行共 96 通过、1 条第三方弃用警告（前述 49 项包含在 96 项中）。前端 TypeScript 检查与 Vite 构建通过；OpenSpec strict 校验通过。未运行全量测试与覆盖率统计。

发布核对：切换前生产数据库无活动或未确认清理的执行；只更新 API 镜像，无数据库迁移或节点程序重启。发布后 API 和纳管服务健康，`/healthz` 正常、首页 HTTP 200；13 个未删除槽位最近一分钟内均有心跳和设备遥测。此项只证明发布后上报和入口正常，不等同于高负载或真实 GPU/NPU 业务验收。
