# SSH 执行器等待与数据库隔离修复

触发条件：纳管执行器连接或响应变慢时，管理列表/检查/确认/验证/取消/指纹信任及清理接口仍持有认证查询的SQLAlchemy连接；清理预检还在调度事务锁内调用执行器。单次IPC虽然有20秒上限，多条并发请求仍可能占满小连接池。

修复前真实PostgreSQL回归失败：两条被挂起的执行器列表请求占满2/2数据库连接，预期归还的断言失败。原输出保存在before.txt。没有用模拟连接池替代PostgreSQL。

修复：先读取所需身份和载荷，关闭只读Session/事务，再调用有界执行器IPC；清理结果读取完成后重新开启事务核对可信回执。清理预检不再持有调度锁等待SSH，真正执行前仍必须通过cleanup/begin重新检查修订、纳管状态和活动执行，预检不构成删除授权。接口权限、凭据内存通道与20秒通信上限不变。

新增8项测试覆盖2连接慢请求时心跳/取消继续、各IPC入口释放连接、PostgreSQL调度锁可获取、清理预检期间修订变化后旧begin拒绝。关联纳管/解除/重试测试共55项通过（119.15秒，无跳过）；最终全量单列。此修复仅更新API，无数据库迁移、Worker或Runner升级要求。
