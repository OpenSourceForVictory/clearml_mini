# 多推理地址评测

在集合运行向导的客户端步骤添加推理地址，每行选择「独占」或「共享」。预检、单回合试跑和正式运行使用同一列表。平台没有推理服务池，也不部署推理服务。

单任务、集合批次和批次预检的 `client` 均可使用：

```json
{
  "template_id": "客户端模板 ID",
  "endpoints": [
    {"url": "ws://inference-a:8000", "mode": "exclusive"},
    {"url": "ws://inference-b:8000", "mode": "shared"}
  ]
}
```

列表必须有 1–100 个地址，模式必填，协议必须被模板允许。不能同时提供 `endpoint` 和 `endpoints`。旧 `endpoint` 请求继续生效，模式沿用模板的 `endpoint_exclusive`；显式列表的模式覆盖模板默认，包括 Cosmos 模板。

同一规范化主机和有效端口代表同一资源，URL 路径不隔离占用；主机名忽略大小写和末尾点、IP 使用规范形式。不解析 DNS 别名，用户应统一同一服务的主机名，避免用不同别名绕过互斥。完整 URL 路径仍原样传给客户端。

## 调度与执行

每次执行从可用地址中选占用最少的一个，相同时按列表顺序。任一占用方或申请方为独占，该地址不能并发；共享之间可并发，无额外服务容量参数。此规则跨用户、批次和资源池生效。忙碌的首地址不会阻挡后续可用地址。GPU 与地址在同一调度事务内预留，没有 GPU 时不占用地址；沿用现有用户公平性，不为独占任务抢占共享任务。

预检逐地址显示占用和可用状态，不访问推理服务、不预留资源。因此预检成功不保证提交后立即执行，也不代表服务健康。全部候选受阻时任务排队。

一个执行尝试固定一个地址。Worker claim 接收兼容旧协议的 `client_spec.endpoint`，不接收候选列表；重复认领、恢复和短暂断线不改变绑定。重试创建新尝试并重新选择地址。未认领的预留被取消、暂停、过期或因节点配置修改撤销时清空绑定。已认领执行即使终止或节点离线，只要尚未确认容器清理，仍保留占用。

详情、批次监控和 JSON/CSV 报告包含 `endpoint`、`endpoint_mode` 和 `endpoint_candidates`。前两项表示实际尝试，未分配时为空，不能用第一候选冒充实际地址。历史单地址执行继续可读；重试历史保留原地址。比较报告把地址与模式变化列为配置差异。

## 升级与回退

迁移 `i952d34` 在 Run 添加成对可空的实际地址/模式及约束，回填已有 execution_id 的非 PENDING 单地址尝试。未分配任务保持空值。部署前备份数据库与 API 镜像，执行 Alembic upgrade head/check，然后更新 API/UI；Worker 输入兼容，不要求升级 Worker。

存在多地址待执行、执行中或待清理任务时禁止降级。排空和清理后，降级仍不能使旧 API 正确读取多地址历史快照；完整回退需恢复升级前数据库和 API/UI，并另存升级后的数据，避免丢失新结果。不要仅切换旧镜像继续运行多地址任务。
